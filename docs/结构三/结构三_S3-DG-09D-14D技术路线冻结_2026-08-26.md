# 结构三 S3-DG-09D～14D 技术路线冻结

日期：2026-08-26  
决策人：项目负责人  
范围：结构三完整闭环；本记录不缩小研究方向

## 1. 冻结选择

| Gate | 冻结路线 | 不允许退化成 |
|---|---|---|
| S3-DG-09D | Multi-parse posterior compiler（多解析后验编译器） | 单次 LLM 输出一个确定解析后直接执行 |
| S3-DG-10D | Probabilistic dynamic instance graph（概率动态实例图） | 检测框到实例 ID 的贪心硬匹配 |
| S3-DG-14D | Revision-aware neuro-symbolic evidence graph（可修订神经符号证据图） | VLM 文本判断直接成为人物、事件或习惯真值 |
| S3-DG-11E | Habitat + Isaac/ROS dual platform（双平台） | 只做单一仿真器并把平台专属结果当通用结论 |
| S3-DG-12C | Complete neighbor audit（完整邻近系统审计） | 只选择容易复现或较弱的外部基线 |
| S3-DG-13D | Layered hybrid ingress（分层混合入口） | 评测时直接读取可变 Hub cache，或把八列元数据伪装成完整具身 episode |

## 2. 联合架构

```text
用户原话
  -> 多解析语言后验 {parse_i, p_i, unparsed mass}
  -> 每个可落地解析独立运行六通道融合
  -> 对 parse 后验边缘化，未解析/拒答质量进入 unknown
  -> 概率动态实例图 {existing instance, new instance, unknown}
  -> 可修订人物/事件提案，经验证后激活
  -> 习惯软证据只引用当前有效的事件 revision
  -> 主动观察 / Habitat 或 Isaac-ROS 执行
  -> 概率执行反馈写回并触发后验与修订更新
```

双平台使用同一个 task manifest（任务清单）、action semantics（动作语义）、
outcome vocabulary（结果词表）、成本轴和评测规则，但运行时依赖隔离。这样既能使用
FindingDory/Habitat 的原生任务，又能验证 Isaac/ROS 中导航、抓取和放置的迁移有效性。

## 3. 已实现边界

### 3.1 S3-DG-09D

- 至少两个语义不同的解析假设；
- 解析概率与 `unparsed_probability` 必须归一；
- 每个非拒答解析必须有独立 grounding request（落地请求）；
- 不同解析必须共享候选 support（候选支撑集）和终止策略，防止比较口径漂移；
- 未解析和拒答质量只能进入显式 `unknown`，不能被丢弃或分给最佳实例。

### 3.2 S3-DG-10D

- 显式维护已有实例、新实例和 `unknown` 的归一关联后验；
- 视觉、3D 和 re-ID 似然在 log space（对数空间）累积；
- 同一 `evidence_cluster_id` 只能消费一次；
- anchor（锚点）和 frame（坐标系）不一致时拒绝更新；
- 只有通过概率阈值和 margin 的关联才写入动态地图。

### 3.3 S3-DG-14D

- VLM、sensor（传感器）、geometry（几何）、user（用户）和 action（动作）只产生提案；
- 人物提案必须绑定 authorization scope（授权范围）；
- 事件只能引用当前已验证的人物 claim（声明）；
- 修订日志支持 verify、reject、retract、supersede 和 reactivate；
- 习惯 soft count（软计数）不能超过“事件验证概率 × actor 后验”；
- 事件撤回后，派生习惯自动退出 active projection（有效投影），历史不被删除。

### 3.4 S3-DG-11E

- Habitat 与 Isaac/ROS 分别绑定 runtime hash（运行时哈希）和 adapter version（适配器版本）；
- 两侧都必须覆盖冻结的观察动作、机器人动作和模态；
- 每个平台、每种执行动作都必须绑定 outcome model（结果模型）和 calibration domain（校准域）；
- 任一侧能力缺失时，语义一致性检查失败。

### 3.5 S3-DG-12C

首批完整审计集合固定为：FindingDory official agent、VLMaps、DynaMem、
ConceptGraphs、ReMEmbR、Embodied VideoAgent。每项必须满足以下三态之一：

1. `runnable`：固定 upstream revision、源码哈希和适配器版本；
2. `excluded_with_evidence`：有明确范围理由和可核验材料；
3. `pending_reproduction`：保持待办，并阻止封闭比较启动。

当前六项全部为第三态。这是诚实的进展状态，不是复现完成声明。

完整 pending registry（待复现登记表）已由
`apps/evaluation_runner/initialize_direction_three_external_audit.py` 生成到
`output/direction_three/external_audit/selected_neighbor_registry_v0_1.json`。比较 CLI 一旦
发现 `external_system=true`，现在强制要求 `--external-audit`；审计仍含 pending 或运行
结果没有覆盖全部 runnable 系统时，sealed comparison 直接拒绝启动。

### 3.6 S3-DG-13D

- Hub 获取必须固定 40 位 commit SHA；
- Hugging Face `datasets` 只在 acquisition layer（获取层）延迟加载；
- 获取结果规范化为排序键、稳定分隔符的 JSONL，并记录 SHA-256；
- 规范 artifact（制品）不可原地覆盖，评测前重新验哈希；
- `pyarrow` 继续负责原始 Parquet 旁路；
- `datasets` 与 `pyarrow` 位于可选依赖组 `findingdory`，不污染核心运行时。
- CLI 入口为
  `apps/evaluation_runner/prepare_direction_three_findingdory_layered.py`，同时生成规范
  JSONL 和独立 manifest；两者路径不能相同，也不允许无提示覆盖。

2026-08-26 核验到官方 `yali30/findingdory` 当前提交为
`016160dd7ec1d0d23aa09bba7d48470e835030a0`。第一次固定 revision 的三行流式验证
遇到 HTTP 429；等待限流窗口后的一次受控重试成功。3 行全部通过严格 schema，规范
artifact 与 manifest 已发布到
`output/direction_three/findingdory/016160dd7ec1d0d23aa09bba7d48470e835030a0/`，
完整结果见 `docs/experiments/direction_three_findingdory_layered_ingress_v0_1.md`。这只
证明真实八列元数据入口，不证明视频、实例转移或完整具身 episode 已接入。

## 4. 仍未完成，不能提前宣称

- 真实 LLM ensemble（集成）、解析采样、温度/提示敏感性与校准；
- 真实 detector/segmenter/3D reconstruction/re-ID（检测、分割、三维重建、实例重识别）；
- 经授权的多人物跨时跟踪、真实事件验证和长期习惯估计；
- Habitat FindingDory sidecar 与 Isaac Sim/ROS 2/Nav2/MoveIt 2 sidecar；
- 六个外部邻近系统的固定版本复现或证据化排除；
- 官方 FindingDory 固定 revision 的真实下载与 artifact 发布；
- 从语言、感知、证据图、主动确认、机器人执行到长期反馈的真实多步端到端实验。

这些项是下一阶段实施清单，不是缩减候选项。任何外部系统已覆盖部分能力时，先标出
覆盖边界，再在多解析边缘化、动态实例图、可修订证据传播或双平台迁移中形成方法级创新，
不以“已有工作覆盖”为理由删掉完整结构三。
