## 操作与覆盖

同一房屋、同一 Apple asset，北/南两个目标摆放条件 × 原生 320/640 分辨率 × 直接初始化 225° / 从 270° 实际左转 45° × 两次新进程启动，共 16 格。每格首个命令为 Pass 或 RotateLeft，随后 7 个 Pass，共 128 帧。第二次重复交换两初始化路径的执行顺序；未根据检测结果选择帧或提前终止。FOV 60°、俯仰 30°与实际相机位置逐帧核对；苹果为 kinematic，其他物体保持原场景设置。

公共输入仍只有现有 RGB/动作状态。新增 worker 将完整 SDK 元数据写入 evaluator_only 后返回原公共响应对象；两模型预测生成后才读取私有实例掩膜进行评价。SSDLite 与 Faster R-CNN 使用既有官方权重和 0.5 过滤值，不重选模型/阈值。

执行顺序：第一轮 31 项测试通过；实际新采集 8 帧合法夹具；第二轮 13 项测试通过；Ruff 通过；完整 16 格采集；对同一 128 原图重新执行两模型，共 256 次帧推理，所有完整输出、分析与汇总逐字段一致。六条命令均 0 退出，Python/依赖源图始终一致。两轮为 A 顺序自审，包含完整合法序列、完整一致伪造阳性、重新封装后的漏帧、错误掩膜摘要、完整元数据位姿篡改，以及公共响应/视觉依赖绑定；不冒称覆盖整个结构二或 B 独立验收。

运行前后 SDK 的 27 个 Python 文件与 Unity app 的 166 个文件摘要一致；实际 ai2thor 5.0.0、SDK Python 3.11.16、默认质量 Ultra。模型环境复用上一批锁定依赖，非独立安装。详见 evidence/repeatability-attempt01/commands.json、source.json、runtime-verification.json。

全部 16 格相机及目标几何检查通过，格内 8 张目标掩膜逐字一致。南侧 320 的四格都在第一帧检出、以后七帧漏检，直接初始化和实际转动两种路径均出现；对应的南侧 640 四格始终检出。北侧 640 全部 32 帧无目标像素仍报告 apple，不能据类别阳性计作成功。

同一格第一帧到最后一帧的全图 RGB 绝对字节差均值为 14.7103–14.9600（0–255 字节尺度），南侧目标区域为约 10.7885（320）或 10.8828–10.8831（640）。这不是位姿变化。128 帧全部 `isSceneAtRest=false`；其他物体相对初始状态的最大坐标分量位移为每格约 0.00802–0.00868 米，最大欧拉角分量变化约 21.13–22.83°，不是欧氏距离或刚体旋转角。目标固定并不意味着整个世界静止。

最后两帧的 640 图像相同，320 仍有小范围变化；八帧不足以证明长期稳定。不同初始化路径在相同帧序号配对，共 64 对，目标掩膜全部相同，RGB 均不完全相同，但全图差均值仅 0.000157–0.029639。相同路径两次启动的 64 对中 46 对 RGB 完全相同，其余差均值最高 0.029430，掩膜全部相同。这说明本次最明显的读数变化与启动后帧序号相伴；不能把曾经的直接初始化首帧与转动后第二帧比较解释成单纯的转动路径效应。

完整元数据证实存在物理演化，图像也存在启动阶段变化。尚未做冻结物理/显式步进/渲染时间的干预对照，因此不能断言物理运动、曝光或任何单一因素造成全部变化。重复观察在这个固定场景中可复现，仍不构成独立场景的误差率或泛化概率估计。
