## 两轮审核及保留失败

- 第一轮 `round1-...-01`：6 个场景全部通过，包括 N=1/2/3/6、非法类型/数量/代次/请求字段后合法恢复、未建房拒绝。检查实际原始传输、唯一 ID、有限且分离的位置、RGB-D 数组和逐实体转向隔离。
- 第二轮初版 `round2-...-01`：连续状态机场景通过，覆盖重复请求、改请求/人数、非主 agent 请求、旧代次、主/副 agent 重初始化拒绝、reset 新代次后重新生成。
- 第二轮扩展 `round2-...-02`：**3 场景通过 / 1 场景失败**。连续状态机、持物边界及重复建房通过；`partial_house_failure` 在 `house_failure_reported` 断言失败。该失败仍为最终已执行的扩展结果，不被初版通过覆盖。
- 持物负例使用真实 `PickupObject(forceAction=True)` 准备非空库存，仅用于禁止复制持物状态的对抗边界测试，绝不是合法人类行为数据或完整训练输入。

### 失败根因与最新修复

`ProceduralTools.spawnHouseObject` 在资产 ID 不存在时只 `Debug.LogError` 并返回 null；递归对象生成继续，`CreateHouse` 最终仍报告成功。这会把缺对象的世界误称为成功建房，生命周期原型继承了该漏洞。

`f52271cf` 将该路径改为抛出 `ArgumentException`，由外层捕获建房失败并将 episode 标为不可继续，要求 reset。实现尚未重新编译或复测：当准备构建时，计算机工具明确返回 Mac 已锁定且不能自动解锁。不能把新修复标为关闭。
