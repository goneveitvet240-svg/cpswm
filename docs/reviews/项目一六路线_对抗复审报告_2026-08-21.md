## 3. 🔴 F3 — CF-BOCPD 名不副实（高严重度）

### 3.1 结构二的原始定义（三份文档）

- `方向结构二_MajorRevision_P0整改与创新边界_2026-08-14.md` §CF-BOCPD：
  > 已有覆盖必须明确提醒：BOCPDMS 已联合 \(p(r_t,m_t\mid y_{1:t})\)。**本项目不能把 \(m_t\) 改名为 \(C_t\) 就宣称创新。**
  >
  > 仍有价值的新增算子是：\(p(r_t,C_t,Z_t,\Theta_t\mid D_{1:t}),\ \Theta_t = R_{C_t}(\Theta_{t-1}, D_t)\)。其中 \(R_C\) 必须是可测试的 **selective reset operator**：observation cause 只更新观察模型，actor cause 只更新人物混合，identity cause 只更新关联，owner-habit cause 才允许更新个体阶段，noise cause 不改长期参数。

- `方向结构二_技术路线创新改进与首轮死亡测试_v0.1.md` 算子二：
  > **这不同于"BOCPD 后面接一个分类器"：原因变量直接改变转移核、危险率和哪些参数允许被重置，因此会产生不同的长期记忆状态。**

- `全框架统一总纲` line 105：
  > CF-BOCPD 的原因后验直接决定 RGRC 可以修改哪些长期参数，**而不是检测后仅输出标签**。

核心：CF-BOCPD 的唯一创新载体是**选择性重置算子 \(R_{C_t}\)**（不同原因只重置各自的长期参数块），并驱动下游 RGRC。

### 3.2 Codex 实际实现（`src/cpswm/world_model/habits_transitions/cause_factorized_bocpd.py`）

- 四个**完全独立**的标准 Adams-MacKay BOCPD 后验，`reset()` 里 `{cause: {0: 1.0} for cause in ChangeCause}`；
- 每路的 per-cause 似然（`continuation_likelihoods[cause]` / `changepoint_likelihoods[cause]`）由**调用方预先算好喂入**；
- **无 \(\Theta_t\) 长期参数块、无 \(R_{C_t}\) 重置算子、无实际维护的习惯阶段 \(Z_t\)、四路零耦合**；
- 输出为每个 cause 的 changepoint 概率——即"仅输出标签"。

### 3.3 逐条对照

| 结构二要求 | Codex 实现 | 判定 |
|---|---|---|
| 联合后验 \(p(r_t,C_t,Z_t,\Theta_t\mid D)\)，从共享 D 归因 | 四个独立后验，似然外部喂 | ❌ |
| 选择性重置算子 \(R_{C_t}\)（不同原因重置不同参数块） | 无 \(\Theta\)、无重置算子 | ❌ |
| 原因后验驱动 RGRC 能改哪些长期参数（非仅标签） | 仅输出 changepoint 分数 | ❌ |
| 必须区别于"BOCPD+分类器 / 每信号独立跑" | 就是每信号独立跑 | ❌ |

## 4. 其他发现

### 🟠 F1 — 习惯模型残差模式的审计不一致（已实测证实）

`HierarchicalDirichletHabitModel` 开启 `actor_residual_weight` 后，`HabitPrediction.pseudo_counts` 返回的是 `household_scores`，而 `probabilities` 是收缩混合结果。实测（3×L1 + 1×L2，residual_weight=0.5）：

```
probabilities   : {L1: 0.7099, L2: 0.2901}
pseudo_counts→归一: {L1: 0.70,   L2: 0.30}
audit reconstruct consistent? False
```

`HabitPrediction` 文档称 pseudo_counts 是"支撑 probabilities 的伪计数"，在残差模式下失真——审计字段无法重建输出。建议：残差模式下让 pseudo_counts 反映实际混合，或在契约上明确 pseudo_counts 仅对默认模式有效。

### 🟠 F2 — "非住户隔离"作用范围窄于名称

隔离只门控 household 聚合通道（`household_weight = weight * resident_mass`）；person/context 计数循环仅排除 `unknown_actor`，**已知非住户访客仍完整写入其自身 person/context 模型**。主人预测不被污染（读的是主人自己的 key），但"隔离"实际只作用于共享通道一路。建议：补一条测试固化"访客放置不移动主人预测"，并在文档/命名上明确隔离范围。

### 🟠 F6 — 公平消融是"声明预算"非"实测预算"

`FairAblationManifest` 只校验各臂**声明**的 budget/trace/test-split 相等，不校验实际运行是否在预算内。一个臂可声明 `maximum_parameter_count=1000` 却实跑 10⁹。**这与 F0 第一轮对抗审查的 F-4（declared≠measured）同类**。建议：把关键预算改为运行时实测并绑定，或明确降级为"自声明字段"（如 F0 对 `model_versions` 的处理）。
