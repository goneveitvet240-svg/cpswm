# 第一轮：真实神经评分进入原生联合状态

实现 `NeuralNativeProducer`，用已有三种 proposal（提议）网络的真实开发检查点重新计算完整分解概率，再由原生粒子消费者复验。候选/测量模型需显式配置并绑定实现；不把开发检查点变为 production-authorized，不改变自然视觉资格、长期账本写入门或既定研究范围。

当前仅覆盖 branch 与 preserve_unresolved 的有限支撑枚举。每个配置候选恰好一次，积分系数设为 q，抵消重要性权重中的 1/q。否则将枚举误作从 q 随机抽样，会错误偏向低提议概率候选。此处 posterior（后验）取决于原有目标密度，网络 q 不应凭空改变精确枚举后验。本轮是执行/接线正确性，不是神经加速或效果优势；完整六操作学习核和自然联合训练仍未闭合。

输入由实际已接受的机会、检测、父粒子/完整历史、快照地点、账本头构成，不输入任务标签或隐藏仿真状态。保存精确 typed 输入和支撑，不将 RGB 历史递归复制到每条证明。消费者从自己拥有的原生历史重建同一输入，然后重跑模型。共享证据 revision 的候选采用确定性的 per-world-line 视图名字，原生证据没有改写。保留 unknown 支撑，乱序字典不改变祖先顺序。

配置时 core 固定 producer binding 及神经验证模块源码摘要；之后不能换成另一个真实但未配置的检查点。合法发布、持久恢复、完整重封概率伪造、可见输入/账本替换、无证明积分系数、已加载代码替换分别测试。验证缓存只复用本进程已实际重算的内容，缓存命中仍核验模型/文件/执行依赖。保护范围为拥有的 Python 代码与当前检查路径，不是防御任意解释器/全进程内存篡改的安全沙箱。

12 个受控原生来源的长历史测试：撤回一个已消费来源后，旧视图禁止读取，重新计算保留的 11 个来源，建立新 runtime generation（运行代），再从 SQLite 恢复相同视图和 producer 状态。重放不是局部神经 rejuvenation，也没有补造接触、释放、人物身份或位姿标定。

两轮顺序自审由 `run_frozen.py` 在同一 Git SHA 执行，每条命令前后核验所有已跟踪 Python/依赖文件等于该提交，拒绝未跟踪 Python。第一轮侧重计算、合法发布和完整伪造正路径；第二轮侧重12来源纠错、恢复、依赖和加载代码攻击。随后跑三种真实检查点的同一长历史。独立审核人数仍为0；B正式比较/验收不由本轮替代。

## 实际开发反例

`evidence/development/verifier-pre-fix.log` 记录一个真实生产缺陷：将已加载的 `verify_neural_evidence.__code__` 换为空函数后，完整重封的假概率包未被原消费者拒绝。新增源码编译结果对照实际加载函数及导入别名的核验，复现测试修后通过，同时合法包继续可消费。首次代码核验误把 dataclass 生成函数当成源码声明函数；改为以独立编译出的声明函数列表为准。

其他早期失败：包含 RGB bytes 的 proof 无法 JSON 摘要；改为存 typed 输入并由消费者重建原生上下文。旧受控 fixture 在第二步丢失显式 preserve_unresolved；保留原生产 unknown 门，为本轮新增正确 fixture，未放宽支撑校验。这些开发失败均不计作冻结版本通过。
