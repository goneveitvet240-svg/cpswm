## 0. 为什么不能只加一个 enum 值

`fair_ablation.py:104`：

```python
required = {arm_id.value for arm_id in ProjectOneAblationArmId}
```

必需臂集**从整个 enum 推导**。一旦给 enum 加 `JOINT_CAUSE_FACTORIZED_BOCPD`：

- `ProjectOneFairAblationManifest.require_project_one_arms` 立刻要求 11 臂 → 旧 10 臂 manifest 判“缺第 11 臂”；
- `ProjectOneProtocolPilotManifest.validate_complete_topology`（每臂恰一次）与 `arm_results` 固定 `min_length=10,max_length=10`（pilot:222）与旧报告冲突；
- `comparisons` 固定 `min_length=5,max_length=5`（pilot:155），SHIFT 仍是二臂拓扑。

已提交资产必须保护：
- `benchmarks/project_one_ablation/project_one_protocol_pilot_v0.1.json`（config，`protocol_version=project-one-ablation-protocol-pilot@0.1`）；

## 2. v0.1 ↔ v0.2 schema 如何并存（核心设计）

**原则：v0.1 的类字段/校验器/默认值一律不改（保证反序列化与 content hash 不变）；所有 v0.2 行为放进新类。唯一对既有类的改动是把“必需臂集从 enum 推导”改成“从冻结常量取”——这对合法 v0.1 内容行为等价，且只影响校验、不进入 hash。**

### 2.1 enum（`fair_ablation.py`）
- 追加成员 `JOINT_CAUSE_FACTORIZED_BOCPD = "joint-cause-factorized-bocpd"`（末尾，不改旧成员值）。
- 追加两个冻结常量：
  ```python
  PROJECT_ONE_ARMS_V01 = frozenset({ ...现有 10 个 value... })   # 显式冻结
  PROJECT_ONE_ARMS_V02 = PROJECT_ONE_ARMS_V01 | {JOINT_CAUSE_FACTORIZED_BOCPD.value}
  ```

### 2.2 兼容性修复（唯一对既有类的改动）
- `ProjectOneFairAblationManifest.require_project_one_arms`：把
  `required = {arm_id.value for arm_id in ProjectOneAblationArmId}`
  改为 `required = PROJECT_ONE_ARMS_V01`。
  - 效果：合法 v0.1（正好 10 臂）行为不变；加 enum 成员**不再**回溯要求它。
  - 不影响 content hash：该校验器不参与 `content_sha256`；旧报告存的是 arm_id 字符串，enum 加成员不改这些字符串。

### 2.3 新增 v0.2 类（不动 v0.1 类）
- `ProjectOneFairAblationManifestV2(FairAblationManifest)`：`require` 用 `PROJECT_ONE_ARMS_V02`（11）。
- pilot 侧新增：
  - `ProjectOneProtocolPilotManifestV2`：`comparisons` 仍 5；但每臂恰一次的必需集 = 11；`protocol_version` 记为 `@0.2`。
  - `ProjectOneProtocolPilotReportV2`：`arm_results` `min_length=11,max_length=11`；`formal_experiment_ready: Literal[False]`；`claim_scope: Literal["protocol_only"]`（B1 不变）。
  - `ProjectOneProtocolPilotRunnerV2`：产出 v0.2 manifest/report；joint 臂走 unbound 分支。
- v0.1 的 `ProjectOneProtocolPilotManifest / ...Report / ...Runner / ProjectOneFairAblationManifest` **一字不改**。

## 4. 三臂 comparison 如何表达

```python
_COMPARISON_ARMS_V02 = {
    **_COMPARISON_ARMS,   # 其余 4 组二臂不变
    ProjectOneMatchedComparisonId.SHIFT_CAUSE_FACTORIZATION: (
        ProjectOneAblationArmId.ORDINARY_BOCPD,            # control / baseline
        ProjectOneAblationArmId.CAUSE_FACTORIZED_BOCPD,    # legacy independent（旧 ID，标 legacy）
        ProjectOneAblationArmId.JOINT_CAUSE_FACTORIZED_BOCPD,  # new joint
    ),
}
```
- v0.2 的 comparison 拓扑校验：SHIFT 组要求这个**有序三元组**，其余 4 组仍要求各自二元组；`baseline_arm_id = ordinary-bocpd`。
- 旧 ID 语义澄清：在 `_model_version` / 注释 / 报告 note 里把 `cause-factorized-bocpd` 显式标注为 “legacy independent-per-cause baseline”，`joint-cause-factorized-bocpd` 标为 “joint (real CF-BOCPD)”，避免旧 ID 被误解为 joint。
