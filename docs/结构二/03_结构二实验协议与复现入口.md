## 2. 主效用与硬护栏

### 主效用

PCT（惩罚后任务完成时间）使用等效秒数。优效要求：

```text
相对点估计改善 ≥ 10%
绝对点估计改善 ≥ tau_verify
配对一侧 95% CI 下界 > 0
任务成功率下降不超过 2 个百分点
全部硬护栏通过
```

`tau_verify=max(5秒,D2 pilot 标准验证行动中位时长)`。每个任务族的
`T_max=向上取整到5秒(max(2×匹配基线成功时长中位数,匹配基线成功时长p95))`。D1 的动作秒数
来自 D2 pilot，不使用 Unity 程序墙钟时间。

### 污染与恢复

| 门 | 阈值 |
|---|---:|
| C1 短期、未影响行动 | 点估计 ≤1%，95% 上界 ≤2% |
| C2 已影响行动、可恢复 | 点估计 ≤0.5%，95% 上界 ≤1% |
| C3 长期人物污染 | 最终未恢复 0；发生率 95% 上界 ≤0.5% |
| recovery p95 | 首次决定性反证后 ≤3 次有效机会、≤10 行动步；D2 ≤60秒 |
| C1/C2 最终未恢复 | 点估计 ≤1%，95% 上界 ≤2% |
| 安全/隐私严重事件 | 0 |

### Full-rerun equivalence

- belief：关键轴 TV p95 ≤0.05，最大值 ≤0.10；
- action：top-1 一致率 ≥99%，action TV p95 ≤0.05；
- utility：TOST 90% 区间同时在相对 ±2% 和绝对 ±0.2 `tau_verify` 内；
- 人物身份、提交/撤销、权限、安全和隐私状态：完全一致。

### 动作构念的当前适用边界

上述 PCT、SEARCH（搜索）和 PUT_BACK（放回）指标是目标协议，不代表历史 Route C v0.2 已经实现该
合同。v0.2 用同一无类型地点 UUID 分布同时计算 SEARCH、PUT_BACK 和旧 contamination 指标；主两臂
54/54 次均选择当前位置，44 次 `action_success=true` 对应 0 次实际状态改变，search regret 非零为
0 次、put-back errors 为 30、旧 proxy events 为 18。因此旧工件只能证明 transition API 被调用，
不能证明任务分离动作、非空 action-responsive behavior（动作响应行为）、组合效用或长期人物记忆污染。

`structure-two-action-utility-construct-gate@0.1-development` 是单独的 3-step D0 正路径诊断：它使用
绑定同一决策前信息集的 typed SEARCH/PUT_BACK，SEARCH 不改变环境状态，PUT_BACK 产生 1 次成功
nonnoop 实际状态改变；有 1 个 step 中 SEARCH 与 PUT_BACK 选择了不同 location。SEARCH-only
control 使搜索遗憾从 0 增至 0.5 而放回不变；PUT_BACK-only control 使放回错误从 0 增至 1，同时
`execution_success=true`、`goal_satisfied=false`，搜索不变。它证明两类指标 wiring 可被独立复算；
readout 还绑定 run/source/step/visible observation，并在 fresh recomputation（鲜重算）
路径中经过不序列化的 instance-local single-use capability（实例局部单次能力）检查；
这不是独立托管证据。
`combined_utility=UNRESOLVED_NOT_AGGREGATED`，长期产品动作语义与长期污染尚未建立；历史 Route-C
与 P0–P5 后果性轨迹的 production runtime identity（生产运行时身份）、科学优越性和 Task 8 正式
通过均为 false。legacy ordinary Architecture-A binding（历史普通转移的 A 架构绑定）则已成立。

2026-09-10 项目所有者选择 `P5_FIRST`：下一项 D0 死亡测试先在完整七算子 P5 full-eager 路径上
使用 typed SEARCH/PUT_BACK，以验证完整计算路径能否产生非退化行动差异；完整动作族继续保留。
adaptive router 的主选择采用 validation-only calibration，固定解析阈值保留为基线，确认集不得参与

## 3. 对照与消融

系统级必须比较：

- 完整结构二；
- matched AMG/full-rerun 类强邻居；
- learned matched two-stage；
- 普通 RBPF/粒子方法；
- append-only、reweight-only 和 full-rerun 修订策略；
- no-VLM、VLM prior-only、VLM evidence-proposal、VLM direct-decision、oracle。

七算子消融只有在依赖回执全部通过后才可正式运行。每个移除算子都要换成信息、容量和计算匹配的
直接替代方法，不能简单设成 no-op 后宣称贡献。

Route C v0.2 的 seven-operator neutralization（七算子中和）是正式消融前的**开发诊断**：冻结
evaluator 内仍生成各算子的自报告调用与回执，只把独有作用替换为预先注册的中性元，用来检查局部
计算路径是否到达 evaluator-local action posterior。它不证明 `StructureTwoProductionSystem` 中的
具体算子实例被调用，也不证明其输出被下游动作、环境转移或下一状态消费；更不能替代上述信息/容量/
计算匹配的正式替代臂或单独授权“算子有贡献”。

## 8. 独立确认运行前清单

在第二台机器开启确认集前，必须同时存在：

- 冻结的 Git commit、依赖 lock、模型 revision 和 prompt hash；
- 未被开发方查看的 house/actor/schedule seeds；
- 独立账户、签名密钥和 trust-anchor enrollment（信任锚登记）；
- 数据、参数、状态访问、训练和推断计算预算匹配证明；
- 每条 consequential trajectory（后果性轨迹）绑定 `runtime_execution_id`、`operator_instance_id`、
  `callable_symbol`、`invocation_id` 和 `consumed_output_ids`，并证明算子调用—输出—动作读出—环境
  转移—下一状态的依赖链；
- D2 pilot 产生并预先登记的 `tau_verify`、`T_max` 和动作时长表；
- C0--C3 标注指南和双人冲突裁决规则；
- privacy/safety incident（隐私/安全事件）记录和失败关闭规则；
- 原始输出、日志、失败 episode 和 Pareto 失败点完整回传。

任何一项缺失，都只能产生开发或诊断结果，不能写成论文级确认。
