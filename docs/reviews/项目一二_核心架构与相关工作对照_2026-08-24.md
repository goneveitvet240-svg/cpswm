## 第二部分　项目一：核心架构

### 2.1 自动状态判断链（前向路径）

```text
连续机器人可见习惯证据
  → Joint CF-BOCPD          仅提出变化候选，p(r_t, C_t) 联合 beam
  → confirmation window     候选先隔离（quarantine），不写任何长期统计
  → CCRR                    create / reactivate / stay / unresolved
  → RLSRegimeBank            自动切换或保留 head，旧 regime 参数与协方差不衰减
  → HierarchicalDirichletHabitModel   人物条件化位置分布
  → HybridStatisticLedger（Hybrid RGRC） 来源簇绑定的可逆充分统计量
  → VersionedBeliefMap       原子信念地图版本
  → 搜索 / 归位建议
```

### 2.2 五个真正承重的技术点

**① 统一 owner 统计权重**

```text
statistical_owner_weight = owner_posterior × evidence_weight × IPW
```

同一个值原样进入 RLS 加权更新、Hybrid RGRC delta 和 Dirichlet 贡献——三条统计
分支不允许各算各的。合法的 `IPW > 1` 不再被 RLS 静默截断（这是把"选择性观察校正"
真正接进统计层，而不是当预处理掩码）。

**② 有界超额惊讶度（bounded excess surprise）**

```text
q = -log(p) / log(K)
surprise = 1 - exp(-max(0, q - 1))
```

均匀概率在任意位置类别数 `K` 下都映射为 0；比均匀更差的仍保留严格严重程度排序，
不会在 1 处截平。这条是为了让"K 不同的物体"可比。

**③ habit cause signal 需要两路同时发声**

位置改变本身不再产生满值信号，必须 **位置改变 + Dirichlet predictive surprise +
RLS target residual** 共同出现。RLS residual 经 `1 - (1-r)²` 映射后与 surprise 做
概率并集，两路 guardrail 权重各自可配（默认 0.1，非论文冻结阈值）。

**④ 三阶段事务 + 时间序重放**

修订事务固定 `hybrid → dirichlet → rls` 三个故障注入点，任一阶段失败则
Dirichlet 参数、RLS 充分统计量、Hybrid 可重放日志与谱系、信念地图快照、
regime 路由状态**一起回滚**。重放按 `event_time` 排序，因此遗忘因子 `f < 1` 时也必须
等于从头做的时间序重放，不能依赖 revision 字典插入顺序；重放还会重新给每条
RLS sample 分配 regime head，禁止沿用被撤销变化点产生的旧标签。

**⑤ 派生证据谱系与墓碑**

强化统计保存 `derived_from_revision_id`。父 observation 被撤销 / 修正 / 重新隔离时，
所有多层派生后代递归撤出三套统计。恢复语义由 `DerivedEvidenceReactivationPolicy`
显式控制（默认 `require_fresh_feedback`）；显式 retract 写永久 tombstone，
显式 correct 只保留修正版本，祖先失效写 ancestor-invalidated tombstone——都不得从
archive 自动复活。

### 2.3 当前诚实成熟度

* 工程进度约 78% 核心原型；
* 系统更接近"**带隔离窗口的 regime 状态机 + RLS 多头模型**"，个性化模型残差尚未成为
  变化判断的主要输入，**不能**宣称已完成"残差驱动、可逆且严格在线的持续习惯变化判断系统"；
* 评测 v0.3（2026-08-24）：多 seed 扩到 300 条测试流后，项目历史上第一次拿到
  `CONCLUSIVE`——`full` 相对 `no_rls` 变化确认 **+0.100**（CI [+0.078, +0.123]，误切换代价 0），
  相对 `shuffled_rls` 配对间隔 **+0.043**（CI [+0.036, +0.051]），24 项对照 SIG=13 / NULL=11 / inconclusive=0。
  **仅限合成基准**，不构成外部有效性或具身效用。

## 第三部分　项目二：核心架构

### 3.1 端到端链

```text
ObservationDetectionResult (before @ L1, after @ L2)
  └─ CHEH branch ─────────► 开放世界隐藏事件假设
                            （direct + handoff，按责任人物；+ unknown-mechanism 质量 + unresolved 质量）
ExecutionFeedbackRecord（搜索 / 放置结果）
  └─ ExecutionFeedbackProjector → ProjectedFeedbackEvidence（类型化路由、似然感知、快照绑定、去重）
  └─ 校准因子 r        search：presence Bayes factor；transition：候选方向校准似然因子
  └─ ActorResponsibilityEvidence   每个已知责任人物带 r；unknown_actor 中性 → 开放世界增长
  └─ PCHMP.infer      来源防火墙 + 单次消费下重新传播联合后验
  └─ ORRER.revise_*   一次可逆、父链绑定的修订
  └─ EventRevisionOutcome → ProjectOneStatRequest（RETRACT / CORRECT / REINFORCE）
```

### 3.2 六个真正承重的设计

**① 强度而非事实（strength, not fact）**
反馈永远只产生贝叶斯因子 `r = odds(posterior)/odds(prior)`，失败 `r<1`、成功 `r>1`，
幅度完全来自 `ActionOutcomeLikelihoodModel`。`retraction_threshold = 0.0`——反馈只
**重新加权**，永远不硬清零某个假设。

**② 两种修订模式必须分开**
- 仅存在性证据（一次搜索成功/失败）：同一个 `r` 加到每个已知行为者，因此**只能**修订
  事件存在性置信度，主人 vs 访客的相对赔率**按构造不变**；
- 行为者责任修订：必须显式提供 `actor_likelihood_ratios`（行为者区分通道），
  每个已知行为者按 `r × factor[actor]` 重加权，相对赔率才真的变。

把搜索失败写成"所以是访客干的"，正是这条设计要禁止的。

**③ 开放世界三类质量互不混淆**

```text
sum(concrete hypotheses) + unknown_mechanism_probability + unresolved_probability = 1
```

再加 `unknown_mechanism_actor_posterior` 单独审计"未知机制里已知/未知行为者"。
因此"已知机制+未知人物"、"未知机制+已知人物"、"未知机制+未知人物"三种情形保持可区分。

**④ 四道防火墙（都有测试）**
- `provenance firewall`：物体 id、目的地匹配、household/session/trace 双向一致、因果窗口
  `feedback.valid_time.start >= interval_end`；
- `StaleFeedbackError`：反馈观察窗口触及或跨越该物体后续已知移动 → 拒绝（窗口被后来的世界状态污染）；
- `LineageConflictError`：重放时呈现的历史 head 既不是缓存的 superseded 也不是 corrected → 拒绝；
- `ProjectionInputConflictError`：同一 feedback record 配不同 actor/transition 证据 → 冲突而非静默重放。

**⑤ 保持谱系的位置修正**
在别处成功放置时，向同一 ORRER 历史追加 `REVISE_LOCATION`，更新最新修订的
`destination_location_id` 与承载目的地的物理步骤；旧修订保持不可变，
`ProjectOneStatRequest.location_id` 从修订后的事件导出，因此事件历史与项目一不可能不一致。

**⑥ 多轴修订**
提供 `TransitionRevisionModel` 时，place/transfer 反馈升级为
`revise_event_mechanism → revise_role_binding → revise_actor_responsibility` 三个独立可逆的
ORRER 步骤，并断言其联合结果等于 PCHMP 在全部轴上的重新传播；没有转移模型时
**拒绝该路由**（`UnsupportedFeedbackRouteError`），绝不静默降级。

## 第四部分　项目纲领（两级）

### 4.1 总纲级（`项目总纲_持续个性化语义世界模型_v1.0.md`）

* **中心**：长期记忆驱动的持续个性化语义世界模型。主动搜索是下游能力，不是唯一中心。
* **状态**：`M_t = (G³ᴰ, E, R, V, H, B, P)` ——几何图、实体、关系、事件、习惯、信念、来源谱系。
* **七个 RQ**：表示能力升级 / 跨天实例保持 / 个性化习惯学习 / 未观测转移推断 /
  LLM 可追溯查询 / 任务执行反哺地图 / 适应与稳定的平衡。
* **九个子项目 SP1–SP9**，共享同一地图格式、实体 ID 与事件语义。
* **七个阶段 Phase 0–6**：标准 → 实例级地图 → 关系与习惯 → 隐藏状态 → LLM 查询 →
  任务耦合维护 → 长期部署。
* **六层评价**：地图质量 / 实例与关系 / 时间与事件 / 个性化与持续学习 / 语言查询 / 下游具身任务。
  下游指标不能替代地图与记忆指标。
* **准入红线**：与世界模型没有清楚接口、只换更大模型、只优化单个代理指标、
  另建不兼容格式、因历史代码反向改方向、把模块集成包装成创新——都不得成为主线。

### 4.2 结构二论文级（`方向结构二_全框架统一单篇论文创新总纲_v1.0.md`）

统一后验：

```text
B_t = p(L_t, I_t, S_t, A_t, E_t, Z_t, C_t, Θ_t | O_{1:t}, M_{1:t}, π^obs_{1:t}, U_{1:t})
```

八条不得静默缩减的决定里，对你现在最关键的三条：

1. 全部机制**共同组成一篇统一方法论文**，不拆成互不完整的多篇；
2. 已有项目覆盖某项功能，**不是**绕开、删除、降级或另找小空白的理由——先出"已有覆盖提醒"卡片，
   再围绕假设 / 潜变量 / 表示 / 更新算子 / 目标 / 监督 / 保证 / 决策闭环八个轴找方法创新；
3. 局部被强基线击败触发 **redesign**，不是删科学问题。（项目二被 matched AMG 击败，
   走的就是这一条。）

创新台账状态机：

```text
innovation unresolved → method specified → closest prior art checked → implementation complete
→ direct baseline passed → system ablation passed → embodied utility passed
→ external validity passed → paper contribution supported
```

**当前没有任何一个算子越过 `direct baseline passed`。** 因此对外表述只能用
"候选创新 / 工作方法 / 拟提出"，不能用"首次"。

### 6.2 工程与实验层面（这一部分才是你最近两周真正的产出）

**防泄漏 / 防造假**

1. `_BaseMethod.observe` 改为模板方法，顺序硬性固定 **预测 → 决策 → 学习**，
   子类只能实现 `_predict`（只读事件前状态）。修完链式 arm 的 log-loss 从 0.390 掉到
   0.529——**原来 0.23 的优势里有 0.14 是偷看来的**。
   通用测试：两条只在最后一个事件位置不同的流，最后一步位置概率必须完全相同。
2. `test_no_arm_peeks_at_the_event_it_is_scored_on` 对七个 arm 逐个参数化验证。
3. sealed test / validation 分离：validation seeds {101,103}，test seeds {211,223}，
   四个 episode 在 household / scene / object-family 三维互斥，
   tuning receipt 里 test episode ID 必须为空。

**不削弱基线**

4. BOCPD 基线从二元"是否移动"换成 **Dirichlet-multinomial categorical BOCPD**，
   充分统计量按 `context_key` 分层——与链式 Dirichlet 同一 pooling 层级。
   log-loss 0.607 → 0.560。削弱的基线不构成证据。
5. 每个基线给自己的 config 对象、独立调参、`config_hash()` 写进 `metrics.json` 与
   `predictions.jsonl`。
6. O-STaR / DynaMem / STAR 明确标为 **matched replay adapter**，不冒充忠实复现
   （缺 RGB-D / pose / voxel / caption / 具身技能输入）。

**量程与校准**

7. **sigmoid 源头修复（2026-08-24）**：`RLSHabitScoreHead.score_candidates` 底层是拟合到
   `{0,1}` 的最小二乘，原始输出**本身就是分数**，再套 sigmoid 把 residual 压进
   `[0.269, 0.5]`，任何一次移动的 habit signal 都不低于 0.466。
   已把 `apply_sigmoid` 默认改为 `False` 并在 bank 层透传；
   顺带修掉"regime 尚无 head 时两种量程返回同一个 `1/n`"的第二处 bug。
   修复后 `full` 与 `shuffled_rls` **首次分开**（确认率差 0.000 → 0.100，
   配对间隔差 0.002 → 0.031），`full` 误切换降 61%。
8. 保留 `LEGACY_SIGMOID` 显式重现旧读数，使修复前后可比。

**统计功效**

9. 每个场景族扩到 60 条 seeded 变体（测试流 5 → 300），确定性锚点原样保留并单独版本化。
10. **重采样单元是 stream 不是 event**——一条场景里 20 个事件共享 regime、位置词表和
    变化点，按事件 bootstrap 会把区间缩小约 √L 倍，把相关性制造成显著性。
11. **三分判决**：`significant` / `null_result`（功效充足且跨 0，这本身是发现）/
    `inconclusive`；整体只在 inconclusive 为零时才判 `CONCLUSIVE`。
12. `powered_sd = max(empirical_sd × 1.5, 0.05)`，`required_pairs = ceil(7.849 σ²/MDE²)`。

**语义正确性**

13. **分桶键从 `(household, actor, object)` 改为 `(household, subject_id, object)`**。
    按 actor 分桶会把 `biased_observation` 的访客日切成独立分桶，等于凭空造出
    "访客的杯子习惯"模型——**那等于把 RQ8 要研究的问题从数据里删掉**。
    改成 subject_id 后访客事件留在主人分桶内、被 `owner_mass` 正确降权。
14. seed 由三元组 sha256 派生而非计数器（CPython 字符串 `hash()` 按进程加盐，
    会让每次运行日志都不同而所有产物还声称自己有 seed）。
15. 位置词表**声明**而非从观测推导，把误报家族留在分母里。

**不可识别性诚实标注**

16. D0 结论：不含人物证据时，**访客变化与主人习惯变化在机器人可见日志中完全等价**，
    位置基线的 actor→owner leakage = 1.0。现已显式标为 `non_identifiable`，
    正确做法是**输出未决并触发可用干预**，而不是猜单一标签。
    受控噪声/oracle 人物后验把泄漏降到 0——但那只说明人物信息够用，
    **不是 CHEH/PCHMP 的创新收益**。

   这是 CF-BOCPD 从 `implementation complete` 走到 `direct baseline passed` 的唯一路径。
3. **数据外部有效性**：D0 只有 2+2 household，任何 CI 都不稳。推进 D1 simulator / D2 真实感知回放。
4. **OPCEU / PCHMP / CCRR**：仍是 working specification。在没有实现前，
   "观察过程感知"和"来源约束消息传递"不能进论文贡献列表。
5. **补检索**：新增近邻 MEMORA、Learning to Forget、Multi-User Personalisation in HRI、
   Learning to Evolve Scenes 需要各出一张"已有覆盖提醒"卡片。
