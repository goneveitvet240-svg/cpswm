## 1. 项目二：可逆修订收益接到 next-action 读出

### 1.1 真正的失败点

v0.2 的判决说「可逆反馈收益没有及时转化为 next-action put-back 和恢复优势」。
定位到具体一行：

```python
# project_two_action_benchmark.py，v0.2
distribution = self.spine.action_location_distribution(snapshot)
put_back = _argmax(self.locations, distribution)
```

而 `action_location_distribution` 就是归一化的 `hybrid_alpha`——**一个 actor-blind、
time-blind 的累计计数**。与此同时 `_current_suggestion()` 里已经有更好的读出
（当前 regime 的 Dirichlet × RLS），但它只喂给地图的 `suggested_location_id`，
**从来没有到达行动基准的 planner**。

对照 matched AMG 的读出：

```python
put_back = self.amg_owner_location or _argmax(self.locations, self.counts)
```

即「**最近一次被归因给主人的位置**」。而评测的 put-back 打分对象正是
`true_owner_habit_location`。所以 AMG 赢的不是推断能力，是**读出选择**。

### 1.2 改了什么

在 `CorePrototypeSpine` 上新增显式的 planner 读出策略：

```python
class ActionReadout(StrEnum):
    HYBRID_ALPHA = "hybrid_alpha"                    # 冻结的 v0.2 边界，仍是默认值
    REGIME_LOCAL = "regime_local"                    # 当前 regime 的 Dirichlet × RLS
    SURVIVING_OWNER_REVISIONS = "surviving_owner_revisions"
    REVISION_AWARE = "revision_aware"                # 三者加权混合
```

`ActionReadoutConfig` 携带 `owner_mass_floor`、`recency_half_life`、三路权重、
`pending_correction_discount`、`active_regime_only`，并在构造边界做区间校验。

`surviving_owner_revisions` 直接读 `self._committed_events`——它是**权威的存活集合**：
显式 retract 删除条目，correct 用修正版本替换，rebuild 按 `event_time` 重新提交。

### 1.3 一条必须写清楚的归因边界

**`surviving(hl=0, floor=0)` 与 pooled hybrid alpha 在决策层完全等价**，有测试钉住
（`test_a_flat_surviving_readout_changes_no_decision_at_all`）。

所以收益**不是**「读了另一个池子」，而是 **recency 衰减 + owner-mass 门控**。
验证扫描（validation-only，2 户）：

| 读出 | put ↓ | contam ↓ | recovery ↓ |
|---|---:|---:|---:|
| pooled alpha（冻结 v0.2） | 0.3281 | 0.0156 | 3.08 |
| surviving, floor=0.5, **hl=0** | 0.3281 | 0.0000 | 3.08 |
| surviving, floor=0.0, **hl=1.0** | 0.2188 | 0.0625 | 1.50 |
| **surviving, floor=0.5, hl=1.0** | **0.1719** | **0.0000** | **0.00** |

结论：**recency 是必要条件，owner-mass floor 单独无效、与 recency 合用才把污染压到 0。**
而 actor-blind 的 recency 基线（0.3255 put / 0.2513 contamination @24 户）说明
「在存活的主人归因证据上做 recency」才是关键，不是 recency 本身。

## 2. quarantine → feedback 交接门

### 2.1 原假设是错的

v0.2 报告写「其余 6 个请求对应仍在 quarantine、尚无可撤销 live statistic」。
实测这 5 个请求（2+3）全部是 **REJECTED**，不是 deferred。逐条分类后：

| 数量 | 状态 | 原因 |
|---:|---|---|
| 4 | deferred_due_to_quarantine | superseded 事件仍在隔离；重试绑定到它的晋升——**后来都晋升并应用了** |
| 3 | rejected | CCRR 把被隔离事件判为 **short-term disturbance** 并丢弃 |
| 2 | rejected | superseded revision 已被更晚的修正取代（**stale lineage head**） |

deferral 路径本来就是通的（`_commit_event` 会调 `retry_deferred_project_one_requests`）。
真正的缺口是 rejection，而且其中「既不是 committed 也不是 quarantined」这条
rationale 把两种完全不同的情况混在一起。已拆开命名。

### 2.2 改了什么

新增 **action-scoped negative ledger**：当一个负向 owner-mass 请求被拒绝或延迟时，
按 fingerprint 记下 `(location, delta)`；请求一旦 APPLIED 就释放该条目（否则同一条证据
会推动 planner 两次）。`pending_correction_mass()` 汇总 deferral + action-scoped negatives，
读出层可按 `pending_correction_discount` 打折。

设计原则一句话：**RGRC 的隔离管的是「能不能写进长期记忆」，不是「机器人下一步该怎么做」。**

### 2.3 诚实的 null 结果

在 D0 上，`pending_correction_discount` 从 1.0 一直调到 0.0，
**四项主指标一个字节都没变**（pooled 与 surviving 两种读出下都是如此）。
机制确实在跑（实测第 8 步起有一条 −0.1133 的负证据挂在账本上），
但那个位置从来不是 planner 选中的位置。

更深一层的解释：一旦 planner 改读**存活集合**，被 CCRR 拒绝的证据本来就不在里面——
交接缺口是被新读出**顺带关掉的**，不是被这个折扣关掉的。
所以该旋钮在参数空间里保持惰性（1.0），账本作为**审计面**保留：
5 条拒绝现在全部有名字、可计数。D1 上 426 个请求里 45 个被拒（10.6%），
这个比例值得单独看。

## 3. CF-BOCPD：BOCPDMS 匹配对照 + 四臂评测

### 3.1 新增了什么

`OnlineBOCPDMSBaseline`（`shift_baselines.py`）——Knoblauch & Damoulas (ICML 2018)
的忠实**适配**，不是代码移植。保留的：

- 对 `(r_t, m_t)` 的**单一联合递推**，绝不是「先检测再分类」；
- 每个模型用自己的通道打分（model-specific predictive likelihood）；
- 模型身份在 growth 中保持，只在变化点重新抽取，由显式 `model_switch_weight` 控制；
- 模型后验作为模型选择答案读出。

不保留、因此不声称的：作者的时空自回归模型宇宙、剪枝方案、超参优化。
模型宇宙就是四个原因通道，所以它看到的信息**与 CF-BOCPD 完全相同**。

新增 `SHIFT_FOUR_ARMS`（冻结的 `SHIFT_THREE_ARMS` 原样保留，旧 ATG 产物继续验证），
新增 `project_one_shift_four_arm.py` 与 `run_project_one_shift_four_arm.py`。

### 3.2 两个必须记下来的基线公平性教训

1. **第一版 BOCPDMS 检出率恒为 0。** 它的检测统计量是真正的 `p(r_t=0)` 后验质量，
   量级被 hazard 压住（实测 max 0.04）；而 ordinary BOCPD 之所以能到 0.5，
   是因为它的 growth 用了跨通道的 **min** continuation likelihood。
   把 BOCPDMS 挤到别人的绝对阈值网格上 = 让它永远不开火 = **削弱的基线不构成证据**。
   改为**阈值 = hazard 的比例**后，网格里每个点在每个 hazard 下都可达。
2. **选择器会选一个「不检测但答得对」的配置。** 选择键以 F1 为首，而 F1 不依赖检测，
   于是它选了一个检出率 0 的点——然后评测器把「零检测」报成
   `mean_absolute_change_time_error_hours = 0.0`，读起来像满分。
   已加 `timing_metric_is_vacuous` 标记；这是**共享评测器本身的一个报告陷阱**，
   其它臂将来也可能踩到。

### 3.3 结果

冻结九种子（18 个 test case）与 8 种子/split（48 个 test case）两档，
同套件、同证据帧、同 18 次调参预算、同选择键，**重采样单元为 scenario seed**。

**8 种子 / split（48 test cases）：**

| 臂 | cause F1 ↑ | exact set ↑ | **false owner-habit ↓** | Brier ↓ | NLL ↓ | ECE ↓ | 检出率 |
|---|---:|---:|---:|---:|---:|---:|---:|
| ordinary-bocpd | 0.6812 | 0.3958 | 0.8438 | 0.1447 | 0.6370 | 0.1651 | 0.6250 |
| cause-factorized（独立） | 0.4167 | 0.3333 | 0.3750 | 0.1842 | 0.7880 | 0.1894 | 0.6667 |
| **joint CF-BOCPD（候选）** | 0.6515 | 0.3958 | 0.7188 | 0.1640 | 1.3079 | 0.1642 | 1.0000 |
| **bocpdms-model-selection** | **0.6429** | **0.4583** | **0.3750** | 0.1593 | **0.6233** | **0.1572** | — |

配对区间（候选 − 对照，正=候选更好）：

```text
vs ordinary-bocpd        F1 −0.0333  CI [−0.1196, +0.0228]   未胜出
vs cause-factorized      F1 +0.2365  CI [+0.1405, +0.3076]   胜出
vs bocpdms               F1 −0.0295  CI [−0.0793, +0.0168]   未胜出
guardrail（主人习惯误报，正=候选更好）:

vs bocpdms              −0.4062  CI [−0.5938, −0.2188]      候选显著更差
```

### 3.4 判决

```text
ledger transition: implementation complete (unchanged)
```

**CF-BOCPD 没有通过直接对照。** 具体地：

1. joint 臂唯一稳定的胜利是打赢**它自己的独立版本**（+0.2365）。
   对任何外部对照都是 null。
2. 它在 **false owner-habit change rate** 上被独立版本和 BOCPDMS **显著击败**——
   而这正是 RQ8「避免把访客行为固化成主人习惯」最贴近的指标。
3. 它的 NLL（1.3079）是四臂里最差的，接近 BOCPDMS 的两倍：检出率 1.0 是靠
   在每个流上都宣称变化换来的。

这直接推翻了一个原本要写进论文的说法：
「联合推断 run length 与变化原因」本身不是贡献——BOCPDMS 早就联合了 run length 与
模型身份，把模型宇宙换成原因通道就得到同等的原因归因，而且更少误报主人习惯。
可辩护的空间只剩下 **cause-specific reset operator**（原因特异重置矩阵），
而它目前还没有单独的对照实验。

## 8. 你需要手动执行的两条命令

1. **删掉一个 stale 的 git 锁**。我这边的挂载沙箱不允许 unlink，`git status` 留下了一个
   0 字节的 `.git/index.lock`；不删掉，你下一次 `git add` / `git commit` 会失败：

   ```bash
   rm -f .git/index.lock
   ```

2. **本机跑一次测试对齐真实基线**（云端容器里没有 `.git`，provenance 类测试会假失败）：

   ```bash
   PYTHONPATH=src .venv/bin/python -m pytest \
     tests/test_project_two_action_readout.py \
     tests/test_project_one_shift_four_arm.py \
     tests/test_innovation_contribution_gate.py -q
   ```

另：本轮产生的三个临时 tarball 已移入 `_to_delete/`（沙箱不能删文件），可以直接删掉该目录。
