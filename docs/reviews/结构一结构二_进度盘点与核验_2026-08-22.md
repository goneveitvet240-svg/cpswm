## 3. 距离"接入真实数据"和"接入 LLM"还有多远

### 3.1 接入 LLM —— 更近

架构上 LLM 的位置已经被**死死限定**（技术框架 §8.2）：

```text
自然语言 → 结构化 WorldModelQuery
LLM/VLM 不得直接写入 M13–M19
```

代码里已有占位：`contracts/grounded_search.py` 写明 "An LLM may compile a query or propose candidates, but it cannot create..."；结构三 pipeline 已用 `compiler_model_version="structured-llm-symbolic@0.1"`。

**真正的前置件（按依赖顺序）**：

1. M13/M14 落一个真实存储（时序图 + 情景时间线），从 `contract_only` 升到纵切；
2. M16 信念投影引擎（把存储投影成可查信念）；
3. **M20 查询引擎**：当前状态/历史有效时间/人物条件/Top-k/`retrieval_budget`/`retrieval_coverage`/`projection_lag`/unknown/ambiguous；
4. **M21**：NL → `WorldModelQuery` 编译器（这一步才是 LLM 本身，且只做编译）；
5. M22 证据化解释 + 用户纠正入口（route 5 的证据 DAG、claim-to-node binding、baseline closure gate **已实现但未激活**）。

**估计**：这条路是纯符号工程，不依赖任何感知。以你现在的推进节奏（近一周每天多个闭环 + 死亡测试），最小可跑纵切（"找我昨天喝水的杯子" → 时间/人物/活动约束 → Top-k + 后验 + 证据路径）大致是 **2–4 周量级**；其中 LLM 本身（M21）只占很小一部分，绝大部分工作量在 M13/M14/M16/M20。

### 3.2 接入真实数据 —— 有两条路，差一个数量级

**路线 A：现成数据集适配（快）**
你的检索总结 §6 已经把可用资源列全了：HOMER（5 家庭 50/60 天）、WorldLines/ObsMem、DynaBench、PersonEQA/HUMEMBR、EGG/GESTO query set、MEMENTO、POCD 真实半静态场景、STARBench。
前置件只有两个：
1. M05 的 **dataset adapter**（账本里 M05 的 blocker 原文就是 "real robot, rosbag, and **dataset adapters** not implemented"）；
2. M09/M10 的最小离线感知投影（把数据集自带的检测/标注投影成 `ObservationEnvelope`，不需要自己跑检测器）。
外加 M31 开一条真实数据 benchmark 轨道。
**估计：2–4 周量级**可以有第一条真实/半真实回放轨。注意每个数据集都只覆盖你四重困难中的一两项（矩阵里没有一个是全 ●），所以第一轮只能做单项外部有效性，不能做全系统。

**路线 B：自建真实感知栈（慢）**
`FORMAL_B1_REAL_VALIDATION` 要求 M05–M12 全部 `real_data_validated`，而 M07（VIO/SLAM）、M08（语义三维地图）、M09、M10（开放词汇感知）、M11（实例关联）、M12（人物与交互事件）**六个模块全部 `absent`**，且中间还夹着一道 `B1_SYNTHETIC_READINESS`（先全部升到 synthetic）。
**估计：数月量级**，且需要真实机器人/传感器与隐私采集方案（技术框架 §14 ADR 里 Habitat/iGibson/Isaac Sim、真实平台都还没定）。

**建议**：申 RA / 投稿的时间尺度上，路线 A 是唯一现实选项；路线 B 应该在论文里写成 limitation 和 future work，而不是当作必须先做完的前置。

## 4. 哪些已经被其他项目覆盖（不能算你的创新）

你自己的文档里已经把这件事记得很诚实，下面是汇总（含证据等级）。

### 4.1 功能层面已被覆盖

| 功能 | 覆盖它的工作 | 结论 |
|---|---|---|
| 机会式观察 + 可见性负证据 + Dirichlet 位置信念 + 成本感知搜索 | **O-STaR** | 不能作为 OPCEU 创新 |
| 观测间隙枚举所有兼容事件序列并更新信念 | **Bernert & Ramparany 2021**（full text checked） | 不能作为 CHEH 的 candidate recall 创新 |
| 多事件全局一致解释 + 事件似然 + 角色/共享约束 + MAP 搜索（Greedy/MHT/RJMCMC-SA/IP） | **Damen & Hogg 2012 AMG**（full text checked） | 不能作为"加机制分数/角色对"创新 |
| 事件溯因式 belief update | **Boutilier 1996**（full text checked） | 不能作为"用事件解释观察"创新 |
| 联合 run-length × model identity 在线变点 | **BOCPDMS, Knoblauch & Damoulas 2018**（full text checked） | 不能把 \(m_t\) 改名 \(C_t\) 就宣称创新 |
| 人—物事件层次 / 时序场景图 / 4D 场景图 | GESTO、EGG、HERMES、DAAAM | 事件表示本身不是创新 |
| 在线动态开放词汇三维记忆 | DynaMem、DovSG | 地图更新本身不是创新 |
| 家庭上下文漂移下的持续物体迁移学习 | STREAK | 持续学习本身不是创新 |
| 记忆—行动统一循环 / 时空检索 | STAR、ReMEmbR、Mind Palace | 闭环本身不是创新 |
| 异构 GNN / Transformer 消息传递 | 通用 | 不能作为 PCHMP 创新 |
| replay / EWC / Fisher 防遗忘 + 分层软计数 | 通用 | 不能作为 RGRC 创新 |
| sticky HMM / HDP-HMM / 历史模型库阶段复用 | recurrent concept drift 文献 | 不能作为 CCRR 创新 |
| active perception / VOI / active BOCPD | 通用 | 不能作为 CIAV 创新 |
| 给定习惯的导航、个性化整理偏好 | UcON、TidyBot、Housekeep、TIDEE、AEG | 习惯**利用**已被覆盖 |

### 4.2 已经被实测打平或打败的

| 对照 | 结果 |
|---|---|
| ORRER v0.1 **vs** matched open-world AMG（同样拿到 actor/mechanism/ordered-role 三类证据） | **1.000 vs 1.000** —— 表示缺口修好了，优势没有 |
| CHEH v0.3 **vs** 封闭 AMG | 0.500 vs 0.542 —— CHEH 更差 |
| joint CF-BOCPD **vs** ordinary BOCPD（v5 行动级） | joint balanced regret **更高**（+0.053 / +0.063，CI 全正） |
| 全部 detector **vs** `never-act` | 没有一个在两轨都胜出；retuned legacy 与 never-act 完全相同 |

**这是你目前最大的科学风险**：功能缺口已经补齐，但"补齐"不等于"更好"，而所有强基线都还没被击败。

## 5. 你采取的创新方法

### 5.1 方法论层面（目前最扎实、最难被质疑的部分）

1. **"已有覆盖提醒 — 创新状态"双卡片强制协议**：每发现一个近邻必须写系统/证据等级/它已实现的功能/它的具体方法/重合的输入输出场景/它未解决的假设，然后才写自己的创新状态。杜绝了"别人做过了就绕开"和"把已有实现包装成创新"两种失败。
2. **创新台账状态机**：九级状态，当前无一项超过 `implementation complete`，在此之前统一用"候选创新/工作方法/拟提出"，禁止"首次"。
3. **预注册死亡测试**：v1→v5 五轮预注册 + 冻结 + 结果分离，测试集封存/解封 receipt（ATG-3），解封后禁止重调参与二次解封。

7. **action baseline guardrail（`never-act` / `always-reset-verify`）**：这一条直接把 v4 已经得出的"legacy 优势"判为不成立。这是很少有论文会给自己设的护栏。

### 5.2 算法层面（候选创新，尚未成立）

1. **ORRER**：`unknown_actor` 从"只能承担 direct 最终责任的特殊标签"升级为可进入 initiator/carrier/recipient/placer 四类角色的**匿名实体节点**，支持 `resolve/merge/split`；三因子似然比更新（actor × mechanism × ordered-role），每因子声明 reference prior / endpoint role / evidence cluster / provenance 防"后验乘后验"和相关帧重复计数；**影子后验 `revival_probability`** 保存不可变剪枝前分数，只有 LR>1 且提升影子后验且超过阈值三条同时满足才产生 `REACTIVATE` 修订（中性证据不能复活）。
2. **joint CF-BOCPD**：联合 \(p(r_t, C_t)\) beam + 分块充分统计量 + **原因特异重置矩阵** + 瞬时噪声态。区别于"BOCPD 后接分类器"的关键是原因变量直接改变转移核、危险率和哪些参数块允许被重置。
3. **RGRC 方案 B**：来源簇绑定的原子增量束 \(\Delta S_c=(\Delta A_c,\Delta b_c,\Delta\alpha_c,\Delta\Lambda_c,\Delta\xi_c)\)，整簇隔离/原子晋升/撤销；**leave-one-cluster-out 投影**（B-DC3）使残差监督从排除自身簇的投影计算，结构性地禁止自证与双计数；Dirichlet + RLS 混合、数值失败降级为受影响阶段日志重放；合法状态转换只有四条，`REACTIVATED` 是新修订进入而非旧记录复活。
4. **CIAV 方案 B**：不可变 belief snapshot 保证执行器永不看到半完成统计量；**地图信念图与任务动作图分离 + 显式依赖桥**；动作级版本切换只重规划受影响后缀；**学习型 VOI 代理只负责排序，精确风险验证器拥有最终否决权**。
5. **PCHMP**：来源类型防火墙（每类证据只能沿允许的边发消息）+ 互斥假设归一化 + 人物置换等变 + 强制返回证据子图，禁止推断结果循环充当独立事实。
6. **五条跨领域一级技术路线（08-23 冻结）** —— 这是最有辨识度的差异化角度：把 incremental view maintenance / 双时态数据库 / MVCC、information-flow control 与 taint tracking、machine unlearning 与多模型估计、object-centric process mining 与 truth maintenance、self-adjusting computation 与因果一致性，正式引入具身世界模型。上表 4.1 里那些"已被覆盖"的机器人文献，**没有一篇是从这五个领域切进来的**。
