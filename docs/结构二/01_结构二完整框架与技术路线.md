# 结构二完整框架与技术路线

## 1. 研究对象与不可缩减边界

结构二联合处理 selective observation（选择性观察）、hidden events（隐藏事件）、multiple
residents（多人共享）、open-world unknowns（开放世界未知）和 non-stationary habits（非平稳习惯）。
隐藏事件推断、多人责任、未知人物、可逆归因、主动验证和具身反馈必须存在于同一个统一系统中。

系统输入不是一串干净标签，而是任务、路线、视角、遮挡、检测结果、人物线索、时间、用户纠正和
执行反馈。输出也不是单一位置，而是带来源的联合信念、候选事件链、人物/阶段后验、长期记忆状态、
验证动作和最终具身行动。

## 2. 七层记忆不能混在一起

| 层 | 回答什么 | 主要规则 |
|---|---|---|
| observation evidence | 传感器在什么条件下看到了什么 | 追加保存，不直接等于事实 |
| current belief | 物体当前可能在哪里 | 快速变化，允许多假设 |
| episodic event | 某时某地可能发生了什么 | 带时间、来源和置信度 |
| inferred event | 未观察间隙的候选事件链 | 保存候选集，不只留 top-1 |
| personalized habit | 某人物在某情境下通常怎样 | 经过人物、原因和责任门控 |
| habit regime | 当前属于哪个习惯阶段 | 版本化，允许历史阶段复活 |
| preference/norm | 用户明确偏好和家庭规则 | 与观察到的行为严格分开 |

如果这些层混在一起，一次错误检测就可能沿“事件→人物→习惯→行动”整条链扩散。

## 3. 统一概率状态

每个离散粒子维护：

```text
H：完整隐藏事件链
R：pickup/carrier/handoff/placer 等有序人物角色
I：物体实例或 unknown_instance
C：observation/actor/identity/habit/noise/unresolved 变化原因
Z：stay/create/reactivate/unresolved 阶段目的地
r：阶段持续长度
V：修订谱系
```

位置 Dirichlet、RLS（递归最小二乘）自然统计量和 information-form belief（信息形式信念）作为
Rao-Blackwellized analytic blocks（解析块）按粒子条件维护，不需要全部采样。系统额外保留正式的
`unresolved mass（未决概率质量）`，证据不足时可以诚实地不作决定。

## 4. 三层权限与数据流

| 层 | 权限 | 禁止事项 |
|---|---|---|
| Neural proposer | 提出、扩展和打分候选 | 直接写人物习惯或把 top-1 当真值 |
| Typed particle reviser | 归一化、施加约束、重采样和局部修订 | 绕过账本提交长期统计量 |
| Reversible RGRC ledger | 隔离、晋升、撤销、纠正和重放 | 接受没有来源/权限的派生更新 |

每个提交单位是完整的 `evidence_cluster_statistic_bundle（证据簇统计增量束）`。一个证据簇造成的
位置、RLS 和信息统计更新必须原子地一起提交或一起撤销，不能只撤一半。

## 5. 在线正常路径

1. 记录任务、路线、视野和检测条件。
2. OPCEU 判断观察机会和负证据强度。
3. ORRER/CHEH 从前后状态生成开放人物、多机制、多角色事件链。
4. 神经提议器产生 Top-K 候选，同时保留规则候选、unknown 和 unresolved。
5. 类型化粒子核加入观测似然、转移先验、物理约束、角色约束、身份约束和来源约束。
6. CF-BOCPD 更新变化原因与游程长度；CCRR 提出保持、新建、恢复或未决阶段。
7. RGRC 把高风险证据放入 quarantine（隔离），只有满足责任、来源、独立性和授权后才 promote。
8. CIAV 根据任务价值、原因信息、运动成本、隐私和打扰选择验证行动。
9. 规划器从冻结的 belief snapshot（信念快照）读取搜索、放回、交接或协助策略。
10. 执行成功、失败、not-found 或用户纠正重新进入证据链。

这是目标动作合同，不代表历史 Route C v0.2 已满足。v0.2 使用同一个无类型地点 UUID 分布同时承担
SEARCH（搜索）与 PUT_BACK（放回）的决策、执行和计分；新构念门才把二者的 action type（动作类型）、
副作用和指标分开，而且仍没有选择 combined utility（组合效用）或长期产品动作语义。

## 6. 迟到反证路径

当前 Task 7 的下一版路线联合：

- correction-ready ancestry reservoir（面向纠正的谱系储备）；
- backward-message checkpoint（后向消息检查点）。

当迟到证据否定过去的人物或事件时，系统定位受影响谱系，恢复窗口外检查点，在局部窗口内重新
计算，再重建解析块和后续行动。如果支持已经丢失、误差超门或成本失控，就显式 fallback 到 full
rerun（完整重跑）。必须与 reservoir-only、backward-message-only、combined、full-rerun 和旧失败
实现五臂比较。

## 7. Task 8 的在线计算路线

Task 8 保留三个轴：

- 主轴：online compute（在线计算）；
- 辅助轴：distribution shift（分布漂移）；
- 辅助轴：information restriction（信息限制）。

正式问题不是“联合模型能不能拟合交叉项”，而是：在相同数据、参数、状态访问、训练计算、推断
计算和延迟预算下，learned joint 是否改善 action-quality--compute frontier（行动质量—计算前沿），
并优于 learned matched two-stage。信息受限对照不能替代信息完整的最强匹配对照。

2026-09-07 项目所有者已选择 Route C：`stateful_joint_inference`。v0.1 先把完整
`H/R/I/C/Z/r/V` 状态、三个 Rao-Blackwellized blocks、七算子输出和反馈放进同一递推回放环。
2026-09-08 的 v0.2 在 evaluator-local runtime（评估器局部运行时）中加入环境 transition API、
动作后观测、train/validation 学得交互、RGRC 正反例和“接口保留、独有作用中和”的开发诊断。

2026-09-09 的重新审计确认，v0.2 的 27 个注册 Route C runs 均由
`LearnedInteractionRuntime` 构造和执行；公开的 `StructureTwoProductionSystem@0.2` 在这些 runs
全部结束后才被构造，只形成 post-run static sidecar manifest（运行后静态旁挂清单）。源码路径、
SHA-256、静态前向边和 `CIAV → OPCEU` 边只能证明该历史静态清单的内部一致性；A 接口落地后，
它与当前 checkout（检出版本）的源码绑定已过期，更不能证明轨迹由该生产
对象或其中算子实例生成。1,998 条旧 operator receipts（算子回执）均缺少所需的 runtime execution、
operator instance、callable invocation 和 output-consumption dependency 绑定；因此
`structure-two-runtime-identity-gate@0.1` 为 false，production equivalence（生产等价）未成立，
`architecture_selection_status=A_SELECTED_STRUCTURE_TWO_PRODUCTION_SYSTEM`；旧 Route-C 的 runtime
identity、production equivalence 与 independent custody 仍为 false。

历史机制识别对照共享状态和计算日程，但注册差异仅为 learned cross-axis log-potential（学习式跨轴
对数势）与零系数，所以只检验该特定交互势，不是一般的 joint/factorized architecture 比较。27 个
配对步骤均出现微小 action posterior 差异，却有 0 步改变最终选择；两主臂合计 54/54 次选择当前位置，
44 次 `action_success=true` 仍对应 0 次实际位置改变。旧每臂 `0.555556/step` 的 put-back error 和
`0.333333` 的 contamination 只是由同一个无类型地点读出得到，后者只能解释为
non-owner/current-location/owner-habit-mismatch proxy，不能解释为长期人物记忆污染。

新的 `structure-two-action-utility-construct-gate@0.1-development` 已在 3-step D0 诊断上通过：
SEARCH 与 PUT_BACK 类型化并绑定同一决策前信息集，搜索不改变物体状态，放回产生 1 次成功 nonnoop
实际状态改变；两个 single-head sensitivity controls（单头敏感性对照）只改变各自指标。这个结果只
建立构念与指标 wiring（接线）的局部正路径。Architecture A 已在真实生产对象的 legacy ordinary
transition 上绑定不可变 plan、六个实际调用回执和 CIAV N/A；P0–P5 已有传递只读计划/依赖注册表、
P0 债务
路径、异位置 detected full CIAV 闭环、同位置 fast verification 及已执行算子耗时，但
negative-observation full closure、全 wrapper debt barrier、origin-policy/trace-bound replay、
state-derived feature extraction（状态派生特征提取）、
P1/P2/P4 独立内核、真实 fallback 与完整资源核算尚缺。因此历史 Route-C 及 P0–P5 后果性轨迹的完整
production runtime identity（生产运行时身份）均仍未通过。combined utility、长期产品动作语义、
长期污染、Task 8 正式通过和科学优越性也仍未建立。

## 8. 具身效用和硬护栏

主效用采用 PCT（惩罚后任务完成时间）；污染、恢复、安全和隐私是独立硬护栏。每个任务族的
`T_max` 由 D2 pilot 的匹配基线成功时长按冻结公式产生。优效要求点估计
同时达到至少 10% 相对改善和至少一次标准验证行动 `tau_verify` 的绝对改善，配对一侧 95% 区间
下界还必须大于 0。完整阈值见：

[最终效用、护栏与外部验证协议](../../configs/project_two_experiments/structure_two_final_utility_guardrail_external_validation_protocol_v0_1.json)

## 9. 数据和外部有效性阶梯

| 层级 | 用途 | 当前状态 |
|---|---|---|
| D0 合成事件流 | 快速证伪机制、合同和评价器 | 已大量运行，只是开发证据 |
| D1 ProcTHOR + AI2-THOR | 多房屋、长日程、多人事件、计算规模 | 已选择，尚未接入 |
| D2 受控 RGB-D | 感知噪声、遮挡、人物和真实动作时间 | 协议已选，尚未采集 |
| D3 半真实/遥操作 | 感知与真实执行耦合 | 保留，尚未排期 |
| D4 长期真实机器人 | 完整具身外部有效性 | 最终目标，尚未开始 |

ProcTHOR 本身需要增加结构二自己的 actor/event scheduler（人物/事件调度器）；不能把程序生成房屋
直接说成已经具备长期多人行为。

D1 计划规模为开发 100 houses × 10 schedules、验证 200 × 5、密封确认 1000 × 5。吞吐 pilot
只允许据此增加规模或安排并行资源，不能因为方法结果不理想而缩小确认规模。
