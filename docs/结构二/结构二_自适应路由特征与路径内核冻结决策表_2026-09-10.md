# 结构二自适应路由特征与路径内核冻结决策表

日期：2026-09-10
状态：`PARTIALLY_FROZEN_P5_FIRST_AND_CALIBRATION_STRATEGY_SELECTED`
证据边界：D0 engineering design input（D0 工程设计输入），不是实验结果

## 项目所有者已冻结的推进顺序

2026-09-10，项目所有者选择：

1. `P5_FIRST`：先用 P5 full-eager（完整急切路径）验证完整七算子路径的行动收益上界，再决定是否
   继续投入完整 P0--P5 router；该顺序不删除任何路径或算子；
2. 第一项死亡测试先使用 typed SEARCH/PUT_BACK（类型化搜索/放回），完整 HANDOFF、DELIVERY、
   REMIND、ASSIST 动作族继续保留在统一框架和后续正式评价中；
3. 新实现开始前先建立当前结构二 checkpoint；
4. adaptive router 采用 validation-only calibration（仅验证集校准），同时保留 fixed analytic
   thresholds（固定解析阈值）作为独立基线；确认集不得用于选择特征、阈值或路径策略。

当前源码中的 `0.45/0.35/0.30/0.20/0.25` 只登记为 fixed-threshold baseline candidate
（固定阈值基线候选），不是最终 adaptive policy。最终特征公式、校准网格、选择规则和冻结阈值仍需在
P5 死亡测试出现可重复行动信号后单独冻结。

## 为什么 adaptive 细节仍需后续冻结

当前已存在 immutable P0–P5 plan registry（不可变 P0–P5 计划注册表）、部分真实路径、P0 inference
debt（推理债务）、P3/P5 different-location detected full CIAV closure（异位置检测的完整主动验证闭环）、
same-location fast verification（同位置快速验证）和逐算子耗时回执；但 negative observation
（未检测到观测）尚无完整下游闭包，普通生产入口也没有从当前
状态计算 `AdaptiveRouterFeatures` 的 runtime-owned extractor（运行时自有提取器）。同一状态下，调用方
可以提交不同的歧义/冲突/风险分数，从而选择不同路径。与此同时，P1/P2/P4 尚未对应三套不同的实质
计算内核，登记的 failure/timeout fallback（失败/超时回退）也没有执行化。

因此当前只能证明“给定调用方特征后，部分控制流可以运行”，不能证明“系统根据真实生产状态选择了
正确路径”。项目所有者已经选择 validation-only calibration 加固定阈值基线，但以下特征公式和路径
语义仍具有科学含义；若 P5 死亡测试通过，它们仍需再次由项目所有者冻结，不能由实现者用方便的默认
值代替。

## 一、路由特征需要逐项冻结

| 特征 | 必须冻结的含义与信息时点 | 可选实现族 | 主要风险 |
|---|---|---|---|
| `observation_opportunity_coverage` | 当前决策前可见机会覆盖率；窗口、分母和缺失处理 | 单 opportunity 概率；最近 K 次校准覆盖；分层后验均值 | 用未来观测或评价器真值泄漏 |
| `evidence_conflict_score` | 决策前证据间冲突，不含完整路径推断输出 | 最大 pairwise divergence；来源加权 Jensen–Shannon；leave-one-source-out 变化 | 与 PCHMP 完整推断重复计费 |
| `provenance_dependence_score` | 证据来源非独立程度 | cluster concentration；共享祖先比例；有效样本量折损 | 来源 ID 多不等于独立 |
| `actor_ambiguity` | 人物责任不确定性 | 归一化熵；top-2 margin；credible-set size | 不同人数下不可比 |
| `instance_ambiguity` | 物体实例身份不确定性 | 归一化熵；top-2 margin；关联图未决质量 | 把 known out-of-support 与 unknown 混合 |
| `unknown_mass` | 开放世界未知人物/事件/实例的质量 | 显式 unknown posterior；分类型 unknown 后取上界 | 用 residual 当 unknown 会失准 |
| `action_margin` | 决策前 top-1 与 top-2 可行动作效用差 | 绝对差；按效用范围归一化差；风险调整差 | SEARCH/PUT_BACK 量纲混合 |
| `pending_long_term_commit` | 当前是否存在将要跨越长期写入边界的候选 | 由 RGRC transaction state 直接读取 | 调用方布尔值不可接受 |
| `regime_hazard` | 决策前阶段变化风险 | CF-BOCPD predictive hazard；cause-factorized 上界；校准后的变点概率 | 不能使用本路径完整 posterior |
| `outstanding_debt_count` | 生产债务账本中的未偿数量 | 直接读取 ledger | 已实现账本绑定，仍需纳入 extractor receipt |
| `oldest_debt_age` | 最老未偿债务的在线步龄 | 当前 step 减 `created_step` | step source 必须单调且同一时钟域 |
| `maximum_debt_flip_bound` | 延迟推断可能改变动作/归因的保守上界 | 解析界；验证集校准界；conformal upper bound（保形上界） | 不能随意填 `0/1` 作为普通路径特征 |
| `state_staleness` | 特征读取的状态版本距当前提交点的差 | revision delta；单调 step delta；时间上界 | 与 wall-clock 混用会不可复现 |
| safety/privacy flags | 当前生产授权策略，不是模型预测 | 直接读取 runtime-owned policy | 已绑定本地策略，但尚非独立保管凭证 |

每项还需共同冻结：数值范围、缺失值的 fail-closed 行为、校准 split、版本号、输入 source SHA、计算成本
和禁止读取列表。冻结前不应新增一个“看起来合理”的公式并把 eligibility gate 改成 true。

## 二、P1/P2/P4 需要冻结为真正不同的计算内核

| 路径 | 当前已有 | 尚需项目所有者冻结的实质差异 |
|---|---|---|
| P1 event/actor local | 完整 core pass + CIAV debt，mode labels | ORRER/CHEH 局部展开半径、PCHMP 受影响子图、RGRC 局部修订边界，以及明确不运行的 regime 工作 |
| P2 regime/recovery local | 完整 core pass + CIAV debt，mode labels | CF-BOCPD/CCRR 候选阶段集合、历史阶段检索范围、RGRC 恢复对象，以及明确不运行的 event/actor 精化 |
| P4 combined | 与 P1/P2 基本同一 core pass + CIAV debt | 两类局部计算怎样组合、共享哪些中间量、何时升级 P5，以及为何成本应不同于 P1/P2/P5 |

冻结后的每条路径必须通过 positive consequential test（正向后果测试）：在同一 branch point（分支点）
上，不只 trace mode 不同，还必须观察到预期的 invocation set、输入支持、成本和允许状态变更不同；错误
内核即使能重算自洽哈希也必须被 verifier 拒绝。

## 三、失败回退和资源核算需要冻结

必须明确区分：

1. pre-path invalid input（路径前无效输入）与 safety/privacy denial（安全/隐私拒绝）直接
   `SAFE_ABSTAIN`，不得先运行 P5；
2. P0–P4 的 operator timeout/failure 何时 rollback 并从同一检查点升级 P5；
3. P5 再失败时如何签发包含原错误、已花成本、动作处置和状态哈希的 safe-abstain receipt；
4. feature extraction、router selection、每次 fallback、replay、CIAV sensing、peak memory、storage、
   energy 与 latency 怎样进入同一资源账本；caller-provided `feature_extraction_cost_units` 不得作为实测值。
5. pending debt 期间 policy/evidence-trace rebinding（策略/证据轨迹重绑定）是必须冻结，还是允许但要求
   同时记录 origin/current identity（起点/当前身份）；当前屏障只证明 core transition 不会旁路演化。

## 四、关闭四个工程门的最低证据

- `path_eligibility_policy_bound_to_production_state=true`：每项特征由生产 extractor 从允许的 pre-path
  状态重算，调用方不能替换数值；特征、来源、版本和耗时进入 trace。
- `legal_path_executor_bound_to_production_runtime=true`：P1/P2/P4 具有各自内核，六路径 invocation/cost
  反例通过，timeout/failure fallback 与 safe-abstain receipt 完成。
- `p0_p5_consequential_runtime_identity_established=true`：state → feature → selection → kernel calls →
  action → next state 全链可鲜重算，不能只验证调用方自洽哈希。
- `resource_accountant_bound_to_production_execution=true`：至少完整覆盖冻结协议列出的所有资源轴和每次
  回退/重放；窄的 operator wall-clock receipt 只能保持为单独 diagnostic（诊断项）。

在这四项关闭前，readiness 必须维持 `shadow_execution_authorized=false`。这不删除 P0–P5 或七算子中
任何能力；它只是阻止不完整实现被包装成已经可信运行的自适应方法。
