## 已推进的下一步：从训练检查点到可恢复推理

新增 `ProposalInferenceSession`，直接加载已有三候选训练检查点，消费不含监督的 `ProposalContext` 和外部提供的完整候选支持集。评分不推进随机数；采样具有明确种子、请求 ID 和事务式随机数状态。返回完整目标、九因子概率及被替换修订/重放要求，不将完整目标自动缩成缺少修订效果的原生回执。

- 同一个请求与相同输入可重复读出；更换可见历史、候选支持、模型参数或执行线程绑定时拒绝相应复用。候选顺序变化保持相同语义。
- 随机数已经消耗后发生异常或 KeyboardInterrupt，恢复到原采样位置；成功后才登记请求。
- 快照固定检查点、参数、源码字节、PyTorch 版本和 CPU 线程数；恢复逐条重跑历史推理，比对目标、完整概率、请求顺序和最终随机数位置。重封摘要后置换成另一个合法目标及其合法概率也被发现。
- 完整快照/权重预期摘要仍须由调用方保管；能够伪造整段合法历史并同时控制外部摘要者不受此机制认证。此接口验证可重放性，不能代替采集来源签名或独立人工审查。
- 全量参数摘要和逐条恢复会增加成本，长历史/跨设备性能与数值可迁移性未验证；执行绑定不同即拒绝，不静默降级。返回对象始终没有账本写入和原生发布授权。

`run_checkpoint_proposal_inference.py` 使用第二轮实际训练出的三份权重，每臂评分六操作，保存 3 次请求后恢复，逐项比较后续 5 次采样，并检验重复请求不推进状态。这一工具没有新增优化器更新，输入明确为组件夹具；不是自然数据验证或默认联合粒子工厂已完成。

最终 **405 passed / 10 个既有 warnings，mypy 358 个源文件，Ruff 通过**；最终 4 命令均成功、运行前后源码相同，并逐文件对照该 SHA 的 Git 对象一致。三臂均完成六操作概率评分、3 个历史请求恢复及 5 个后续请求精确比对。结果由 `evidence/final-manifest.json`、`evidence/inference-summary.json` 和日志记录。
