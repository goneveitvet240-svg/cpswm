# CPSWM 六项信任边界修复与两轮对抗审核

日期：2026-08-28

## 结论

本轮修复的是证据和评测的信任边界，不改变结构一、结构二、结构三或
OAM-PHM 的研究路线。六个已知漏洞均已建立 fail-closed（封闭失败）入口；
旧兼容入口仍可用于开发重放，但不得生成正式论文证据。

这不代表外部基线复现、真实数据实验或论文创新已经成立。它只代表提交者
不能再仅靠自填字段、共享密钥、调用参数或同进程对象，把结果升级成正式证据。

## 六项修复

1. 正式证据签名从对称 HMAC 改为 Ed25519 非对称签名。提交者侧和评测侧只
   持有公钥验证器；旧 HMAC 明确标记为非正式等级，正式门会拒绝它。
2. OAM-PHM 的复现完成、预算合规、bootstrap 报告和判定标准必须分别绑定
   外部签名回执。`accepted=True` 等自填字段只表示声明，不能使复现完成。
   外部复现回执还绑定原始数据签名、帧来源清单、独立调参选择、独立进程
   回执和实际输出哈希。
3. 结构三缓存签发前会重新读取原始数据文件并校验完整文件和分块哈希，再由
   冻结的帧物化函数从该文件重算 raw-frame（原始帧）与 decoded-input
   （模型实际输入）哈希。缓存预测必须绑定后者，不能只复用 metadata 哈希。
4. 四层放置权限不再在每次决策调用中接受 `trusted_issuer_ids`。可信集合来自
   服务构造时绑定的家庭 trust-store snapshot（信任库快照），快照由独立
   Ed25519 根签发并绑定家庭、版本和前序快照。
5. 正式 sealed TEST 由独立 custodian process（保管进程）持有，主评测入口
   只接受外部保管器和一次性签名解封授权。旧 `SealedTestSplit` 被明确降为
   `formal_isolation=False` 的开发兼容类，ATG-3 正式入口会拒绝它。另有独立
   测试进程回执绑定命令、环境、父子 PID、超时、stdout/stderr 和输出文件。
6. `check.sh` 优先使用仓库 `.venv`，uv fallback 的缓存固定在
   `.checkout/uv-cache`，不再依赖用户级 uv cache；pytest、mypy、ruff 和
   format 的任一非零状态都会成为脚本非零退出。

## 第一轮：已知攻击复现

覆盖公钥反签、HMAC 冒充正式证据、OAM 自填完成、签名替换、原始文件漂移、
解码输入替换、缓存跨帧复用、假家庭根密钥、请求级可信签发者注入、提前读取
TEST、重复解封和伪造独立进程产物。

初次结果：108 passed。全仓攻击又补出帧旧调用、软链接逃逸、残留子进程和
笼统 OAM 完成声明四类组合漏洞；修复后重新执行本轮：113 passed。

## 第二轮：组合与回归攻击

把六条边界同既有 method falsification（方法证伪门）、OAM-PHM 基线协议、
四层权限预注册、结构三缓存、结构一 SHIFT ATG-2/ATG-3 和可复现性攻击放在同一
测试轮中，检查跨模块替换和兼容入口旁路。

初次结果：148 passed；吸收全仓新增攻击后重新执行：153 passed。

## 全仓回归

并发全仓运行在 45 分 10 秒时达到 2541 passed、1 xfailed、7 failed，随后因
超过冻结的 22 分钟预算两倍而中止。七项失败的归因和处置如下：

- 五项属于新增攻击发现的真实实现/迁移遗漏，已修复；相关安全集合串行复跑
  全部通过。
- 一项 `source_tree_sha256` 失败来自同机另一套 pytest 和工作区改动并发发生；
  稳定工作区串行复跑通过。
- 一项是 P0 checkpoint manifest 过期。当前工作区包含大量跨任务未提交改动，
  本轮没有替整棵树重新盖章，因此此门仍诚实失败。

最终静态核验：Ruff lint 通过；351 个 Python 文件 format check 通过；
`git diff --check` 与 `bash -n check.sh` 通过；十个本轮核心源文件的定向 strict
mypy 通过。没有把现存全仓类型债务写成通过。

## 仍然不能声称的内容

- Ed25519 解决“验证者不应拥有签名能力”，但私钥的线下托管、轮换和吊销仍需
  真实评测组织或 CI secret manager（密钥管理器）部署。
- Python 子进程不是恶意代码的操作系统沙箱。正式投稿实验仍应放入只读镜像、
  无网络、最小文件挂载、不同 UID/容器的外部 evaluator（评测器）；当前进程
  回执用于证明进程边界和产物绑定，不宣称等价于容器隔离。
- 帧物化函数必须由评测方冻结并记录实现/容器哈希；本轮提供的是路线无关接口，
  没有替项目选择 FFmpeg、Habitat 或具体视觉模型。
- trust-store 根公钥必须在服务部署配置中固定。若攻击者能替换 composition root
  （程序装配根）或整个运行镜像，应用层契约无法自行恢复信任。
- O-STaR、STREAK、DynaMem 等外部完整系统仍需忠实复现和独立重调参；签名脚手架
  不能替代这些实验。
- 全仓 strict mypy 的既有类型债务和 checkpoint manifest 是否需要重新盖章，
  与本轮六项安全修复分开报告，不得伪装为已解决。

## 正式证据最低部署条件

只有同时满足以下条件，才允许把本轮接口产生的结果写成正式比较证据：评测方
独占私钥；候选只拿公钥；原始数据只读且签名；帧提取实现冻结；TEST 与候选调参
隔离；候选执行在无网络、最小挂载的外部容器；所有输出由评测方重新哈希签发。
