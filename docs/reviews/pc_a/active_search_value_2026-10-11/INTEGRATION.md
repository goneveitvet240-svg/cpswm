# 接口与接入边界

## 本轮可执行入口

`tools/run_active_location_search.py`构造既有`build_task_separated_full_joint_state`，外包`ActiveLocationSearchState`，由原评价器实际运行observe→predict→feedback。`src/cpswm/system/evaluation_operations/structure_two_active_location_search.py`提供位置请求、环境回执、预算/时序/完整回执校验、搜索记忆及最终反馈动作绑定。默认旧入口与所有应用调用方不变；本轮没有自动迁移或合并共享分支。

人物CIAV和七算子完整推断仍由既有路径执行。新位置请求只在被动位置缺失时选择菜单中的一个位置；环境先记账，再读取D0隐藏当前位置，返回所查位置是否找到目标。没有给策略返回其他位置或真实人物。正结果只进入搜索记忆；查空只排除本步位置。后续feedback和重建保持既有路径。测试核对请求错绑、重复/预算/时序、完整伪造回执和真实修订后的输出，评分再核对各联合后端臂的最终习惯状态/账本相同。

这只是同进程内可审查的API约束，不能阻止恶意Python代码自行读取环境成员。hash用于确定性核对，不能冒充独立签名、可信硬件或外部不可变证明。局部伪造检查不能代表全仓接受矩阵。

## 成本与终端执行

最多2次主动检查实际调用模拟环境并留下逐条回执。每步余下的最终检索顺序由评分器换算为位置检查次数，跳过已查空位置；已找到则不重复计算终端查找。该续搜尚未执行、不更新下一步记忆。因而总检查数是明确的**实际探测＋隐含执行代价**，不是机器人实测动作数或时延。尤其passive没有隐含续搜后的记忆反馈；相对passive的改善不等于完整执行闭环收益。各active臂同预算、同检测接口、同续搜评分，是本轮最直接的策略对照。

原查询后错误率不收费，故独立保留`metric_post_query_uncharged`，不拿它替代总成本。沿用原支持数归一化额外检查代价和放回错误；支持外目标单列失败。本轮公开菜单取现有D0注册位置，尚未实现新位置发现；负反馈不会自动写长期人物/习惯统计。

## 自然环境接入还缺什么

已有Unity观察worker执行Rotate/Pass并提供真实RGB/RGB-D；它没有完成“导航到指定位置并判断目标在否”的检测器契约。替换D0环境必须补齐：从公开位置到可执行移动/观察动作的绑定、目标实例支持与有效深度、可区分未找到和不可见的观测结果、实际动作成本、终端搜索执行与跨步反馈。不能把旋转成功或收到一帧图像直接登记成目标存在/缺失。

联合习惯概率当前仅用于query proposal（查询建议），不是current-location belief（当前位置信念）。若后续加入可逆的当前位置/遮挡/搬运状态或观测似然，需要单独明确模型、开发数据、强简单基线和全预算执行比较；本轮没有据留出结果追加先验、调阈值或改变正式科学门。完整H/R/I/C/Z/r/V、三个RB blocks、七算子、多人物和开放世界研究范围保持。
