# 计算修复的性能范围

查询分块降低临时内存需求，不减少每行读取的键数，因此完整图自注意力计算仍随节点数近似平方增长。显式65,536节点配置不是长期在线复杂度的解决方案；本轮能签收的上限仅是已计划的四段、各四帧、完整783候选案例及列明数值/恢复检查。

当前评分还会逐条件检查完整上下文、候选/缓存和实际参数字节。这些保护有CPU成本，不能为提速移除其语义验证，也不能把候选子集各自归一化。没有做独立性能剖析，不将任何单一函数宣称为已测得的主要瓶颈。

最终报告需保留每个视频的端到端耗时；没有预先规定在线延迟门，本轮通过不等于实时性能达标。若后续优化计算，必须保持全部候选、同一概率定义和原定数值门，再针对合法正路径、完整重封、恢复和动作后果重新双审。模型架构/科学训练日程仍不在本轮自动选择。

一秒只读OS采样（2026-09-26 18:14本地，89次主线程样本）另显示当时在Python的frozenset/JSON编码与模式对象处理，不能把整段延迟全部归因于注意力矩阵；此单点样本也不是整段性能剖析。工具报告当时physical footprint 653.9M、已观察高水位1.9G，不等于本次完整最终RSS峰值。未改变进程、线程或源码。采样摘要及原文SHA见evidence/video-0003-runtime-sample-summary.json。
