本任务从匹配过渡死亡测试最终 head `2d54c541107bd718d02c5427220f5715a0eca93a` 开始，修复 PR99 生产实现 `a5385ddaf6724d2d346fc222866edc2b7ec9407c` 在同一冻结三帧中两次把 Kettle 锚点错误恢复为 CounterTop 的问题。沿用原死亡测试的 raw RGB-D、native masks、查询、三动作预算、SDK 隔离真值和严格未扩张 AABB，不重新采集、不重新运行检测器、不替换任务。

## 方法冻结

- 保存每条可报告轨迹最近一帧的 feature ID、像素、公共深度反投影世界点和选中特征谱系。
- 当常规 tracker 因边界框越界而报告 LOST，但本次更新仍产生直接前后向光流对应时，不丢弃这些对应。候选必须先通过现有外观—几何能量，再满足至少 4 个候选 mask 内参考特征；每个特征继续使用既有 `FB ≤ 1.5 px`，世界点残差继续使用现有 `geometry_scale_m=0.5`，不新增调参阈值。
- 通过的对应按三维残差、feature ID、像素作确定性排序；以最小残差对应读取公共深度位置。重新初始化只消费这些已核验点及其原 feature ID，不在完整宽语义 mask 上重新抽取 80 个无谱系角点。
- 无直接对应、少于 4 点、无有效深度、几何残差超限、多候选或共享候选均保持 UNKNOWN；晚出生 query 隔离、事务 staging 和 detector/SDK 权限不变。

## 冻结验收

1. 同一输入重复两次逐字节一致，且仍拒绝 payload、mask、candidate ordering、完整重封 mask 和源码 SHA 攻击。
2. 原两次错误重识别必须归零；至少一个旧版 LOST anchor 要恢复为身份正确且严格 AABB 位置正确。
3. 完整重复候选控制必须保持 `UNKNOWN_AMBIGUOUS_REIDENTIFICATION`；无参考谱系不能凭外观能量恢复。
4. 原三个查询槽不得退化。原死亡测试的 query-level joint gain 门不事后删除；若本冻结面板没有查询目标的自然恢复收益，完整死亡测试仍记 FAIL，不扩展 S1 矩阵。
