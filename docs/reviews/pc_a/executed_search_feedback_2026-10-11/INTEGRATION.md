# 执行链与边界

入口为`tools/run_executed_search.py`，包装已有`build_task_separated_full_joint_state`，再由原benchmark实际调用observe→predict→feedback。新模块`structure_two_executed_search.py`不修改PR108入口。

## 每一步

1. 接收原被动观测与原框架推断；若上一检索未结束或框架反馈未消费，不允许前进。
2. 对缺失位置的步骤，按固定策略最多两次预探测；每次先登记动作/费用，环境再返回该位置是否找到。
3. 生成并绑定搜索计划。保留这个执行前输出，不能根据后来的终端结果把它改成首位正确。
4. 切换到completion阶段，按已提交计划检查尚未访问的位置。找到就停止，所有注册位置均空则报告support_exhausted。每位置每步最多一次，总上限等于公开菜单大小。
5. 将已收费回执支持的最终位置传入下一步搜索记忆；支持耗尽时清除失效位置。current_no_carry是唯一明确关闭终端记忆的消融，它仍执行并计费全部动作，保留原预探测记忆。
6. 调用原人物/习惯执行反馈。位置检索结果不赋予长期习惯写授权。

D0环境的实际调用与真实机器人执行不同。本轮闭合的是**理想检测器上的位置检索及跨步搜索记忆子循环**；外生世界轨迹和原人物反馈仍预先给定。没有导航/抓取执行、自然传感器检测、动作改变后续世界、新当前位置信念或联合信息增益策略。

## 计费与解释

`search_execution.staged_receipts`是实际请求/结果/阶段记录，`paid_checks`必须逐条重算。probe上限2，不意味着整项任务最多2次动作；其后的completion是PR108原先已计费的续搜，现在真实调用同一D0环境。找到后不再收费，也不重复查空位置。

原`metric_pre_completion_uncharged`仅反映预探测结束、终端执行之前的计划。各臂已获得的探测量不同，因此该首位错误数不能单独解释为公平的任务成功率；主比较看实际总检查及最终失败。尤其terminal_only与current_rank可能具有完全相同的实际位置序列，却出现不同终端前错误数。评分保留这种差异供审查，不把它当收益。

当前接口只返回确定的found/not_found，所有支持内任务最终找到是理想检测/允许遍历菜单的预期上界，不代表自然场景成功率。支持外位置明确失败，无自动注册新位置。开放世界、多人物、可逆归因等完整研究范围保持，但本轮不覆盖其全部验证。

## 局部核对边界

原D0请求校验继续拒绝错绑定、重复ID/位置、越界/预算；新增阶段门拒绝前步未完成、过早结束、重复切换、找到后继续及跨阶段消费。完整伪造响应即使重算hash也须与本环境实际签发响应一致。独立评分核对阶段、真值、成本、跨步记忆、预执行动作/修订绑定、联合/因子化公平性与长期状态不变。

这是同进程API和本地artifact复核，不是对恶意Python访问、外部签名信任、崩溃中途恢复或全仓状态机的全面验收。新进程重复从头开始，不冒充中途恢复。B独立设备复核和共享集成仍需另行完成。
