# 第二部分　结构三的研究对象

## 2.1 完整定义（§0 原文）

> 当用户使用模糊、时间化、人物化、关系化或功能化语言描述目标物体时，机器人如何把语言编译成可检查的查询约束，结合视觉、三维几何、事件、人物和习惯证据维护包含 `unknown` 的实例级联合后验；在证据不足时保留 Top-k 和 `ambiguous`，通过多视角、实例重识别和必要且安全的触觉主动确认，并根据 value of information 选择下一观察点；最终把未找到、抓取失败、滑落、部分成功和未知执行结果作为带不确定性、可追溯的证据写回长期世界模型。

## 2.2 六项不可缩减的能力

1. 从单次语义相似度升级为"**语言＋视觉＋几何＋事件＋人物＋习惯**"的联合后验
2. 使用多视角主动确认、实例重识别和必要且安全的触觉，避免单张图强行确定身份
3. 分离静态几何层与动态物体层，物体移动时不重建整张静态地图
4. 保留 Top-k、`unknown` 和 `ambiguous`，支持拒答和澄清
5. 使用信息价值选择下一观察点，而不是执行固定搜索位置列表
6. 将未找到、抓取失败、滑落、部分执行和未知结果作为**概率证据**写回，而不是确定事实

§14 原文：**"这些是实现成熟度，不代表永久砍掉后续能力。"**

## 2.3 典型查询与它们为什么难

```text
"把我晚上经常放在床边用的那个东西拿来。"
"找昨天从书房拿出来的那本书。"
"拿一个能修车的工具，不要客人刚用过的那个。"
"找那个蓝色的、像杯子、但我通常用来放笔的东西。"
```

拆开第一句，每个限定词指向的都不是外观：

| 限定词 | 指向 | 证据来源 | 属于哪条主线 |
|---|---|---|---|
| "我的" | 拥有者 | 人物身份解析 + 授权 | 结构一 SP2 |
| "晚上" | 时间/活动上下文 | 事件历史 | 结构一 SP4 / 结构二 |
| "经常" | 频率与习惯阶段 | 人物条件化习惯模型 | 结构一 SP3 / 结构二方法簇 D |
| "床边" | 三维空间关系 | 几何锚点 + 拓扑 | SP1 |
| "用的" | 功能可供性 | 使用事件记录 | 结构一 SP2 |
| "那个东西" | **实例**而非类别 | 跨天实例重识别 | SP1 |

而且目标**可能根本不在已建图部分**——被拿走了、在未探索房间、或从未被看见。

## 2.4 必须防止的十个错误（§1.2）

这份清单实际上是整个实现的规格说明：

1. LLM 依据常识猜出一个物体后直接写入世界模型
2. 只按文本—图像相似度选第一名，忽略事件、人物和习惯反证
3. 把一帧中的高置信检测当作跨天实例身份确认
4. 连续视频相邻帧被错误地当成多个独立证据
5. 物体移动导致整张静态地图重建或旧地图被覆盖
6. Top-k 截断后重新归一化，隐藏未返回概率质量
7. 没找到目标就写入"目标不在这里"
8. 抓取失败就写入"目标不是该物体"或"目标不存在"
9. 只最大化熵下降，忽略路径、时间、打扰、隐私和安全成本
10. 用 LLM 生成的解释文本反向改变世界状态

# 第三部分　三条贯穿全篇的设计原则

## 3.1 语言模型没有写入世界模型的权限

> LLM 只输出 `CompiledSemanticQuery` 或候选解释；真正的实例后验由世界模型计算。语言模型没有写入 M13–M19 的权限。

对应总纲 §11.3 的风险条目「LLM 幻觉污染地图」。LLM 的失败模式是**流畅地编造**；一旦编造物进入世界模型且带着置信度，下游无法与真实观测区分。

推论：M21 输出**查询**不输出**答案**；硬约束由独立 evaluator 给出 `satisfied/violated/unknown`；禁止用解释文本反向改状态。

## 3.2 证据缺失不等于否定证据

这条同时是结构二的中心困难之一（selective observation → 缺失是 **MNAR**，非随机缺失）。

代码形态是 `ChannelEvidence.availability`：

```python
"""``availability=0`` makes a channel explicitly missing rather than
silently treating a missing score as negative evidence."""
```

如果把"没数据"当成低似然，**从未被观察的物体会被系统性排到后面**——而那恰恰是最需要被找到的。

同一原则的其他化身：硬约束三值制；`not_found` 必须绑定真实观察机会；Top-k 不重归一化并显式报告 `posterior_mass_returned`。

## 3.3 规范记录只能追加，派生投影必须可重建

M13–M15 是 append-only 的规范层；M16 是**可删除、可重放、可重建的派生投影**。

这不是洁癖，是长期系统的必需：模型会升级、检测器会发现 bug、用户会要求删除隐私记录。当前信念若是唯一副本，这些操作要么做不了，要么静默污染历史。

代码形态是分层地图的双 revision：杯子移动只 bump `dynamic_revision`，不触发静态地图重建。

# 第四部分　闭环与七个模块

## 4.0 完整闭环

```
用户模糊描述
   ↓
M21 语言编译 ─────────► CompiledSemanticQuery（约束，非答案）
   ↓
M20 混合召回（图 + 向量 + 事件 + 历史）
   ↓
M16 六通道联合后验 ◄──── M17 习惯/转移　M18 隐藏事件　M12 人物
   ↓                      （这三路来自结构一/结构二）
   ├── resolved ──────► M25 导航 → M26 操作 → M27 写回 ──┐
   ├── ambiguous ─────► M24 信息价值选动作 ──┐            │
   └── unknown ───────►                      │            │
                     ask_user / 多视角 / 开容器 / 触觉 / 停止
                                             ↓            │
                                    M10/M11 新观测 ───────┤
                                             ↓            │
                                          回到 M16 ◄──────┘
                                             ↓
                                 M19 记忆可信度与生命周期
                                             ↓
                                   M13–M15 规范记录（append-only）
```

**这不是流水线，是环。** `ambiguous` 不是失败，是"我需要更多信息"的正常状态。

## 4.1 M21 自然语言落地与消歧（SP6）

输出 `CompiledSemanticQuery`：约束集合，不是答案。

**硬约束三值制**是这里的核心设计：每个候选必须对每条硬约束给出 `satisfied / violated / unknown` 加 evaluator 版本。

- `violated` → 候选后验为零，直接排除
- `unknown` → 保留候选，但**阻止 resolved**
- `soft_constraints` → 只改变似然与先验，不排除

**为什么三值？** "不要客人刚用过的那个"这类约束，多数时候你没有证据判断。二值制下你要么排除（漏掉真目标）要么当满足（拿错）。三值把这种状态显式化，并逼系统去问或去验证。

`person_entity_ids` 必须来自**已授权**的身份解析（M28 治理）；未解析指代不得静默绑定给当前用户。

## 4.2 M16 多假设概率信念投影（核心）

维护的联合后验：

$$P(O,L,I,E,A,Z \mid Q, Y_{1:t}, G_{1:t}, V_{1:t})$$

物体实例 $O$、位置 $L$、身份 $I$、事件 $E$、行为者 $A$、习惯阶段 $Z$。

**注意 $A$ 和 $Z$——这两个变量把结构三和通用开放词汇检索彻底分开。** 详见第五部分。

候选集合必须含一个显式 unknown：$\mathcal C = \{c_1,\dots,c_n,c_{\text{unknown}}\}$。它表示目标可能尚未建图、召回失败或描述无法落到已知实例；它不是普通物体节点，不能携带伪造位置。

**当前基线**（经校准的加权对数意见池）：

$$\log \tilde p(c)=\log p_0(c)+\sum_{m\in\mathcal M}w_m\,r_{m,c}\,a_{m,c}\log p_m(e_m\mid c)$$

§4.2 与 §4.3 明确这是**可审计、可替换的 baseline，不是最终概率图模型**，后续可换成因子图、动态贝叶斯网络、粒子滤波、结构化能量模型、神经符号概率模型或学习式融合——**"最终选择需要由匹配基线、校准、行动效用和外部有效性共同决定；本文件不替项目负责人预先固定唯一方法。"**

**决策门控（三态）**：

```
unknown 质量高，或高于最佳已知实例    → unknown   → active_verify / abstain
最佳实例低于阈值，或前二 margin 太小   → ambiguous → active_verify / ask_user
两条件同时满足                       → resolved  → return_top_k
```

阈值必须按任务风险分别校准——药品、隐私物品和高风险操作不能复用普通遥控器的阈值。

**询问不是失败**（§5.2）：M24 把 `ask_user` 当作与转头、绕路、开容器、安全触摸并列的信息获取动作。

## 4.3 M11 实例重识别与数据关联（SP1）

融合来源：开放词汇检测与分割、DINO/CLIP/SigLIP 表征、RGB-D 点云形状尺度、相对静态锚点的空间关系、跨时间位置与运动连续性、**人物携带/放置/使用事件**、历史实例特征与冲突候选。

**证据簇去重**：同一视频片段的相邻帧共享 `evidence_cluster_id`，只取质量最高的一帧作代表。防止把 30 个高度相关的观测当成 30 份独立证据。

**身份 resolved 需三条件同时满足**：独立视角数达标、第一名后验超阈值、前二 margin 超歧义阈值。否则保持 `ambiguous`。

**触觉是受限动作**，不是默认：需视觉/几何确实无法区分、经可供性与安全检查、不涉及危险/易碎/污染/药品/隐私/未授权对象、预期信息价值高于成本、触觉模型在当前物体域有校准证据。且**契约边界拒绝绕过**——即使外部直接构造触觉身份证据，未授权或不安全的请求也会被拒。

触觉不能通过"摸起来像"覆盖明确视觉或用户反证。

## 4.4 M08 三维场景与拓扑地图（SP1/SP7）

| 层 | 内容 | 何时改版本 |
|---|---|---|
| `StaticGeometryAnchor` | 房间、墙、地面、固定家具、容器锚点；mesh/TSDF/occupancy 引用；层级拓扑；稳定坐标系 | 仅静态结构变化 |
| `DynamicObjectState` | 实例 ID、所属锚点、6DoF 位姿、局部点云与特征引用、状态概率与来源 | 物体移动 |

**强制约束**：动态物体位姿 frame 必须与所属静态锚点 frame 一致；跨 frame 写入必须先经 M02 `FrameRegistry` 变换。防的是相机坐标系检测被直接写进世界坐标地图。

旧状态通过 M13–M15 追加式历史保存；**内存中的当前动态视图是可重建投影，不能覆盖规范历史**。

**§7.3 的职责划分**：

- VIO/SLAM（M07）→ 位姿、相机位姿、坐标变换。**不负责语义识别**
- RGB-D/点云/TSDF → 几何、遮挡、尺度、抓取输入。**不决定物体属于谁**
- VLM/检测/重识别（M10/M11）→ 开放词汇语义与实例候选
- 全局搜索/导航（M24/M25）→ 房间、锚点、观察视点
- MPC/MPPI → 动态约束下的局部安全运动。**不决定语义搜索顺序**

## 4.5 M24 主动搜索与主动感知（SP8）

$$IG(a)=H(B_t)-\mathbb E_{y\sim p(y\mid a,B_t)}[H(B_{t+1}\mid y,a)]$$

$$V(a)=\lambda_I IG(a)-\lambda_M C_{\text{motion}}-\lambda_T C_{\text{time}}-\lambda_U C_{\text{interrupt}}-\lambda_P C_{\text{privacy}}-\lambda_S C_{\text{safety}}$$

动作集合是**异质**的：`move_viewpoint / micro_verify / open_container / touch / ask_user / stop`。询问与物理动作在同一效用尺度上竞争。

**全篇最尖锐的一条工程约束**（§8 末尾）：

> M24 和 M16/M09 必须使用同一版本的 `ObservationLikelihoodModel`，否则机器人会用一种检测概率规划、再用另一种检测概率解释"没找到"。

契约层用 `observation_likelihood_model_id` + `calibration_domain` 强制这一致性。

> 总纲 §0.2 提醒：**主动搜索是世界模型的下游能力，不是项目中心。** M24 的价值在于它让 M16 的信念可被行动检验，而不在于它本身省了多少路径。

## 4.6 M27 闭环写回与在线重规划（SP7）

结果不是布尔值而是分布：`success / not_found / grasp_failed / object_slipped / partial / unknown`。

$$P(X=1\mid f,a)=\frac{P(f\mid X=1,a)P(X=1)}{P(f\mid X=1,a)P(X=1)+P(f\mid X=0,a)P(X=0)}$$

**三条不变量：**

1. **`not_found` 必须绑定目标实体、尝试位置和事先记录的观察机会（M09）。** 没有观察机会记录，无法区分"不在那儿"和"被遮挡/太远/没看那个方向"。
2. **结果模型必须覆盖反馈中所有正概率结果。** 实际出现 `grasp_failed` 但模型只定义 `success/unknown` → 拒绝更新，而非静默丢弃概率质量。
3. **动作成功 ≠ 任务目标达成**：`task_goal_satisfied_probability ≤ outcome_distribution.success`。导航成功只推进任务图，不让取物闭环提前结束。

**保证的语义**：未找到降低概率但不降为零；抓取失败不否定身份；滑落意味着机器人自己造成了位置变化，需产生新位置候选；部分与未知保持概率质量。

## 4.7 M19 记忆生命周期与持续学习（SP5）

**核心立场**：

> `time since last seen` 与 `category stability` 只是**先验变量**，不等价于当前记忆可靠度。

因为**旧 ≠ 错**：桌子可能半年没动，杯子可能 30 秒被拿走。统一指数衰减把两者当成一回事。

代码里写成硬不变量：`age_used_as_direct_reliability_evidence=False`；原始 `seconds_since_last_direct_observation` 只用于区分呈现层的 fresh/stale。

**当前状态可靠度应取决于**：原始观测质量、实例身份后验、机器人定位与坐标不确定性、后续人物与物体事件、未观测携带/放置/交接候选、视野与遮挡与容器状态与检测似然、正证据与已验证负证据与冲突、**人物条件化习惯和当前习惯阶段**、证据独立性、用户纠正与权限与模型版本、机器人自己的行动结果。

要表达"过去十天可能被移动"，必须由带人物、物体、活动、情境和时间间隔的 `TRANSITION_SURVIVAL` 模型提供似然——**这个模型来自结构一/结构二**。

**八个生命周期状态**：`uncertainty_growth` / `contradicted` / `superseded` / `historical` / `habit_regime_change` / `archived` / `deleted` / `true_forgetting`。

`contradicted`（我错了）与 `superseded`（情况变了）的区分尤其重要，多数系统混为一谈。`habit_regime_change` 直接对应结构二方法簇 D 的非平稳习惯生命周期。

# 第五部分　person / event / habit：结构三的分水岭

这一节是上一版最大的缺失。

## 5.1 六通道不是六个平等的通道

```
language  ─┐
visual    ─┤ 这三路 = 通用开放词汇实例检索也有
geometry  ─┘
─────────────────────────────────────
event     ─┐
person    ─┤ 这三路 = 结构三独有，来自结构一/结构二
habit     ─┘
```

**去掉后三路，结构三就退化成 ConceptGraphs / OK-Robot / GOAT 那一类工作。** 前三路是必要基础设施，后三路才是研究身份。

## 5.2 三路各自的来源与作用

**person 通道**（M12 人物、活动与事件感知 → M13 关系图）

- 来源：结构一 SP2「人物归属、使用关系与家庭角色」
- 内容：`belongs_to` / `used_by` / `carried_by` / `shared_by`
- 作用：让"不要客人刚用过的那个"成为可检查的硬约束
- 难点（结构二困难三）：同屋多人会把别人的行为写进主人模型

**event 通道**（M18 隐藏事件与因果候选推理）

- 来源：结构二方法簇 C「事件层次与反事实行为者归因」
- 内容：拿起、携带、交接、放置的**未观测**候选链及其证据
- 作用：让"昨天从书房拿出来的那本书"可解析——书现在不在书房，但事件链解释了它去哪
- 难点（结构二困难二）：关键转移常发生在机器人离开后

**habit 通道**（M17 个性化习惯与转移模型）

- 来源：结构一 SP3 + 结构二方法簇 D「可回归、可复用的非平稳习惯生命周期」
- 内容：人物—物体—时间—活动—地点条件化习惯，及当前习惯阶段 $Z$
- 作用：让"晚上经常放在床边"成为一个有概率含义的量，而不是一句修辞
- 难点（结构二困难四）：习惯会形成、渐变、突变、周期切换、中断再返回

## 5.3 这条依赖关系的双向含义

**向下**：结构三不能假装这三路是现成的。它们的质量上限由结构一/结构二决定。结构三的 oracle 轨道必须**分维度**给出身份、位置、事件、人物、习惯阶段各自的真值上界（§14.1），才能定位到底是哪一路拖后腿。

**向上**：结构三是这三路的**下游检验场**。总纲 RQ6「如何让任务执行反过来持续改进语义地图」和 §11.6 风险「地图提升无法转化为机器人能力」——结构三的 M27 写回闭环就是回答这两条的地方。结构二 §6 的 RQ2-6「信念怎样改善不止一种机器人能力」同样在此检验。

**所以结构三既是消费者也是验证者。** 这个双重身份是它在总项目里的位置，也是它不能被讲成"一个检索系统"的原因。

# 第八部分　评价协议

## 8.1 四类指标

**查询与联合后验**：object-instance Recall@k、MRR、Top-k accuracy；`unknown` AUROC/AUPRC 与 open-set risk；ambiguous 检测准确率；selective risk/coverage；ECE、Brier、NLL；询问正确率与不必要询问率；每通道缺失与误校准下的鲁棒性

**实例确认**：跨视角/跨房间/跨天 re-ID accuracy；ID switch rate；单帧→多视角→+事件→+必要触觉的消融；证据相关性重复计数造成的过度自信；相似实例误拿率

**地图与行动**：静态地图不必要重建次数；动态对象更新延迟与位置误差；每次确认的信息增益、移动成本与打扰成本；correct-instance retrieval success；搜索时间、路径长度、SPL；抓取失败/滑落/未知后的恢复成功率；**写回前后信念与后续任务效用变化**

**必须报告的基线**（11 条）：从 `text-image similarity only` 到 `oracle identity/location/event upper bounds`

## 8.2 两条约束

结构三 §13.4：

> ECE、Brier 和 NLL 只作为**诊断**，不能单独证明方向有效。最终 go/no-go 必须看同预算下的实例检索、误拿率、行动效用和真实/半真实外部有效性。

总纲 §0.3：

> 搜索时间、移动距离、观测成本和验证成本**不得取代**语义地图质量、长期记忆质量、人物—物体关系和持续学习能力。

**两条合起来的意思是**：校准分数和搜索代价都只是仪表盘上的读数，不是方向的目标函数。结构三是否成功，要看它有没有让语言真正接上一个可追溯的长期个性化世界模型，并且让行动结果真正回流改善那个模型。

# 第九部分　完成定义（§15 原文）

> 结构三最终完成不是"LLM 猜对了一个物体"，而是：
>
> 对模糊描述，系统能够从真实世界模型中召回已知实例并保留未知可能，输出经校准、可追溯的多模态联合后验；当身份或位置证据不足时，不强行下结论，而是在询问、多视角、移动、开容器和必要触觉之间选择净信息价值最高且安全合规的动作；机器人搜索、导航和操作产生的成功、失败、滑落、部分和未知结果以概率证据进入规范记忆，驱动可重建的信念更新与在线重规划，同时保持历史事件、当前信念、个性化习惯和真正遗忘之间的语义边界。

最后一句是全篇的收束：**历史事件、当前信念、个性化习惯、真正遗忘——四者之间的语义边界不能塌陷。** 这四个东西分别活在 M14、M16、M17、M19，而它们的边界正是结构三与结构一、结构二共享的那套契约在守护的东西。

# 第十部分　当前文档层面的开放项

以下不是"缺陷清单"，是按结构二 §0.6 的口径需要**由实验和 ADR 确定**、或需要在文档中补齐的开放项。

## 10.1 融合算子尚未由实验和 ADR 确定

§4.2/§4.3 已诚实声明加权对数意见池是可替换 baseline，候选包括因子图、DBN、粒子滤波、Rao-Blackwellized filter、结构化能量模型、神经符号模型、学习式融合。**尚未有 ADR 记录选择依据。**

需要注意：$\{w_m\}$ 是一个聚合权重族。你自己的 RRCL 工作给出了「在二阶充分统计量信息集下这类权重的选择可能不可辨识」的刻画（命题 A/B）。这可以作为**保持 $w_m$ 外部固定并做敏感性分析**的正面论证，写进 ADR。

## 10.2 `unknown` 的似然缺少生成模型

契约强制每个候选（含 unknown）提供全部六通道 `ChannelEvidence`，那么 $p_{\text{language}}(e\mid\text{unknown})$ 的语义是什么？目前只能外部指定，而 §13.1 的 `unknown` AUROC 指标恰恰建立在它上面。

一条可能的出路：从**空间覆盖率**导出——未探索体积上的目标先验，加上已观测区域的校准漏检率。这样它有可证伪性质（覆盖率↑ → unknown 后验↓，且应与经验频率吻合）。**属于待定，不预先冻结。**

## 10.3 `unknown` 不带位置与 VoI 需要位置之间的张力

§4.1 说 unknown "不能携带伪造的位置"；§8 要选下一观察点则必须知道去哪找它。可能的调和：unknown 不带**点**位置，但带一个覆盖率导出的**空间密度场**。需要在文档中显式处理。

## 10.4 硬约束长期 `unknown` 的退化风险

`best_has_unknown_hard_constraint` 强制降级为 ambiguous。现实中多数硬约束长期处于 unknown，可能导致"永远 ambiguous → 永远询问"。**需要消融，并可能需要按约束风险分级处理。**

## 10.5 M24 当前为一步贪心

`open_container` 是天然两步动作（开门本身可能 IG=0）。非近视规划（rollout / POMCP）属于待评估选项，不预先冻结。

## 10.6 §13.4 的基线全是内部消融

11 条基线没有一条外部工作。这与总纲 §9「基线与消融原则」和结构二 §7「最强基线不是单篇论文，而是组合系统 …… 必须构造增强组合基线」的要求不一致。**需要补外部匹配基线，并按结构二 §7.2 的口径构造组合基线。**

## 10.7 分维度 oracle 轨道尚未成套

§14.1 已列为 S3-1 待办：身份、位置、事件、人物、习惯阶段各自可审计的真值轨道。**这条对第五部分的依赖关系诊断是必需的**——没有它就无法判断某次失败是结构三的融合问题还是结构一/二的上游质量问题。
