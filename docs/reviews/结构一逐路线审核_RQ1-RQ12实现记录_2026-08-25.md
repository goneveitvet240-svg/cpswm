## 1. RQ8：硬 actor truth 泄漏，量化后是 95.3%

### 1.1 就是这五行

`CoreHabitChainMethod._step` 里：

```python
owner_mass = (
    event.observation_quality
    if event.actor_id == self.owner_id      # <- 这一行
    else 1.0 - event.observation_quality
)
```

`ProjectOneDatasetRecord.actor_id` 记录的是**谁真的动了那个物体**。
模块 docstring 写着「has no truth-bearing field」，`FORBIDDEN_RECORD_FIELDS` 也
只拦 `expected_location / true_regime_id / ...`——`actor_id` 从来没被算作真值。

### 1.2 泄漏有多大

新增 `audit_actor_truth_isolation`：同一条流跑两遍，第二遍把 actor 标签整体置换，
**其余字节完全相同**，人物证据通道保持不变。任何预测差异只能来自 `actor_id`。

十个确定性场景族，冻结的 v0.3 接线：

| 场景族 | 发散事件 | 最大概率差 | 决策翻转 |
|---|---:|---:|---:|
| stable_habit | 19/20 | 0.2479 | 0 |
| periodic_habit | 23/24 | 0.2329 | 0 |
| short_disturbance | 20/21 | 0.2479 | 2 |
| permanent_change | 24/25 | 0.2479 | 2 |
| recurring_regime | 29/30 | 0.2479 | 4 |
| context_change | 23/24 | 0.2479 | 2 |
| missing_observations | 20/21 | 0.2479 | 0 |
| biased_observation | 21/22 | **0.4270** | 0 |
| **gradual_drift** | 22/24 | 0.2479 | **12** |
| abrupt_change | 22/23 | 0.2479 | 2 |
| **合计** | **223/234 = 0.953** | | |

`gradual_drift` 上 24 次决策里有 12 次翻转——一半。

### 1.3 更要命的一条：只有链式臂在读

逐臂审计（`test_no_baseline_arm_ever_read_actor_truth`）确认：
`CategoricalBOCPDMethod` / `ContextFrequencyMethod` / `PersistenceMethod`
**从来没有读过 `actor_id`**，三个基线在置换下逐字节不变。

也就是说：

> v0.3 里所有「链式臂 vs 三个基线」的读数，都是在**链式臂持有人物真值、
> 三个基线不持有**的条件下取得的。那不是方法对比，是信息量对比。

这条与 08-24 复盘里「你给基线配了与端点同构的读出，自己却用通用读出」是同一个病，
只是方向相反：这次是你自己多拿了信息。

### 1.4 改了什么

新增 `project_one_actor_evidence.py`，四条策略：

| 策略 | 含义 | 是否遮蔽 `actor_id` |
|---|---|---|
| `LEGACY_HARD_ACTOR` | **默认**，冻结 v0.3 接线，所有历史数字逐字节可复现 | 否 |
| `ABSENT` | 完全没有人物证据——D0 记录在案的不可识别情形 | 是 |
| `CONTROLLED_NOISE` | 必须保留不确定性的机器人可见后验 | 是 |
| `ORACLE` | one-hot 真值，**显式标记为上界**（`is_upper_bound=True`） | 是 |

三个设计决定值得单独记：

1. **遮蔽是结构性的**：`_BaseMethod.observe` 在把事件交给子类之前把 `actor_id`
   换成 `masked_actor`，所以将来新写的臂不可能「忘记」。
   `test_masking_is_structural_not_advisory` 钉住这一点。
2. **默认不变**：与 `LEGACY_SIGMOID` 同一手法。一个悄悄改变历史读数的修复不可审计。
3. **策略进 config_hash**：四种策略的 `config_hash()` 两两不同，
   所以 oracle 跑出来的结果不可能被当成方法成绩归档。

`ORACLE` 与 `LEGACY_HARD_ACTOR` 不是一回事：oracle 走的是与其他策略同一条通道，
会被记进 config、会被标为上界；legacy 是从记录字段直接读，什么都不留下。

### 1.5 下一步（唯一有意义的那个）

在 `ABSENT` 与 `CONTROLLED_NOISE` 两种策略下重跑 300 条流的多 seed 对照。
**两者的差值就是「人物信息值多少」**，这正是 RQ8 要回答的问题；
而现在这个数字一次也没被测过。

## 2. RQ5：additive pooling 把一次观察读成三次

### 2.1 量化

新增 `measure_evidence_multiplicity`——不推导，直接测：喂 n 条相同证据，
反解「一个单层 Dirichlet 要多少样本才会这么自信」，再除以 n。

```text
evidence multiplicity (1.0 = 诚实):
  additive HierarchicalDirichlet : 3.0
  back-off LayeredHabitPosterior : 0.5
```

**恰好 3.0。** 原因在 `predict` 的打分式：

```text
score(L) = k0*P_common(L) + w_h*n_household(L) + w_p*n_person(L) + w_c*n_context(L)
```

一条 owner 证据会同时增加 household、person、context 三张计数表，默认权重都是 1.0，
于是它在打分式里出现三次。逐条读数：

| n 条相同观察 | additive | back-off | 诚实单层 |
|---:|---:|---:|---:|
| 1 | **0.8333** | 0.5556 | 0.6667 |
| 2 | 0.9048 | 0.6667 | 0.7778 |
| 4 | 0.9487 | 0.7778 | 0.8667 |
| 8 | 0.9733 | 0.8667 | 0.9259 |
| 16 | 0.9864 | 0.9259 | 0.9608 |

一条观察给出 0.8333，而证据只支持 0.6667。

**这条读数值得和另一条并排看**：多 seed v0.3 报告里
`full` vs `rls_only` 的配对间隔差是 +0.0001，即「Dirichlet surprise 通道叠加在
残差之上几乎没有增量」。一个系统性过锐 3 倍的 Dirichlet，其 predictive surprise
本来就会被压平——这是那条 null 的一个可检验机制假设，不是结论。

### 2.2 一个中途发现的坑

第一版实现写成了教科书式的嵌套 back-off：

```text
P_household = (n_h + k_h*P_common)  / (N_h + k_h)
P_person    = (n_p + k_p*P_household)/ (N_p + k_p)
P_context   = (n_c + k_c*P_person)   / (N_c + k_c)
```

**它同样重复计数**，只是换成了乘法外衣：单住户单情境时 `n_c = n_p = n_h`，
同一条观察先抬高 household，再作为先验抬高 person，再作为先验抬高 context。
实测重复度 5.5，比 additive 还差。

正确形式是 **leave-one-out**：父层只用被预测单元的**兄弟**估计。

```text
n_person_excl(p)    = n_person(p)    - n_context(p, c)     该人物的其他情境
n_household_excl(p) = n_household    - n_person(p)         其他住户
```

这样这个 `(household, object)` 下的每一条观察在整条链里**只出现在一个分子里**，
三个池互不相交、并集是全部证据。`evidence_report` 断言
`counted_evidence_mass == observations_applied` 且 `multiplicity == 1.0`——
是可证的分区，不是希望。

### 2.3 与文档的关系

§4.2 你已经改过了：它不再给单一公式，而是保留三条互斥候选路线
（分层贝叶斯收缩 / 专家混合 / 温度化似然比专家乘积），待 validation-only 选择。

本模块实现的是**路线 1**。同时它把**路线 3 的对象也一并给出**：
`LayeredHabitPrediction.deviation(layer)` 返回的正是该层相对父层的似然比，
而「常识先验 × 各层似然比」重构后验的误差是 **0.0**（`test_the_deviation_product_
reconstructs_the_posterior_exactly`）。所以路线 1 与路线 3 在表示层不是对手，
3 是 1 的乘法读法；两者之间真正要比的是温度与概率地板。

`k`（concentration）顺带把 §4.2 最后那句话变成了机制：
「个性化证据逐渐覆盖常识，但不能因一次异常彻底覆盖长期规律」——
一层大约需要 `k` 条观察才压过父层，所以 20 条稳定证据后的一次异常不会翻盘
（实测仍 > 0.5），而 40 条持续的个人证据能压过 0.9 的常识先验。

## 3. RQ4 + RQ6：七类不互斥，所以表示是轴、名字是投影

### 3.1 冲突本身

文档 §5 给七类：`anchored / stable / home-based mobile / multimodal /
activity-carried / wandering / regime-changing`。
代码 `mobility_profile.py` 给五类，且是真正互斥的分区。两边都不对：

- 文档那七类**不是分区**。水杯可以同时是 multimodal 与 activity-carried；
  钥匙在搬家后几周里同时是 home-based mobile 与 regime-changing。
  强行一物一签，就必须丢掉一个为真的陈述，而丢哪个取决于阈值顺序。
- 代码那五类换来了分区，代价是丢掉三个区分：没有任何量测活动耦合，
  没有任何量测「主位置本身在不在移动」，且 `MULTI_LOCATION` 把 multimodal
  和 wandering 合并了。

`test_an_object_can_be_two_documented_types_at_once` 把非互斥性变成一条会红的测试。

### 3.2 五轴

| 轴 | 定义 | 它单独能分开什么 |
|---|---|---|
| `displacement` | 相邻观察改变位置的比例 | anchored vs 其余 |
| `return` | 离开主位置后最终回来的比例 | 习惯循环 vs 迁移 |
| `spread` | 归一化位置熵 | 涉及几个地方 |
| `context_coupling` | `I(context; location) / H(location)` | **activity-carried**，五类实现里没有任何对应物 |
| `regime_drift` | 前半段与后半段位置分布的全变差距离 | **regime-changing**，熵看不见 |

最后两条是新增能力，各有一个判别性测试：

- `test_regime_change_is_visible_where_entropy_is_not`：
  「隔天在两地之间稳定往返」与「前十天在 A、后十天在 B」**熵完全相等**
  （断言 `approx(abs=1e-9)`），只有按时间切分才分得开。
- `test_activity_carried_requires_context_to_actually_explain_position`：
  同样两个情境、同样两个地方，配对打乱后 coupling 从 1.0 掉到 < 0.5。
  否则「有多个 context」就会把几乎所有物体标成 activity-carried。

七类降为对这五轴的投影，返回**集合**；歧义时 `resolution = AMBIGUOUS`，
同时按一个写死的、有理由的优先序（`MOBILITY_TYPE_PRECEDENCE`）给出主标签，
让下游有东西可 switch，但歧义不被藏起来。

### 3.3 RQ6 的四项

| 缺口 | 落地 |
|---|---|
| 停留时间 | `DwellStatistics`：到达某处到首次在别处被看见的小时数，median/mean/p90 |
| 活动条件 | `ContextualMobility`：逐 context 的位置分布与转移计数，外加 `contexts_disagree` |
| 开放位置质量 | `OpenWorldMass`：落在声明候选集之外的质量**保留**，不归一化掉（§7） |
| 未决状态 | `MobilityResolution`：`RESOLVED / AMBIGUOUS / INSUFFICIENT_EVIDENCE` |

`contexts_disagree` 这个标志有具体用处：为真时，**池化的转移矩阵描述的是一个
从不发生的平均行为**。RQ6 要「活动条件」正是为了这个。

另外补上了 §5 的「人物条件化转移矩阵」：画像键是 `(household, object, person)`，
`person=None` 是池化视图，两者可以不一致且测试要求它们能不一致。

## 4. RQ1：缺失机制第一次成为字段

三件事本来就有且做得不错——`ObservationOpportunityRecord`（机会与选择概率）、
`ObservationDetectionResult`（结果，且漏检时结构性地不能从真值补身份）、
`ObservationPropensityCorrector`（倾向权重）。第四件**只存在于一句 docstring**：
「missingness is usually MNAR」。

这不是记账问题。IPW 只在 **MAR 且以实际记录的协变量为条件**时无偏。MNAR 下它有偏，
而且偏的方向正对着被测效应——机器人**因为怀疑物体动了才回头看**。
今天这两种运行产出完全相同的 `PropensityWeight`，读者分不出来。

新增 `ObservationMechanismEnvelope`，把四件事绑成一条记录，并把机制变成会校验的字段：

- `MAR` 必须给出非空 `conditioning_covariates`——不点名协变量的「随机缺失」是断言不是模型；
- `MNAR` 允许纠正，但强制 `correction_validity = BIASED_DECLARED` 且必须写
  `residual_bias_note`，让残余偏差和数字挨着；
- `UNDECLARED`（诚实默认）**禁止任何非 1.0 的纠正**——沉默不是 MAR；
- `correction_validity` 是**推导**属性，不是字段：一个生产者能设的字段迟早会被设错。

顺带把 §7 里两条一直没有执行体的禁令变成结构性校验：

```text
未打开容器不能产生容器内部负证据   -> FULL/UNKNOWN 遮挡 + 负证据 = 拒绝
低质量视角不能产生强排除          -> FOV < 0.5 + 负证据 = 拒绝
```

（另外两条——`not_observed 不等于不存在`、`纯模型预测不能成为训练证据`——
本来就已经是结构性的。）

## 5. RQ9：权限矩阵

散文里三份文档各说了一半：「CF-BOCPD 仅提出变化候选」「候选先隔离，不写任何长期统计」
「RGRC 负责 quarantine / promote / retract / reactivate」。代码里一句都没有。
一次让检测器直接写计数的改动会通过全部测试，而结果读起来像检测器变强了。

`operator_authority.py` 把它变成会抛异常的矩阵。承重的三行：

| 算子 | 可写 | 关键的「不可写」 |
|---|---|---|
| `CF_BOCPD` | `change_candidate` | 不可写长期统计——「检测器开火」≠「习惯移动了」 |
| `CCRR` | `regime_route`, `regime_library` | 不可写长期统计——选哪个 regime ≠ 判定证据可采信 |
| `RGRC` | `quarantine`, `long_term_statistic` | **唯一的长期写入者**，且必须先 `record_promotion` |

把长期写入权限集中到一个算子，是为了让「访客污染」有唯一的排查入口。
`test_rgrc_is_the_only_long_term_writer` 钉住这一点。

另有一条 RQ8 的延伸：**没有任何消费方可以编辑它被评判所依据的 actor posterior**

门写好了，门后面的东西没做。

## 6. RQ10：审核判断过期了

审核写「分层思想很好，但未实现」。核对代码后，四项里三项此前已经实现：

- 独立 schema：`PlacementMemoryClass` 四类 + `StatedPreferenceAssertion` /
  `PlacementNormAssertion` 两个独立记录类型，都不带训练权重；
- 冲突规则：`PlacementDecisionResolver` 按硬约束与 `safety_priority` 排序，
  硬 `MUST_BE_AT` 压过明确偏好，撞上硬 `MUST_NOT_BE_AT` 直接 blocked，
  且**没有偏好和强制规范时选择弃答而不是回落到观察习惯**；
- 授权来源：`source_type` 按类隔离（明确偏好必须来自 user，常识规范不可以），
  `stated_by` 必须是人。

真正缺的是第四项。`superseded` 是一个生产者随手设的 bool，没有任何东西检查是谁设的。
照当前状态：访客的一句话可以撤销主人的长期指令；一次模型更新可以撤销家庭安全规范——
而且是悄悄的，因为「撤销一条规则」和「写一条规则」长得一模一样。

`update_policy.py` 补上三条：

1. **同级或更高权限才能撤销**（沿用已有的 `AuthorityLevel` 阶梯）；
2. **规范只能在同源内被撤销**：家庭规范可以撤销常识先验，反之不行；
3. **撤销硬安全约束需要显式确认**——不是「权限够就行」，
   而是撤销方必须在一个字段里说明自己知道正在移除一条安全约束；
   硬**家庭**安全规范另加一条：只有 household owner 可以。

另有一条跨类规则：**明确偏好永远不能撤销一条硬规范**，只能共存并由 resolver 裁决。
这正是 §9 「最可能在哪里找到 ≠ 应该放回哪里」的可执行形式。

RQ10 剩下的真正缺口不在实现，而在评价：**没有任何端点测量 §15.3 的
「行为、偏好和规范的区分准确性」**。已写进就绪账本的 next gate。
