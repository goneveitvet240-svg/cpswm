# 可选后缀重放：同状态、少重算，存在内存代价

2026-10-23，12 小时自主推进窗口的第二批。新增 `SuffixReplayMemory`：连续追加复用完整前缀，迟到/修订从受影响位置之前的可用检查点重放全部后缀；缺少检查点则退回全重放。完整模型/先验/24 粒子/三个 RB blocks/七算子范围和动作读出不变。默认仍为完整重放，可显式选择 suffix。

**结果：**开发矩阵中与完整重放逐点一致，24 事件长前缀样例的评分减少 76.6%、输入处理时间约缩短至一半，但缓存增加内存。它是工程执行优化，不是新的推断方法，也不是联合机制的科学收益。

## 实现与等价范围

- 从 `SimulationMemory._rebuild_native` 抽出创建 runtime 和追加单个 observed 历史的方法，完整重放仍沿用相同逻辑。新的缓存类有独立入口，不替换所有生产修订逻辑。
- 缓存绑定已消费证据前缀、episode/人物模型/配置/地点目录及完整原生运行状态指纹。完整指纹含三个 RB 统计、采样回执、操作 journal、账本 pending 状态及内部更新前快照。模型路径使用 basename，实际模型权重完整绑定。
- 缓存只保留未变前缀；修改 observed 为 lost、迟到插入、同事件回正均会失效相应后缀；预测和机器人生成输入不被写为人物历史。公开 runtime 与私有检查点不共享可变状态。
- stride=4，最多 8 个检查点，保留最新状态；这是缓存数量上限，**不是恒定内存上限**。每个检查点仍保留增长的历史/journal。复制、哈希、历史分布计算也有成本，不能宣称整体算法复杂度只等于重放事件数。
- 推断/复制/哈希/内部校验成功后发布缓存；故障注入后，已发布记忆、来源、缓存和账本不变，后续仍可继续。
- 性能计时留在 `replay_history` 遥测中，确定性 audit 只包含状态/来源/计数，避免重放时因计时不同误报。

同来源、相同输入顺序和环境下，检查完整 runtime 指纹、记忆版本、来源集合、当前位置、目标分布、账本和三个 RB 统计；同输入的完整重放是正确性参照。额外逐点匹配 PR119 归档的 128 个原生检查点，防止两条新路径一起引入同一个错误仍互相通过。

## 成本实测

每个方法用新进程顺序执行，两个 native 臂、archive/long 两个输入集、三轮计时重复，总计 24 个进程。第二轮反转 full/suffix 顺序，减少固定运行顺序偏差。没有独占主机或置信区间声明。

archive 为 PR119 两种 fixture × 四条件；每个臂 64 个输入检查点。long 为 24 条既有语义值构造的工程输入，加晚/中/早位置修订及回正 6 次，共 30 点。每轮两个臂合计 188 个检查点，三轮共 564 次配对状态比较全部一致。重复计时不增加独立世界数。
