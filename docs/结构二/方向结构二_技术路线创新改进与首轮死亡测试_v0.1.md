## 0. 结论先行

方向结构二当前不是缺少功能列表，而是缺少一个能够把已有技术积木变成**新方法主张**的中心机制。

已有工作已经分别覆盖：

- O-STaR 的机会式观察、位置概率更新和成本感知搜索；
- STREAK 的家庭物体迁移持续学习；
- GESTO / EGG 的人—物事件图；
- HUMEMBR 的跨日人物身份与规律；
- WorldLines / ObsMem 的观察、状态、信念和规划分离；
- HERMES 的时序场景图、事件边、用户习惯/偏好节点和长期检索；
- BOCPD、HMM 和 rehearsal（回放）等通用非平稳学习机制。

这里必须区分两件事：**已有工作覆盖了某类组件，不等于该组件不能继续产生方法创新**。已有工作只意味着不能把组件名称本身当作贡献；只要我们改变它的建模假设、状态变量、更新算子、学习目标或决策闭环，并证明改变解决了旧方法系统性失败的情形，就仍然是完整的方法创新。

因此，以下内容若**原样复用或只做普通拼接**，不足以构成强方法创新：

- “增加事件图”；
- “增加人物标签”；
- “用 BOCPD 检测变化”；
- “用 GNN / Transformer 预测下一个位置”；
- “建立时序场景图并保存习惯节点”；
- “用 Dirichlet 分布表达不确定性”；
- “把上述模块串成流水线”。

但这些组件都可以成为本项目的创新载体。例如：把普通事件图改成保留互斥隐藏事件假设和可撤销来源的反事实事件超图；把普通 BOCPD 改成不同变化原因重置不同参数块的原因结构化变化点推断；把普通 Dirichlet 计数改成显式建模观察产生过程、证据相关性和人物责任的后验期望更新。这里的判断标准不是“别人是否用过这个名词”，而是“我们的新算子是否产生了旧方法不能产生、且对具身行动有用的行为”。

当前最值得检验、同时也最容易被证伪的中心问题是：

> 当机器人看到的物体位置分布发生变化时，模型能否区分这种变化来自 observation-policy shift（观察策略漂移）、resident-mixture shift（住户构成漂移）、identity/association shift（身份/关联漂移），还是真正的 owner habit-regime shift（主人习惯阶段漂移）？

若不能分离这些原因，变化点检测器会把“机器人最近少去书房”或“访客最近常来”误写成“主人改变了习惯”；联合模型再复杂也只是更难审计的相关性拟合器。

本文件原先将下列内容组织成三条互相竞争的路线；现根据项目范围决定，将三者全部纳入统一方法，作为彼此依赖的子系统：

1. **路线 A：Shift-Cause-Separated Regime Inference（漂移原因分离的阶段推断）**；
2. **路线 B：Posterior-Gated Quarantine Consolidation（后验门控的隔离式巩固）**；
3. **路线 C：Recurrent Regime Library（可回归的历史阶段库）**。

其中 A 负责解释变化原因，B 负责决定证据能否进入长期个体记忆，C 负责新建或恢复习惯阶段。三者全部实现并共同进入一篇论文。首轮死亡测试用于发现各子系统需要怎样重构及验证新增算子是否有效，不再用于在 A/B/C 中删选项目范围。

- 当前测试基线：`92 passed`（2026-08-13 本轮核验，含 D0 漂移原因评价契约测试）。

### 1.2 目前尚不能支持创新主张

- 生成器声明了访客、渐变、突变和周期变化类型，但主执行路径仍是一日一次 `PLACE`；
- 没有在同一观察间隙内生成 `pick_up → carry → handoff → place` 隐藏事件链；
- 观察策略是全局固定概率，尚不能表达“任务、路径、过去信念共同决定看见什么”的 MNAR（Missing Not At Random，非随机缺失）；
- 目前人物后验由调用者提供，尚未形成行为者候选推断和反事实归因；
- 分层 Dirichlet 基线会把所有有效证据立即写入共享/人物统计，没有隔离区、独立证据检验、阶段版本或撤销后重建比较；
- evaluator（评价器）当前主要报告观察召回、异常召回、顺带观察上下文覆盖和额外动作成本；没有主人污染率、变化误归因、旧阶段恢复、搜索 regret（遗憾）或个性化放回错误成本；
- 尚未接入 O-STaR、STREAK、HERMES 或合理增强组合基线；
- 尚未证明任何信念改进能转化成两类具身任务效用。

所以当前仓库是**可靠实验基础的开端**，不是已完成的新算法。

### 2.2 已有技术主干上的二代方法创新

下面不是把已有组件排除掉，而是逐一把它们升级成候选新方法。所有名称均为工作名，不预先宣称新颖性成立。

| 已有主干 | 旧方法的关键限制 | 本项目可提出的新机制 | 需要击败的直接对照 |
|---|---|---|---|
| event / scene graph（事件/场景图） | 通常把单个最可能事件写成确定边，难以保留互斥解释、人物责任和后续撤销 | **Counterfactual Hypothesis Event Hypergraph，CHEH（反事实假设事件超图）**：一个观察间隙保留多条互斥事件链超边，每条边绑定人物、实例、时间、观察支持、来源和反事实残差；新证据到来时做重排序、合并或撤销 | 普通时序场景图；top-1 事件解码；独立事件候选图 |
| BOCPD / change-point model（变化点模型） | 只回答“是否变化”，把协变量、观察机制、人物混合和真实习惯变化混为同一种重置 | **Cause-Factored BOCPD，CF-BOCPD（原因因子化在线变化点检测）**：联合维护 run length、变化原因和习惯阶段；不同原因只重置对应参数块 | 标准 BOCPD；多模型 BOCPD；每种信号独立运行 BOCPD |
| Dirichlet / Bayesian count update（贝叶斯计数更新） | 把被看见的数据近似当成无偏、独立证据，软人物权重仍会持续累积污染 | **Observation-Process-Corrected Evidential Update，OPCEU（观察过程校正的证据更新）**：把未见事件作为潜变量，通过显式观察似然计算期望充分统计量，并按证据簇而不是帧更新；与隔离式巩固结合 | 原始计数；可见性负证据；inverse-propensity 加权；soft actor count |
| GNN / Transformer（图网络/变换器） | 容易把来源、观察和推断边混合编码，输出高分但无法说明用了哪条证据，也可能学习人物 ID 捷径 | **Provenance-Constrained Hypothesis Message Passing，PCHMP（来源约束的假设消息传递）**：只允许合法类型边传递；在互斥假设集合内归一化；对人物置换保持等变；同时输出可追溯证据子图 | 普通异构 GNN；无来源约束的 Transformer；打乱人物 ID 消融 |
| continual learning（持续学习） | rehearsal/regularization 主要防遗忘，没有区分“值得学的新阶段”和“错误人物或观察偏差造成的伪变化” | **Responsibility-Gated Reversible Consolidation，RGRC（责任门控的可逆巩固）**：按人物责任、原因后验、证据独立性和行动损失决定隔离、晋升、撤销或重激活 | 普通 replay；Fisher/EWC；滑动窗口；固定阈值隔离 |
| active perception（主动感知） | 多数方法减少状态或变化点不确定性，未必能区分“为何变化”，也未把隐私和打扰纳入同一目标 | **Cause-Information Active Verification，CIAV（变化原因信息主动验证）**：选择最能区分 observation/actor/identity/habit 假设且改善下游效用的微观察或询问 | 随机检查；最大状态熵；最大变化点信息增益；只看任务效用 |
| recurrent regime memory（回归阶段记忆） | 发现变化后往往新建阶段或回放旧数据，缺少“恢复哪个历史阶段”的显式后验 | **Context-Conditioned Regime Reactivation，CCRR（情境条件化阶段重激活）**：在保持、新建、恢复历史阶段和未决之间竞争，并验证恢复是否由观察策略/访客复现造成 | BOCPD + replay；sticky HMM/HDP-HMM；最近历史阶段匹配 |

这些机制全部放进同一个模型并形成一篇统一方法论文，同时保留七个可独立替换的消融单元。逐项消融用于证明每项方法改进的必要性，不能被解释为可以静默删去某个功能。

### 2.3 三个最关键的新算子

#### 算子一：反事实假设事件超图，而不是确定事件边

对于观察间隙 \((t_0,t_1)\)，不立刻写入唯一的 `person-A moved mug to desk`，而是建立互斥假设集合：

\[
\mathcal{H}_{t_0:t_1}=\{h_k=(E_k,A_k,I_k,\tau_k,\omega_k,\mathcal{P}_k)\}_{k=1}^{K},
\qquad \sum_k\omega_k+\omega_{unresolved}=1
\]

其中 \(E_k\) 可以是一条 `pick-up → carry → handoff → place` 事件链，\(A_k\) 是人物责任，\(I_k\) 是实例关联，\(\mathcal{P}_k\) 是来源记录。后续观察不是简单增加一条新边，而是对整个互斥集合执行 posterior revision（后验修订）。

方法贡献不在“用了超图”，而在三个新操作：

1. `branch`：同一观察间隙生成受物理和身份约束的竞争事件链；
2. `revise`：新证据跨时间修改旧事件链的权重与人物责任；
3. `retract/rebuild`：被推翻的事件不会继续污染派生习惯，相关统计可由来源日志重建。

#### 算子二：原因因子化 BOCPD，而不是先检测再分类

维护联合后验：

\[
p(r_t,C_t,Z_t\mid D_{1:t}),
\quad C_t\in\{obs,actor,id,habit,noise\}
\]

关键是定义 cause-specific reset operator（原因特定重置算子）：

- `obs` 只更新/重置观察策略参数 \(\phi^{obs}\)，不清空主人习惯；
- `actor` 只更新人物混合 \(\rho^{actor}\) 与相应人物阶段；
- `id` 触发实例/人物关联重算，并撤销依赖错误关联的派生证据；
- `habit` 才创建、切换或恢复主人习惯阶段 \(\theta^{habit}\)；
- `noise` 不进行长期参数重置。

这不同于“BOCPD 后面接一个分类器”：原因变量直接改变转移核、危险率和哪些参数允许被重置，因此会产生不同的长期记忆状态。

#### 算子三：面向原因辨识和任务效用的主动微验证

当变化原因不可识别时，不必永久输出未决，也不能随意归因。机器人可在预算内选择一个低打扰动作：

\[
a_t^*=\arg\max_a
I(C_t;O_{t+1}\mid D_{1:t},a)
+\lambda\,\mathbb{E}[\Delta U_{task}\mid a]
-C_{motion}(a)-C_{privacy}(a)-C_{interrupt}(a)
\]

它与普通最大熵主动感知的区别是：目标变量是“变化原因”而不只是物体位置，而且同时要求预期任务收益。可选动作包括改变经过路线、查看一个关键容器、确认人物是否在场、在适当时机询问一次，或保持未决。

## 3. 候选路线 A：漂移原因分离的阶段推断

### 3.1 核心改进

现有流水线通常先根据观察更新位置分布，再对这条分布做变化检测。路线 A 不直接检测观测分布是否变化，而是维护多个“变化原因”假设：

\[
C_t \in \{C^{obs}, C^{actor}, C^{id}, C^{habit}, C^{noise}\}
\]

分别表示：

- \(C^{obs}\)：任务、路径、视野或容器访问发生变化；
- \(C^{actor}\)：主人、家人、访客或机器人自身的行为比例变化；
- \(C^{id}\)：物体/人物身份或数据关联发生变化；
- \(C^{habit}\)：目标人物的真实习惯阶段发生变化；
- \(C^{noise}\)：短期噪声或孤立异常。

模型维护：

\[
p(L_t,I_t,A_t,E_t,Z_t,C_t,\Theta_t\mid O_{0:t},M_{0:t},\pi_{obs},U_{0:t})
\]

关键不是变量更多，而是对每一种变化原因计算可比较的 posterior evidence（后验证据），并让它们对长期习惯更新产生不同后果。

### 3.2 可实现机制

可比较三种实现，不提前选定：

| 实现候选 | 机制 | 优点 | 主要风险 |
|---|---|---|---|
| A1：结构化动态贝叶斯模型 | 显式因子化观察、行为者、事件、阶段与原因变量；粒子/变分推断 | 可解释、适合 oracle/符号轨 | 状态空间膨胀，近似推断可能不稳定 |
| A2：多专家原因竞争 | observation/actor/identity/habit 四个专家各自预测，gating posterior（门控后验）竞争解释残差 | 易做消融和在线更新 | 门控器可能只学数据集捷径 |
| A3：神经提议 + 结构化校验 | 神经网络生成高概率事件/原因候选，概率图模型做约束、归一化和来源记录 | 可扩展到真实感知 | 训练复杂，容易把神经分数误当概率 |

### 3.3 反事实原因分数

对原因 \(c\) 定义：

\[
\Delta_c = \log p(O_{t-k:t}\mid \mathcal{M}_{full})
- \log p(O_{t-k:t}\mid do(C_t\neq c),\mathcal{M}_{-c})
\]

直观上，如果冻结观察模型后似然大幅下降，证据更支持观察策略漂移；如果冻结人物混合后下降，证据更支持住户构成变化；只有在这些替代解释都不足时，才把概率质量提升到真实习惯阶段变化。

这里的 `do` 暂时是研究目标，不应在没有干预数据时冒充已识别的因果量。首轮可先比较 constrained counterfactual score（受约束反事实分数），随后用随机微观察或固定日志中的自然实验验证。

### 3.4 必须正面解决的可识别性问题

仅凭被动观察，以下两个世界可能 observationally equivalent（观测等价）：

1. 主人没有改变习惯，但机器人最近不再进入书房；
2. 机器人观察策略不变，但主人真的不再把物体放进书房。

因此路线 A 不能只依赖更大的网络。至少需要一种识别来源：

- 已记录且具有重叠支持的 observation propensity（观察倾向概率）；
- 少量随机化 micro-verification（微验证）；
- 外生任务路径变化形成的 instrument-like variation（类工具变量变化）；
- 特定人物询问或容器检查；
- 将不可识别情况显式输出为 `unresolved_shift`，而不是强行归因。

如果暂时没有这些条件，系统必须输出 `unresolved_shift`，路线 A 的论文措辞只能写成“漂移解释候选排序”，不能宣称已经因果分离；但仍需继续研究日志倾向、随机微验证或其他识别来源，不能删除这一子系统。

## 4. 候选路线 B：后验门控的隔离式巩固

### 4.1 核心改进

当前软人物权重仍会立即污染统计。例如，某次事件有 0.55 主人、0.35 家人、0.10 未知的后验，重复出现十次后，主人模型会累积 5.5 个证据单位，即使十次其实来自同一个错误关联片段。

路线 B 把“当前状态相信什么”和“允许什么进入长期习惯”分开：

```text
观测/推断证据
→ 当前状态与事件候选立即更新
→ quarantine buffer（隔离缓冲区）
→ 独立性、人物后验、观察支持和阶段一致性检验
→ shared / person / regime memory 分级巩固
→ 可撤销来源记录
```

### 4.2 建议的巩固分数

对证据簇 \(g\) 而不是单帧 \(t\) 计算：

\[
s_g = q_{identity}q_{actor}q_{placement}q_{observation}
q_{independence}q_{regime}
\]

`authorization` 是巩固前的 hard gate（硬门），不是软乘数；`privacy` 是动作/巩固损失中的显式成本。未授权证据直接 reject，不能由其他高分补偿。

并比较三种动作的期望损失：

\[
a_g \in \{promote, keep\_quarantined, reject\}
\]

\[
a_g^*=\arg\min_a\mathbb{E}
[C_{owner\_contamination}+C_{missed\_adaptation}+C_{delay}+C_{privacy}]
\]

这比固定阈值更强，因为不同对象和任务对“误写给主人”与“适应太慢”的代价不同。

### 4.3 可证伪贡献

路线 B 只有在以下条件同时成立时才算方法改进：

- 相比 soft actor update（软人物更新）显著降低主人污染；
- 相比 hard reject（硬拒绝）保留足够适应速度；
- 对重复帧、相似实例、访客和机器人自身操作分别有效；
- 收益不能仅由更高人物识别准确率解释；
- 在搜索或个性化放回中降低真实错误成本。

---

## 5. 候选路线 C：可回归的历史阶段库

### 5.1 核心改进

普通遗忘和 BOCPD 通常关注“何时切到新阶段”。路线 C 维护：

```text
current regime（当前阶段）
candidate regime（候选阶段）
historical regime library（历史阶段库）
```

新证据到来时比较：

\[
\{stay, create, reactivate(z_j), unresolved\}
\]

而不把所有变化都创建为全新任务。历史阶段包含人物、情境、位置/事件参数、证据来源、有效时间和过去效用。

### 5.2 为什么不能单独作为主要创新

recurrent concept drift（回归性概念漂移）、sticky HDP-HMM 和记忆库复用已有大量通用研究。路线 C 的领域价值明确，但只有与 A 或 B 联合并展示以下交互收益时，才可能形成更强贡献：

- 观察策略改变时不错误重激活旧习惯；
- 访客再次出现时重激活访客阶段而不污染主人阶段；
- 主人恢复旧作息时，比滑动窗口和普通 rehearsal 更快恢复具身效用。

## 6. 三个统一子系统的职责与重构边界

| 子系统 | 在统一论文中的方法主张 | 新颖性潜力 | 最便宜的首轮诊断 | 主要代价 |
|---|---|---:|---|---|
| A 漂移原因分离 | 区分观察、人物、身份和真实习惯变化 | 高 | 三组观测等价/干预场景中能否正确归因 | 可识别性与推断复杂度最高 |
| B 隔离式巩固 | 降低多人和重复证据污染，同时不过度保守 | 中高 | 与软更新、硬拒绝在污染—适应 Pareto 前沿比较 | 需要可靠证据簇和代价定义 |
| C 历史阶段库 | 旧习惯/访客阶段可快速、正确复用 | 中 | recurrence 场景中是否胜过 BOCPD + rehearsal | 单独看容易被认为是已有方法迁移 |
| A+B 耦合 | 先解释变化来源，再决定是否写入个体长期记忆 | 高 | 是否胜过独立 A、独立 B 和增强组合基线 | 工程和统计风险都高 |
| B+C 耦合 | 抗污染巩固加阶段复用 | 中高 | 是否在多人复发/习惯回归同时提升效用 | 必须同时接受 A 的观察偏差校正 |

A、B、C 已确定全部实现。首轮基准同时提供三者所需的真值和指标；结果决定的是每个子系统采用哪一种算法实现、哪些耦合结构需要重做，而不是决定删除哪个子系统。

## 7. 最强匹配基线与死亡测试

### 7.1 必须先实现的组合基线 B\*

```text
O-STaR-style Dirichlet location belief
+ visibility-aware negative evidence
+ soft / oracle actor labels
+ BOCPD or tuned sliding-window regime detector
+ STREAK-style rehearsal/regularization alternative
+ typed event/history store
+ independently tuned search/put-back decision policy
```

还应包含：

- `B0`：frequency / recency / Markov；
- `B1`：O-STaR 忠实位置与搜索逻辑；
- `B2`：B1 + learned actor posterior；
- `B3`：B2 + BOCPD；
- `B4`：B2 + STREAK-style continual learner；
- `B5`：B3 + 简单 quarantine threshold（隔离阈值）；
- `B6`：HERMES-style temporal scene graph retrieval，用于查询/指令任务，而不是冒充概率习惯学习基线；
- `B*`：上述合理增强后的最强组合。

每条基线必须独立调参；动作阈值、询问阈值和搜索停止阈值不能沿用对新方法有利的设置。

### 7.2 Death Test D0：观测等价性

建立三个只改变一个真实原因的成对场景：

| 场景 | 真实习惯 | 观察策略 | 人物构成 | 正确输出 |
|---|---|---|---|---|
| D0-O | 不变 | 改变 | 不变 | observation shift，不更新主人阶段 |
| D0-A | 不变 | 不变 | 改变 | actor-mixture shift，不污染主人 |
| D0-H | 改变 | 不变 | 不变 | habit shift，及时适应 |

若当前方法不能在 oracle 人物/可见性轨上区分三者，停止继续堆叠该版本的复杂度，重新设计 A 的识别信号、状态因子或主动微验证机制；A 所代表的变化原因分离能力仍保留在统一系统中。

**2026-08-13 实现状态：** `d0-shift-scenarios@0.2` 已生成并版本化 D0-O、D0-A、D0-H；五类因子指纹保证每对只改变一个真值因子。无人物证据轨中，D0-A 与 D0-H 的 shifted visible log（变化后可见日志）逐记录相同；`LoggedPolicyThenLocationBaseline` 得到 accuracy `0.6667`、macro-F1 `0.5556`、`actor-mixture-to-owner leakage=1.0`。受控噪声和 oracle 人物后验轨把 accuracy 提到 `1.0`、泄漏降为 `0.0`，说明人物信息足以解除首版观测等价，但普通人物后验接入属于诊断基线，不是方法创新。CHEH `branch/revise/retract/rebuild` 首纵切已经实现，下一步必须在隐藏交接、多候选和身份噪声中超过 top-1/独立候选事件图，而不是给位置变化模型简单扩容。

### 7.3 Death Test D1：简单组合是否已经足够

在同一日志、同一预算和独立调参下比较完整方法与 B\*。若 B\* 在主人污染、适应延迟和行动效用上与当前新方法统计等价，则当前联合结构主张未获支持，必须重新设计耦合或新算子；不能以此绕开已经覆盖的功能，也不能把普通拼装改写成创新。

### 7.4 Death Test D2：效用而非校准

至少固定两类下游任务：

1. personalized object search（个性化物体搜索）；
2. personalized put-back / delivery（个性化放回或递送）。

主指标包括：

- 任务成功率；
- 搜索路径/时间/容器检查数；
- 错误拿取、错误放回、错误递送；
- 询问、观察、隐私和主任务干扰成本；
- 相对 oracle policy 的 true-environment regret（真实环境遗憾）。

ECE、Brier、NLL、人物后验准确率和变化点延迟只作为诊断指标。

### 7.5 Death Test D3：外部有效性

在真实感知回放或小规模家庭式环境中固定日志重放。若合成 oracle 轨增益在加入漏检、身份切换、遮挡和延迟后消失，则不能继续宣称面向真实机器人。

## 8. 基准最小因子矩阵

首轮不是做大而全数据集，而是覆盖可识别性所需的最小因子组合：

| 因子 | 水平 |
|---|---|
| observation policy（观察策略） | 固定均匀；任务驱动偏置；信念驱动自选择；带少量随机微验证 |
| actor composition（人物构成） | 单主人；主人+家人；主人+访客；未知行为者 |
| event visibility（事件可见性） | 全见；只见前后；见局部动作；完全隐藏 |
| regime change（阶段变化） | 无变化；孤立异常；渐变；突变；旧阶段回归 |
| identity noise（身份噪声） | 无；人物混淆；相似物体混淆；连续 ID switch |
| downstream task（下游任务） | 搜索；放回/递送；可选查询 |

其中 D0 的三组成对场景必须先完成，之后才扩展全因子组合。

## 9. 新增核心指标

### 9.1 漂移原因

- shift-cause accuracy / macro-F1（漂移原因准确率/宏 F1）；
- unresolved-shift calibration（未决漂移校准）；
- false owner-habit change rate（主人习惯误变更率）；
- observation-to-habit leakage（观察策略到习惯的泄漏）；
- actor-mixture-to-owner leakage（人物构成到主人模型的泄漏）。

### 9.2 巩固与阶段

- owner contamination rate（主人污染率）；
- evidence promotion precision / delay（证据晋升精度/延迟）；
- false consolidation cost（错误巩固成本）；
- true change adaptation delay（真实变化适应延迟）；
- historical-regime reactivation precision / delay（历史阶段重激活精度/延迟）。

### 9.3 决策

- search success、path length、time、container checks；
- put-back / delivery success 与 wrong-person / wrong-place cost；
- question / verification / privacy / disturbance cost；
- utility 与 true-environment regret；
- worst-group utility（低覆盖物体、访客高比例、身份噪声群体）。

## 10. 实现顺序：先造证伪条件，再造新模型

### I0：冻结可比较协议

- 版本化场景、随机种子、预算和数据划分；
- 固定 oracle、controlled observation 和 closed-loop 三条轨；
- 明确两个下游任务的效用函数；
- 为每条基线单独保存调参空间和最优配置。

### I1：扩展 M30 真值事件生成

- 从每日单个 `PLACE` 扩展到 pick-up、carry、handoff、place；
- 同一间隙允许多人物候选和未知行为者；
- 生成 D0-O、D0-A、D0-H 成对场景；**首版已完成**；
- 生成异常、渐变、突变和旧阶段回归。

### I2：扩展 M29 观察产生过程

- 观察概率依赖任务、路径、视野、遮挡、容器和过去信念；
- 显式记录 logging policy（记录策略）和 propensity（倾向概率）；
- 加入身份混淆、观测延迟和重复证据簇；
- 支持少量随机 micro-verification 干预。

### I3：扩展 M32 指标与两个效用任务

- 实现漂移原因、主人污染、巩固和阶段指标；
- 实现搜索和放回/递送的 budget-matched policy evaluation（预算匹配策略评价）；
- 输出逐家庭、人物、物体、阶段和随机种子的失败记录。

### I4：实现 B0–B\* 强基线

- 先完成 O-STaR-style + actor + BOCPD 的可解释组合；
- 再接 STREAK-style alternative 和 HERMES-style query baseline；
- 所有基线独立调参并固定选择规则。

### I5：实现并迭代全部统一方法子系统

- A、B、C 及 OPCEU、CHEH、PCHMP、CF-BOCPD、RGRC、CCRR、CIAV 全部进入最终系统；
- 实现仍按依赖顺序推进：先识别条件和 D0，再进入 A 的复杂推断；先有证据簇和人物责任，再完成 B；先有回归场景和 B\*，再完成 C；
- matched death test（匹配死亡测试）决定的是具体算子是否需要重构、耦合是否真实有效和论文主张能否成立，不决定删减最终能力；
- 已有项目覆盖任何功能时，必须记录已有覆盖提醒，随后在同一路线上继续提出并验证新方法。

## 11. 创新主张成立条件

只有同时满足以下条件，才可以把改进写成论文主方法：

1. 与 O-STaR、STREAK、HERMES、事件图和通用变化点的结构差异可明确定位；
2. 在 D0 中能区分至少观察策略变化、人物构成变化和真实习惯变化；
3. 在同信息、同训练、同计算和同动作预算下超过 B\*；
4. A/B/C 中至少两个困难存在不可由独立模块相加解释的交互收益；
5. 改进转化为搜索与放回/递送两类任务的效用或 regret 收益；
6. 真实感知回放中保留主要结论；
7. 不可识别情况能够拒绝归因并报告 `unresolved_shift`；
8. 失败种子、低覆盖物体和访客高比例群体完整报告。

以下任一情况触发当前局部方法停止扩张并重构：

- B\* 达到同等效用；
- 只改善校准或离线预测；
- 原因分离依赖真值人物/真值可见性，替换为真实输入后失效；
- 隔离机制通过拒绝大部分证据换取低污染；
- 复杂模型无法稳定重放或无法解释来源；
- 收益来自更多观察、询问、标注或算力。

这里的“停止”只针对当前具体算法或未经支持的论文措辞，不针对项目框中的功能。项目仍需寻找新的表示、更新算子、目标或识别机制，直至形成能够与已有方法直接比较的实质改进。
