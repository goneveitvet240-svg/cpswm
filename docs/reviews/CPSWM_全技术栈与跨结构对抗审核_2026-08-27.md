# CPSWM 全技术栈与跨结构对抗审核

日期：2026-08-27  
范围：结构一、结构二、结构三、OAM-PHM，以及四者共用的证据、权限、回放、LLM、统计与评测底座  
结论状态：`engineering_hardened_research_claims_blocked`

## 一句话结论

仓库已经不是只有概念图的空架子：四条路线都有可执行契约、样例回放、局部方法和对抗测试；但它也还不是已经验证成功的完整系统。当前最强的部分是“防止把假证据和开发结果说成论文结论”的工程边界，最弱的部分仍是真实感知、真实长期家庭流、外部完整系统忠实复现，以及由真实行动效用支持的方法证据。

本轮发现并修复了六类可直接利用的漏洞；另有六类必须在真实数据或正式评测接入时继续保持 `BLOCK`，不能用布尔字段、哈希字符串或开发 fixture 代替独立证据。

## 2. 四条研究路线与共用底座

### 2.1 共用底座

四条路线共用以下边界，而不是四套互不相干的代码：

1. identity/time（身份与时间）：家庭、人物、物体、session、trace、valid time 和 recorded time；
2. evidence contract（证据契约）：观察机会、选择概率、遮挡、失败原因、unknown、来源成熟度和证据簇；
3. persistence/replay（持久化与回放）：内容哈希、幂等请求、事件账本、修订和完整重跑；
4. authority/privacy（权限与隐私）：谁能说、谁能改、谁能撤销、谁能执行；
5. LLM seam（LLM 接缝）：proposal、likelihood、referenced posterior 三种权限及模型 provenance；
6. evaluation（评测）：sealed split、独立调参、行动指标、cluster bootstrap、强对手和论文门。

### 2.2 结构一：长期家庭世界模型

它解决的是“机器人长期住在一个家里，怎样把零散观察整理成不会乱写、不会把猜测当事实、还能逐渐学会每个人习惯的记忆”。

当前模块包括场景图、事件时间线、证据来源、信念状态、习惯账本、隐藏事件账本、物体生命周期、查询编译，以及四层放置权限。逐方法门当前登记：

- leave-one-out layered habit（留一分层习惯）对 additive hierarchical Dirichlet 和 nested back-off；
- five-axis mobility（五轴移动性）对二元稳定性和三档刚性分类；
- four-layer placement semantics（四层放置语义）对 collapsed memory 和不看权限的规则解析器。

当前诚实状态：9 条路线有纵向切片，3 条仍是 contract-only；没有真实长期家庭流，也没有一个原生吃完整 posterior 的统一正式方法臂。

### 2.3 结构二：让长期学习在漏看、多人和变化中不被污染

它解决的是“机器人看不全、家里有多人、东西会被偷偷移动、人的习惯也会变；学错之后还要能撤回，而不是越学越偏”。

主要方法和直接对手：

- OPCEU 对 doubly robust correction 和 learned object-state estimator；
- ORRER 对 matched AMG 和 fixed-lag smoother；
- PCHMP 对独立调参 HGT、R-GCN；
- CF-BOCPD 对 BOCPDMS、switching HMM；
- RGRC 对 full-history rerun、Fisher/replay consolidation；
- CCRR 对 sticky HDP-HSMM、factorized sticky finite HMM；
- CIAV 对 cost-aware value of information、max-entropy verification；
- Combination A 对 enhanced O-STaR、ordinary HGT+HMM+full rerun。

当前诚实状态：D0 回放和局部链已跑通，artifact verifier（产物核验器）已经存在；D1/D2 真实数据、外部强基线独立重调参、污染—恢复 Pareto 和跨模块行动效用仍未完成。

### 2.4 结构三：听懂模糊话并真正找到、确认、修正记忆

它解决的是“用户说‘我常用的那个杯子，大概在昨天坐过的地方’，机器人怎样保留多种理解、处理不知道的物体、选择去哪里看，找到或找不到以后再改记忆”。

主要方法和直接对手：

- multi-parse posterior 对 top-1 LLM parse 和 self-consistency vote；
- probabilistic dynamic instance graph 对 learned object-state estimator 和 hard association；
- revision-aware evidence graph 对 full rerun 和 overwrite scene graph；
- CO-CIP 对 conformal information pursuit 和 cost-aware entropy search；
- HCS 对 exponential decay 和 flexible hazard；
- coverage-derived unknown mass 对 conformal Good-Turing 和 learned unknown mass。

当前诚实状态：oracle、controlled noise、FindingDory metadata/layered ingress、prediction cache 和 feedback replay 可执行；真实视频 prediction、VIO/VLM/触觉、正式规划器和机器人硬件没有完成。

### 2.5 OAM-PHM：把整条闭环放到一个统一问题里

它解决的是“在观察不完整、习惯会变、记忆可能被污染的条件下，系统能否同时给出当前信念和长期习惯分布，并用这些信念减少实际搜索和错误行动”。

当前有 WP0 内部基线、双头评分、身份双射、独立调参协议、查询网格和资源预算；完整系统门要求对 enhanced O-STaR、DynaMem、STaR。O-STaR/STREAK 的方程级或组件级脚手架不等于外部忠实复现。当前正式状态仍是 `route_frozen_parameters_pending` / `comparison BLOCK`。

## 4. 仍存在、但不应偷偷替用户选路线的漏洞与阻断项

### R1 高风险：正式证据仍使用对称 HMAC 信任根

当前 `AttestationAuthority` 能挡住“候选算法自己改记录”，但 verifier 持有同一个 HMAC secret，理论上也能签名。它不是对恶意评测管理员的密码学隔离。正式论文运行应把签名放到独立进程/机器，或换成 asymmetric signature（非对称签名）和只读公钥验证。此项不影响开发回归，但影响正式证据等级。

### R2 高风险：OAM-PHM 若直接相信协议对象里的布尔值，仍可自证完成

`immutable`、`evaluator_truth_fields_present`、`generated_before_sealed_test_access`、STREAK `accepted` 和 budget usage 目前是契约字段，不是独立证明。当前正式门仍 BLOCK，所以尚未造成假结论；接正式 replay 时必须由数据保管方、sealed-test authority 和资源计量器分别签发回执，不能让候选 runner 自己填写。

### R3 高风险：结构三 prediction cache 没有从原始帧重算输入哈希

缓存能挡跨 split、跨 episode、模型版本漂移、记录篡改和候选越界，但 `input_content_hash` 仍是 producer 声明。真实数据接入时必须有 frame-level manifest，把原始 frame bytes/URI、解码规则、裁剪和预处理配置绑定到 hash；否则模型可以对另一张图预测后声称来自当前帧。

### R4 中高风险：四层权限的 trusted issuer 集合仍由调用者传入

当前算法能拒绝集合之外的伪造签发者，但“谁进入 trusted set”仍是上游责任。正式接身份和 LLM 时需要 household trust-store snapshot（家庭信任库快照）、版本、变更回执和撤销日志；不能让一次决策调用临时指定攻击者为可信签发人。这是身份基础设施门，不应靠改变四层语义偷偷解决。

### R5 中风险：sealed TEST 仍与候选代码处于同一 Python 进程

公开 API 已禁止提前读取，但恶意 Python 代码仍可能用对象反射读取 `_cases`。正式一次性测试应由外部数据保管进程在 ATG-2 后启动独立 evaluator，候选只接收查询或最终分数。当前实现是工程门，不是强机密隔离。

### R6 中风险：`check.sh` 对 uv 用户缓存有环境耦合

在受限环境中，脚本因无法写 `~/.cache/uv` 而让 pytest、mypy、Ruff 同时假失败。仓库 `.venv` 直接执行不受影响。应在后续执行约定中选择：使用 workspace-local `UV_CACHE_DIR`，或让脚本优先使用现有 `.venv`。这只是工具链选择，本轮未擅自修改。

## 5. 现在能说和不能说的话

现在可以说：

- 四条路线已经形成共享契约和多条可执行纵向切片；
- 本轮六个具体绕行漏洞已有负向测试；
- 开发证据不会再仅靠自填字段打开通用论文门；
- 当前系统对“没做完”能较诚实地保持 BLOCK。

现在不能说：

- 结构一、二、三或 OAM-PHM 已经在真实家庭数据上优于强基线；
- O-STaR、DynaMem、STaR/STREAK 已完成忠实复现和独立重调参；
- FindingDory metadata adapter 等于视频感知闭环；
- 结构二七条路线或结构三六条路线都已经形成论文创新；
- 开发 fixture 上的零违规或局部优势可以外推到真实用户。

## 7. 接真实数据和 LLM 前的硬门

以下门全部通过以前，`paper_claim_allowed` 应继续为 false：

1. 原始数据保管方签名的 dataset/frame manifest；
2. 独立 evaluator 持有 sealed TEST，候选进程不能读取测试真值；
3. LLM/VLM prediction cache 与原始输入、prompt、模型版本、预处理和费用绑定；
4. household trust store、身份认证和权限撤销链可回放；
5. 每个方法的最强直接对手完成忠实实现和独立调参；
6. 以 household/episode/object-family 为簇的置信区间、功效和失败结果完整保留；
7. 至少一个真实或高保真外部闭环证明机制指标能够转成行动效用，而不是只改善 NLL/ECE；
8. OAM-PHM 的完整系统比较不能由组件存在、契约布尔值或方程级脚手架代替。

本审核没有删除任何结构、方法或待选路线，也没有替用户选择 HCS、CO-CIP、融合公式、FindingDory 深层 episode 或最终权限产品政策。
