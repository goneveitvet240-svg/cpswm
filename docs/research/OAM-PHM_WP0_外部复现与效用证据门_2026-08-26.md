2. 建立 machine-checkable fidelity manifest（机器可检查忠实度清单）。任何 mandatory
   requirement（必要要求）未验证时，manifest 不能标为 `reproduction_complete`。
3. 实现 O-STaR equation-level reference core（公式级参考核心）：
   - LLM prior 在几何可行候选上的伪计数初始化；
   - positive hit（正命中）更新；
   - negative miss redistribution（负观测重分配）；
   - Stay+Leak（停留加泄漏）扩散；
   - 显式外部搜索成本上的 probability/cost 排序。
4. 实现 STREAK continual-learning reference core（持续学习参考核心）：
   - Fisher-weighted consolidation loss（Fisher 加权巩固损失）；
   - 按任务年龄衰减的 rehearsal weight（回放权重）；
   - Mean Feature Criteria（均值特征准则）确定性样本选择；
   - 论文明确给出的 `lambda`、`beta`、epoch 参数网格生成器；预测时距要求调用方显式声明，
     不替论文中有歧义的区间表述做选择。
5. 建立 formal competition protocol（正式比赛协议）：
   - 外部 arm（比赛臂）必须携带完整 manifest 对象，不能只填一个自声明 hash；
   - validation/test 内容必须不同；
   - test 在调参完成前访问即使协议失效；
   - 感知、地图、导航、LLM、行动预算和计算预算由比赛协议统一绑定；
   - 每个 arm 必须分别携带完全一致的 `ArmExecutionBinding`（实验臂执行绑定），仅在
     protocol 顶层声明一组 hash 不再足够；
   - 至少包含一个完整 OAM-PHM arm 和一个完整外部强基线 arm。
6. 建立 opportunistic-observation paired intervention（顺路观察配对干预）：
   - 同一任务与随机性下比较 observation disabled/enabled；
   - enabled 必须实际产生更多顺路观察；
   - 只把之后的 future-task utility（未来任务效用）作为收益；
   - 分别报告未来效用变化和当前主任务成本变化；
   - 使用 episode、household 或 object-family cluster bootstrap（簇自助法）。
7. 建立 anti-contamination matched ablation（抗污染匹配消融）：
   - full 与 ablation 除目标模块外必须绑定同一组件 hash；
   - 分别报告 owner contamination（主人污染）、recovery latency（恢复延迟）、
     action utility（行动效用）和 compute overhead（计算开销）；
   - 提供 episode/household cluster bootstrap；
   - 未预先指定价值判据时，状态固定为 `awaiting_user_criterion`，不得自动宣布“值得”。
8. 将 D-OAM-1 至 D-OAM-5 登记为 machine-readable blocking decisions（机器可读阻塞决策）：
   - 每项绑定被阻塞的交付物、候选 option 和选择后果；
   - 后续新增 D-OAM-6/D-OAM-7，并记录用户选中的 option；路线选定不等于证据完成。

`ArmExecutionBinding` 证明的是各 arm 接受同一输入和预算**分配规范**；实际消耗相等仍需正式
runner 产生 compute receipt（计算收据），当前不能据此声称 matched compute 已实测完成。

## 2. 当前忠实复现差距

### 2.1 O-STaR

已完成的是公式核心，不是端到端 O-STaR。以下必要部分仍未关闭：

- LLM ranking → probability 的 provider、prompt 和 cache 映射；
- 真实 3D object-compartment feasibility（物体—容器几何可行性）；
- relaxed transition inference（稀疏时间转移推断）；
- navigation/container action cost（导航/开容器动作成本）与项目接口的映射；
- opportunistic multi-target perception（机会式多目标感知）端到端链；
- HOMER+ 与物理搜索结果复核。

路线已经冻结，但相关 artifacts 尚未生成。因此当前 manifest 为 `equation_core_only`，不能进入正式比赛。

### 2.2 STREAK

论文明确的不可删减组成已经进入 fidelity checklist：

- spatio-temporal streaming GNN（时空流式图神经网络）；
- node classification、location-edge classification、context embedding 三项损失；
- Fisher consolidation（Fisher 巩固）；
- Mean Feature Criteria rehearsal buffer（均值特征准则回放缓冲区）；
- `lambda ∈ {80,100,200}`、`beta ∈ {5,10,15}`、epoch `{25,50,100}`、
  batch size 1、Adam `1e-3` 与 prediction horizon（预测时距）搜索；
- HOMER 五家庭顺序训练、50 天训练/10 天测试的结果复核。

Fisher、任务年龄权重与 Mean Feature Criteria 已有公式级 reference core，但底层 GTM 网络和
项目输入映射尚无可执行实现。因此当前 manifest 为 `equation_core_only`，不能进入正式比赛。

## 3. 2026-08-27 已冻结的技术路线

用户已经完成 D-OAM-1 至 D-OAM-7 的路线选择。机器可读入口是
`current_selected_oam_protocol()`；状态是 `route_frozen_parameters_pending`，表示路线不再阻塞，
但数据、阈值、容器和预算数值仍未冻结，不能升级任何效果声明。

| 决策 | 已选路线 | 机器门禁 |
|---|---|---|
| D-OAM-1 | `recorded-3d-replay` | replay 必须不可变、内容寻址且不暴露 evaluator truth |
| D-OAM-2 | `frozen-response-table` | 原始响应、prompt、候选词表、概率转换和 cache key 必须在 sealed test 前冻结 |
| D-OAM-3 | `component-factored-reproduction` | static GTM → sequential lower bound → joint upper bound → Fisher-only → rehearsal-only → full STREAK；禁止越级验收 |
| D-OAM-4 | `governed-main+learned-sensitivity` | governed arm 是正式 full method；learned arm 只能作为声明差异的 sensitivity arm |
| D-OAM-5 | `non-inferiority-plus-superiority` | 污染主指标要求 superiority；恢复和行动效用要求 non-inferiority；预算向量必须合规 |
| D-OAM-6 | `local-process-dev+container-formal` | 开发按 arm/seed/split 独立子进程；正式运行要求 OCI digest、只读 rootfs、硬超时和硬件/网络绑定 |
| D-OAM-7 | `budget-vector` | tuning、online inference、embodied action 的所有维度分别比较，禁止标量化掩盖超限 |
