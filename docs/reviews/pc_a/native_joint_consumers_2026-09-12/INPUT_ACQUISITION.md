用户确认目前没有全轴提议模型工件及连续测量/噪声模型。本文件是待实现路线，不是数据已采集或模型已训练的回执。未选择新的科学路线，未授权付费算力或采购硬件。

## 1. 全轴模型不是外部现成权重的同义词

沿已有 `structure_two_neural_proposer_architecture_resolution_v0_1.json` 的三候选选择协议执行：类型因子图 Transformer、slot-conditioned Perceiver、自回归类型图策略。不要把 Architecture A 装配选择误当作已选网络，也不要用恢复的原因/阶段 MLP 冒充覆盖 H/R/I/C/Z 的模型。

先审核现有 D0 训练专用生成器/数据：所有轴、六种操作、候选约束、负观测、未知、多人和阶段变化是否有合法覆盖。缺的序列须生成并记录，而不是宣称旧数据已满足全轴训练。训练真值可以监督训练；确认集真值不可输入推理、调参或候选排序。三个候选使用相同可见输入、预算和数据划分，按既定验证指标选择，保留工件、源码摘要、完整条件 log-q 和选择回执。

下一步可不依赖用户提供权重开展：训练样本覆盖盘点、合法可见特征导出器、训练/验证/确认隔离检查和三候选接口契约。内部网络参数化及计算预算仍需明确，不偷偷选择或启动付费任务。

## 2. 原始连续观测在哪里

- ProcTHOR 官方入口：https://procthor.allenai.org/ ，含入门 Colab、房屋生成框架和 ProcTHOR-10K 数据集入口。
- AI2-THOR 观测接口：https://ai2thor.allenai.org/ithor/documentation/environment-state/ ，`controller.step` 返回执行后的事件，包含自视角 RGB 和可选深度。
- 初始化：https://ai2thor.allenai.org/ithor/documentation/initialization/ ，启用 `renderDepthImage`；固定软件版本、相机参数、坐标系与单位。当前在线深度文档写米，不能混用旧版本单位。

房屋不是完整长期多人任务数据。我们需要实现事件调度、遮挡/可见性、真实动作调用、执行成败记录、延迟送达队列、公开观察日志与独立真值日志。场景划分与预算必须匹配比较方法。

仿真器真实交互可以作为仿真证据，但不等于真实机器人外部有效性。不得手写动作成功、注入正确后验或让方法读取完整世界 metadata/实例真值以冒充视觉推理。已有允许输入合同若授权某种元数据，必须显式标识并同等提供给基线。

## 3. Λ/ξ 不从数据集直接下载

需要先定义连续状态 theta 的物理意义，再把观测转成 z、H 和经标定的 R。以线性高斯模型为例，增量是 H^T R^-1 H 与 H^T R^-1 z；本批组件支持这种明确输入，并未把它指定为默认物理模型。三维位置仅是候选例子，不是新增冻结决定。

R 应由校准数据中的测量残差、位姿与感知误差建模取得，不用常数把信息块填成非零。理想仿真深度不自动代表硬件噪声；仿真噪声实验与真实传感器标定分开。校准集独立于最终确认集。

## 4. 完整连续历史的后续验收

必须从真实允许输入开始：默认候选生成/完整 log-q → 非空联合粒子 → 每粒子三个解析块 → 经唯一账本的合法长期贡献 → 完整联合后验的 CIAV/任务决策 → 执行 → 反馈 → 正确修订。上述过程在同一个运行身份与连续历史内完成，并含负观测、未知、阶段变化、迟到反证。记录每条七算子连接的输入、输出、实际消费者、后果及中和对照。

本批只交付解析计算和联合消费者，不覆盖默认生产者、观测校准、长期入库授权或执行器。电脑 B 仍拥有五项边界修复；在其交付、A 审查、整合和 B 复核前，不跨写其两个核心文件。
