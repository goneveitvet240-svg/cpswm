# 结构二 v0.2 联合复苏：两轮对抗审核

日期：2026-08-28  
对象：`structure-two-structured-rejuvenation-gate@0.2`

## 最终裁决

两轮专项攻击与修复后回归通过。代码层可以确认：候选核不读取注册真值、`K=24` 不能被替换、三臂状态评分采用同一计数边界、artifact 指标和来源声明不能仅靠重算 content hash 绕过确定性验证。

科研裁决不是“完整通过”。本轮仍只属于 same-family development evidence（同场景族开发证据）：

- 6 个 posterior/support/cost 条件提供局部判别证据；
- 1 个 action regret 条件机械为真但无主要判别力；
- 不允许据此声称行动收益、AMG 优越性、外部有效性或神经提议器有效；
- 下一行动级门必须使用运行前封存的新场景族或新种子。

七个算子和完整结构二范围均保留；审核没有授权删除任何失败或尚未验证的算子。

## 第一轮：方法、计量和证据链攻击

### R1-1 高：计算量计数边界不一致

单字段与联合粒子方法原先漏计最终 `K=24` 个 receipt weight（回执权重）评估，而完整重跑计入了最后 24 个归一化评分。这使效率比率偏乐观。

修复：v0.2 对单字段臂补计 24，对联合臂在源码计数中加入 `len(selected)`。修复后：

- 单字段：`502.625 → 526.625`；
- 联合复苏：`509.9375 → 533.9375`；
- 联合／完整重跑：`68.54% → 71.77%`，仍低于冻结的 `90%` 门。

此外，该指标被降格为 analytic state-score evaluations（解析状态评分次数）；它不含候选生成、Pydantic 契约验证或实际运行时，不能冒充 wall-clock/FLOPs。

### R1-2 高：行动指标对主要修复轴失明

有限世界的 action location（行动位置）只由 `regime` 决定。即使 `mechanism`、`actor_path`、`identity` 和 `cause` 全部改变，只要阶段相同，行动完全不变。因此 action regret 全零不能证明联合复苏带来行动收益。

修复：artifact 与结果报告新增明确的 non-discriminative（无判别力）状态；最终裁决不再把两个行动条件计为有效行动证据。下一门要求行动读出消费任务相关的 actor/identity/cause/regime。

### R1-3 高：artifact 只有自报哈希，没有重算验证器

旧测试只检查 `content_sha256` 长度为 64。攻击者可以篡改指标，再重算 content hash，仍通过该测试。

修复：新增 `verify_structured_rejuvenation_report`，它先检查 content hash，再根据当前冻结源码与预算确定性重算完整报告并要求逐字段一致。新增两类攻击测试：

- 篡改 truth support 后重算 content hash：拒绝；
- 篡改 provenance 后重算 content hash：拒绝。

runner 新增 `--verify-only`，正式 artifact 已通过重算验证。

### R1-4 中：预注册措辞超过可证明范围

协议在本次会话的首次正式运行前写入，但仓库没有独立时间戳机构或公开注册回执。仅凭文件哈希不能向外部证明时间顺序。

修复：artifact 标记 `repository_local_protocol_written_before_recorded_run; no_independent_timestamp_authority`；结果改称“仓库内运行前冻结”，不作为 external preregistration（外部预注册）主张。

### R1-5 高：同一场景族适应性开发污染

联合核是在读取 v0.1 的 `0.50` 压力支持率和具体失败结构后设计，又在同一 16 格场景族上验证，存在 adaptive overfitting（适应性过拟合）。

修复：证据等级明确降为 development evidence；下一比较必须先冻结 fresh scenario families / sealed seeds，不能只复用这 16 格给出确认性主张。

### R1-6 通过：候选生成未读取 truth

攻击测试把同一场景的 `truth` 全部替换，同时保持可见 frames 不变；联合候选池、parent 映射和 family 标签逐项不变。当前未发现直接 truth leakage（真值泄漏）。

## 第二轮：修复绕过与协议替换攻击

### R2-1 高：粒子预算可替换但协议 ID 不变

第一轮修复后继续攻击 runner，发现 `--particle-budget` 原本允许产生 `K≠24` 的 artifact，却仍标记同一 v0.2 协议。这可绕过冻结比较。

修复：协议运行函数现在强制 `K=24`；12、16、23、25、48 以及边界非法值全部失败关闭。验证器遇到替换预算也无法生成匹配重算结果。

### R2-2 通过：指标篡改后重签 content hash

攻击者将联合 truth support 改为 `1.0` 并计算新的合法 content hash。验证器因确定性重算不一致而拒绝。

### R2-3 通过：来源哈希篡改后重签 content hash

攻击者把 gate source hash 改为 64 位合法格式并重算 content hash。验证器仍拒绝。

### R2-4 通过：truth permutation（真值置换）

将注册真值置换为完全不同的五轴状态，候选池保持完全相同，说明新增联合提议只消费父粒子和可见延迟帧。

### R2-5 通过：相关回归与静态检查

最终运行全部 `tests/test_structure_two_*.py`：72 passed。覆盖 v0.1 exact falsifier、v0.2 gate、对抗测试、行动 death test 和 selected-method authority contracts。Ruff、格式、Mypy、artifact `--verify-only` 与 `git diff --check` 均通过。

## 修复后仍保持的阻断边界

1. neural amortized proposer（神经摊销提议器）没有冻结架构或训练 artifact，继续 fail-closed；
2. 联合核没有经过新场景族、封存种子或外部数据验证；
3. 当前行动读出不具备验证多轴修复行动价值的能力；
4. 候选评分次数不是实际计算成本；
5. `e13` 仍未进入 top-24，完整重跑同样失败；
6. 没有 corrected AMG 三方行动级 fresh-seed 比较；
7. 没有 RGB-D、真实家庭或机器人执行证据。

## 允许进入的下一步

可以进入新的开发／确认分界设计，但必须先冻结：

- 与当前 16 格不同的新场景族或封存随机种子；
- corrected AMG、旧完整系统、完整系统＋联合复苏三臂；
- 相同证据、行动、观察成本与评分函数；
- 消费多轴状态的行动读出；
- 每步净行动损失为主要终点；
- 实测墙钟时间与内存作为效率补充，解析评分次数只作机制诊断。
