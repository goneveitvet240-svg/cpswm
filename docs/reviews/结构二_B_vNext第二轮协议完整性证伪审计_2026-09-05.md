## 结论

本轮先以只读方式执行 forged-but-complete（内容完备但未登记）、cross-version substitution（跨版本替换）、replay/registry replacement（重放/注册表替换）、missing dependency（缺父依赖）和 direct runner bypass（直接运行器绕过）矩阵，发现两个 P0 与一个保证过度；完成最小修复后重新执行全部第二轮测试，指定矩阵全部拒绝预期攻击。

这只表示本轮协议完整性攻击已被处理，不表示科学门已经通过，也不表示存在正式 Round 2 receipt（第二轮正式回执）。当前 Task 7 与 Task 8 仍为 `FAIL`，Gate B raw formal chain（原始正式链）未登记执行，formal monotonic/WORM replay backend（正式单调/只写重放后端）未实现或登记，checked-in authorization policy 的 trust/config/spec/custody 仍未登记。因此唯一结论仍是 `NOT_AUTHORIZED`。

## 发现并修复的 P0

### P0-1：最终授权 verifier 未把 manifest 重新绑定到 checked-in policy

修复前，最终 verifier 只比较 authorization decision（授权决定）中的 manifest hash 与调用方提交的 manifest，自身没有要求该 manifest hash 等于 checked-in policy 冻结值，也没有在 executor 边界验证 registry-root signature。若未来把 policy 标为 `ENROLLED`，调用方可构造自己的 manifest、authorization key 与完整已签名决定。

修复后，最终 verifier 必须同时满足：

1. caller policy 的规范化内容等于 checked-in v1.1 policy；
2. policy 明确为 `trust_anchor_status=ENROLLED` 并冻结 manifest content hash；
3. caller manifest 的 unsigned content hash 精确等于 policy 冻结值；
4. caller 提交的 root verifier identity 等于 manifest 冻结 root identity；
5. registry-root signature 对固定 manifest payload 验证通过；
6. decision 再绑定同一 manifest hash、authorization anchor 与 run ID。

新增负测覆盖“攻击者自建但字段齐全的 manifest/authorization key”和“保留 frozen manifest payload、只替换 root signature”两类路径。

### P0-2：factorial executor 信任 caller-supplied verification time

修复前，core runner 把 `authorization_verification_time_utc` 原样交给 freshness verifier；调用方可把时间回拨到已过期 token 的有效期内。

修复后：

- `run_project_two_factorial_benchmark` 公共签名不再接受 verification time；
- authorization evaluation 与 final execution verification 只读取 verifier process 内部 UTC；
- 测试仅通过私有 clock seam 固定时间，不向生产 runner 暴露时间注入参数；
- 过期 signed authorization 即使调用者意图回拨时间也在 workload 构造前被拒绝。

### 保证收紧：device/inode 不是完整 anti-rollback

Gate B candidate SQLite registry 的 canonical path、regular-file、single-link、`O_NOFOLLOW`、device/inode guard 能拒绝异路径 clone、symlink 与 `os.replace` identity replacement，但不能检测保持相同 inode 的原地内容回滚，也不能证明 filesystem snapshot restore 未发生。

代码 docstring 与 Gate B raw-chain 协议已把保证收紧为 `identity-replacement defense only`。该 SQLite candidate 不得充当 formal rollback-safe registry。authorization v1.1 明确只含 `formal_grade=false` 的内存诊断 registry；schema 直接拒绝调用方自报 `VERIFIER_OWNED_PERSISTENT`。真正正向授权必须由后续新协议实现并登记 verifier-owned monotonic/WORM backend，当前把它保留为硬 blocker。
