## 一、它到底在解决什么问题

### 1.1 表面问题

用户说一句模糊的话：

> "把我晚上经常放在床边用的那个东西拿来。"

机器人要找到并拿来正确的**那一个物体实例**。

### 1.2 真正的问题

表面问题有一个看似显然的解法：把句子和物体标签都编码成向量，取余弦相似度最高的。**结构三的全部设计都是在论证这个解法为什么不成立**，以及不成立时应该怎么办。

它不成立，是因为这句话里的每个限定词指向的都不是外观：

| 限定词 | 指向什么 | 需要什么证据 |
|---|---|---|
| "我的" | 拥有者 | 人物身份解析 + 授权 |
| "晚上" | 时间/活动上下文 | 事件历史 + 习惯模型 |
| "经常" | 频率统计 | 长期观察积累 |
| "床边" | 三维空间关系 | 几何锚点 + 拓扑 |
| "用的" | 功能可供性 | 使用事件记录 |
| "那个东西" | 实例而非类别 | 跨天实例重识别 |

而且——**目标可能根本不在已建图的部分**。它可能被人拿走了、在没探索过的房间、或者从来没被机器人看见过。

### 1.3 结构三的一句话定义

> 把模糊语言编译成**可检查的约束**，用六路证据算出**含显式 unknown 的实例级联合后验**；证据不足时不硬下结论，而是在**询问、多视角、移动、开容器、必要触觉**之间按净信息价值选动作；机器人执行产生的成功、失败、滑落、部分和未知结果，作为**带不确定性的概率证据**写回长期记忆。

## 二、理解全篇的三把钥匙

读这份文档最容易迷失在 M01–M32 的编号里。实际上整个设计由三条不可协商的原则驱动，几乎每一处细节都是这三条的推论。

### 钥匙一：语言模型没有写入世界模型的权限

原文：*"LLM 只输出 `CompiledSemanticQuery` 或候选解释；真正的实例后验由世界模型计算。语言模型没有写入 M13–M19 的权限。"*

**为什么这条这么重要？** 因为 LLM 的失败模式是**流畅地编造**。如果允许 LLM 说"杯子应该在厨房"然后这句话变成世界模型里的一个事实，那么整个系统就退化成一个会给自己编造记忆的东西——而且编造出来的东西还带着置信度，下游无法区分它和真实观测。

推论遍布全篇：
- M21 输出的是**查询**（约束集合），不是**答案**（哪个物体）
- `hard_constraints` 必须由**独立的 evaluator** 给出结构化的 `satisfied/violated/unknown` 评估，不能由编译器自己说满足
- §1.2 第 10 条禁止"用 LLM 生成的解释文本反向改变世界状态"

### 钥匙二：证据缺失不等于否定证据

这条在代码里是 `ChannelEvidence.availability`：

```python
class ChannelEvidence(ContractModel):
    """``availability=0`` makes a channel explicitly missing rather than
    silently treating a missing score as negative evidence."""
    likelihood_given_candidate: StrictlyPositiveProbability
    reliability: Probability = 1.0
    availability: Probability = 1.0
```

**为什么需要显式区分？** 假设"人物通道"对某个候选没有数据（这个杯子从没被人碰过，还是只是没记录？）。如果把"没数据"当成似然 0 或者当成低分，那么**从未被观察的物体会系统性地被排到后面**——而这恰恰是最需要被找到的那些。

同一条原则的其他化身：
- 硬约束的三值制：`violated` 排除，`unknown` **保留但不能直接 resolved**
- `not_found` 必须绑定**真实存在的观察机会**才能作为负证据（§9.1）
- Top-k 截断后**不重新归一化**，`posterior_mass_returned` 显式告诉调用方漏了多少概率质量

### 钥匙三：规范记录只能追加，派生投影必须可重建

原文：*"规范反馈追加到 M03/M13–M15；`FeedbackBeliefUpdate` 是可删除、可重放、可重建的 M16 派生投影。"*

这是一条**数据库设计**层面的决定，但它决定了这个系统能不能长期运行：

- **规范层（canonical）**：append-only 的事件流。发生了什么就记什么，永不修改
- **派生层（projection）**：当前信念、当前地图、当前可信度——全部可以从规范层重算

**为什么必须这样？** 因为长期系统一定会遇到：模型升级了、发现某个检测器有 bug、用户要求删除某条隐私记录。如果当前信念是唯一副本，这些操作要么做不了，要么会静默污染历史。分层之后，删除一条规范记录 → 重建所有派生投影，语义是干净的。

代码里对应 `layered_map.py` 的双 revision：

```python
self._static_revision  # 只在墙、家具等静态锚点变化时 +1
self._dynamic_revision # 物体移动时 +1
```

杯子移动**不**触发静态地图版本变化，因此不会引发整张地图重建。

## 三、一次完整闭环，逐步走一遍

```
用户说话
   ↓
M21 语言编译 ──────────► CompiledSemanticQuery（约束，不是答案）
   ↓
M20 混合召回 ──────────► 候选集 + 一个显式 unknown
   ↓
M16 六通道联合后验 ────► GroundedSearchResult
   ↓
        ┌──────────────┴──────────────┐
   resolved                    ambiguous / unknown
        ↓                              ↓
   M25 导航                    M24 信息价值选动作
   M26 抓取                            ↓
        ↓                    ask_user / 多视角 / 开容器 / 触觉 / 停止
   M27 执行反馈                        ↓
        ↓                       新观测 → 回到 M16
   概率证据写回 M13–M15                （闭环）
        ↓
   M19 记忆可信度与生命周期
```

关键点：**这不是一条流水线，是一个环**。`ambiguous` 不是失败状态，是"我需要更多信息"的正常状态，会驱动主动观察，然后重新计算后验。

## 四、七个模块逐个解剖

### 4.1 M21 语言编译：把话变成约束

**输出结构：**

```
CompiledSemanticQuery
  query_id / utterance
  category_candidates      ← 召回提示，不是事实
  attributes / relations / affordances
  person_entity_ids        ← 必须来自已授权的身份解析
  time_expression / activity_candidates
  hard_constraints         ← 违反即排除
  soft_constraints         ← 只改变似然
  compiler_model_version   ← 可回放
```

**核心设计：硬约束的三值评估。**

每个候选必须对每条硬约束给出 `satisfied / violated / unknown`，并附 evaluator 版本号。代码里的执行：

```python
# joint_posterior.py：violated 的候选直接跳过，不进入打分
if candidate.kind == OBJECT_INSTANCE and any(
    e.status == HardConstraintStatus.VIOLATED
    for e in candidate.hard_constraint_evaluations):
    continue

# 而 unknown 的候选保留，但强制降级为 ambiguous
best_has_unknown_hard_constraint = any(
    e.status == HardConstraintStatus.UNKNOWN for e in best_object.hard_constraint_evaluations)
```

**为什么三值而不是二值？** 因为"不要客人刚用过的那个"这种约束，在绝大多数时候你**没有证据**判断——既不能因此排除候选（会漏掉真目标），也不能当作满足（会拿错）。三值制把这种情况显式表达出来，并且让它**阻止 resolved**，逼系统去问或去验证。

> ⚠️ 这里有一个需要做消融的风险：现实中大多数硬约束长期处于 `unknown`，可能导致系统退化成"永远 ambiguous → 永远询问"。

### 4.2 M16 六通道联合后验：这个系统的心脏

**要维护的东西：**

$$P(O=o, L=l, I=i, E=e, A=a, Z=z \mid Q, Y_{1:t}, G_{1:t}, V_{1:t})$$

物体实例 $O$、位置 $L$、身份 $I$、事件 $E$、行为者 $A$、习惯阶段 $Z$，条件于语言查询 $Q$、感知 $Y$、几何 $G$、规范事件历史 $V$。

**候选集合必须含一个显式 unknown：**

$$\mathcal C = \{c_1,\dots,c_n, c_{\text{unknown}}\}$$

**第一版实现：经校准的加权对数意见池**

$$\log \tilde p(c) = \log p_0(c) + \sum_{m\in\mathcal M} w_m\, r_{m,c}\, a_{m,c}\,\log p_m(e_m\mid c)$$

其中 $\mathcal M = \{$language, visual, geometry, event, person, habit$\}$。

契约层强制**六通道必须全部显式出现**：

```python
if channels != set(JOINT_EVIDENCE_CHANNELS):
    raise ValueError(f"all six joint channels must be explicit; missing={missing}")
```

缺哪个都不行——想表达"这个通道没数据"，用 `availability=0`，不能省略。

**决策门控（三态）：**

```
unknown 质量高，或高于最佳已知实例   → unknown   → active_verify / abstain
最佳实例低于阈值，或第一二名 margin 太小 → ambiguous → active_verify / ask_user
两个条件都满足                      → resolved  → return_top_k
```

**Top-k 不重新归一化。** 这是一条容易被忽略但很重要的规则：如果你返回前 3 名并把它们归一化到 1，调用方无法知道剩下 40% 的概率质量在哪。契约里有 `posterior_mass_returned` 字段专门报告这个。

**诚实的自我限定（§4.2 原文）：** *"这是一条可审计、可替换的 baseline，不是最终概率图模型。使用者不得把六通道默认视为条件独立。"* 后续可换成因子图、粒子滤波、能量模型或学习式融合。

### 4.3 M11 多视角实例身份：防止把一帧当成确认

**核心机制：证据簇去重。**

```python
# identity_verification.py
best_by_cluster = {}
for evidence in request.view_evidence:
    previous = best_by_cluster.get(evidence.evidence_cluster_id)
    if previous is None or evidence.quality > previous.quality:
        best_by_cluster[evidence.evidence_cluster_id] = evidence
```

同一个视频片段的相邻 30 帧共享一个 `evidence_cluster_id`，**只取质量最高的一帧作为代表**。

**为什么？** 因为朴素的多帧融合会把 30 个高度相关的观测当成 30 份独立证据，后验会指数级地过度自信。这是一个真实且普遍的 bug，多数多视角工作都有。

**确认需要三个条件同时满足：**

```python
sufficient_views = independent_view_count >= request.required_independent_views
best_probability >= request.confirmation_threshold
margin >= request.ambiguity_margin
```

否则保持 `ambiguous`，并推荐下一个模态（RGBD 或——在授权且安全时——触觉）。

**触觉的地位：** 它不是默认动作。要求视觉/几何确实无法区分、经过可供性与安全检查、不涉及危险/易碎/药品/隐私对象、预期信息价值高于代价、且触觉模型在当前物体域有校准证据。而且**契约边界会拒绝绕过**：

```python
tactile_already_used = VerificationModality.TACTILE in used_modalities
if request.allow_tactile and request.tactile_safe and not tactile_already_used:
```

即使外部直接构造一条触觉身份证据，未授权或不安全的请求也会在契约层被拒。

### 4.4 M08 分层地图：静态与动态分离

| 层 | 内容 | 何时改版本 |
|---|---|---|
| `StaticGeometryAnchor` | 房间、墙、地面、固定家具、容器锚点；mesh/TSDF/occupancy 引用；层级拓扑；稳定坐标系 | 只有静态结构变化时 |
| `DynamicObjectState` | 实例 ID、所属锚点、6DoF 位姿、局部点云与视觉特征引用、状态概率与来源 | 物体移动时 |

**强制约束：动态物体的位姿坐标系必须与所属静态锚点一致。**

```python
if state.pose.frame_id != anchor.frame_id:
    raise ValueError("dynamic object pose frame must match its static anchor frame")
```

跨 frame 写入必须先经 M02 `FrameRegistry` 完成有效变换。**这防止的是**：相机坐标系下的检测结果被直接写进世界坐标的地图，产生看起来合理但位置完全错误的物体。

**§7.3 的职责划分（这段很值得记住）：**

- VIO/SLAM → 估计机器人和相机位姿、坐标变换。**不负责语义识别**
- RGB-D / 点云 / TSDF → 提供几何、遮挡、尺度、抓取输入。**不决定物体属于谁**
- VLM / 检测 / 重识别 → 提供开放词汇语义和实例候选
- 全局搜索 / 导航 → 选房间、锚点、观察视点
- MPC / MPPI → 动态约束下的局部安全运动。**不决定语义搜索顺序**

### 4.5 M24 信息价值：选下一个观察点

**信息增益：**

$$IG(a) = H(B_t) - \mathbb E_{y\sim p(y\mid a,B_t)}\big[H(B_{t+1}\mid y,a)\big]$$

**净价值（扣五类成本）：**

$$V(a) = \lambda_I IG(a) - \lambda_M C_{\text{motion}} - \lambda_T C_{\text{time}} - \lambda_U C_{\text{interrupt}} - \lambda_P C_{\text{privacy}} - \lambda_S C_{\text{safety}}$$

**动作集合是异质的**，这是设计上的亮点：

```
move_viewpoint / micro_verify / open_container / touch / ask_user / stop
```

**`ask_user` 与物理动作在同一个效用尺度上竞争** ——询问不是失败兜底，是一个有信息价值也有打扰成本的正常动作。

**代码里的关键校验：**

```python
action_hypotheses = set(next(iter(action.outcome_likelihoods.values())))
if action_hypotheses != set(prior):
    raise ValueError("every observation action must score exactly the current hypotheses")
```

以及全篇最尖锐的一条工程洞见（§8 末尾）：

> **M24 和 M16/M09 必须使用同一版本的 `ObservationLikelihoodModel`，否则机器人会用一种检测概率规划、再用另一种检测概率解释"没找到"。**

契约层用 `observation_likelihood_model_id` + `calibration_domain` 强制这一致性，不一致直接拒绝更新。大量 active perception 工作实际上有这个隐藏的不自洽。

> ⚠️ 当前实现是**一步贪心**。`open_container` 是天然的两步动作（开门本身可能 IG=0），贪心策略在这类情形上会系统性失败。

### 4.6 M27 执行反馈：失败不等于否定

**结果不是布尔值，是分布：**

```
success / not_found / grasp_failed / object_slipped / partial / unknown
```

**贝叶斯更新：**

$$P(X=1\mid f,a) = \frac{P(f\mid X=1,a)P(X=1)}{P(f\mid X=1,a)P(X=1) + P(f\mid X=0,a)P(X=0)}$$

**三条不变量，每条都对应一类常见错误：**

**（1）`not_found` 必须绑定目标实体、尝试位置和事先记录的观察机会。**
没有观察机会记录，你就无法知道"没看到"是因为不在那儿，还是因为被遮挡/太远/根本没看那个方向。代码：`test_not_found_without_observation_opportunity_is_rejected`

**（2）结果模型必须覆盖反馈中所有正概率结果。**

```python
if not realized_outcomes.issubset(modeled_outcomes):
    raise ValueError(f"outcome model must cover every realized feedback outcome; missing={missing}")
```

实际发生了 `grasp_failed` 但模型只定义了 `success/unknown` → **拒绝更新**，而不是静默丢弃这部分概率质量。

**（3）动作成功 ≠ 任务目标达成。**

```
task_goal_satisfied_probability ≤ outcome_distribution.success
```

导航成功只能推进任务图，不能让取物闭环提前结束。**这一条防止的是一整类被污染的成功率统计**——很多 LLM planner 论文的 success rate 就是这么虚高的。

**保证的语义：**
- "未找到"降低目标在该处的概率，**但不降为零**
- "抓取失败"可能源自定位、碰撞、姿态、硬件或物体性质，**不能否定身份**
- "物体滑落"意味着机器人自己造成了位置变化，**需要产生新的位置候选**
- 部分成功和未知保持概率质量，不伪造确定事实

### 4.7 M19 记忆生命周期：拒绝指数衰减

**核心立场（§10）：**

> `time since last seen` 与 `category stability` 只是**先验变量**，不等价于当前记忆可靠度。

代码里这条被写死成一个不变量：

```python
"""Age is deliberately excluded from the posterior calculation. ...
Raw elapsed seconds only distinguish fresh from stale presentation states."""
```

以及输出字段 `age_used_as_direct_reliability_evidence=False`。

**为什么？** 因为**旧 ≠ 错**。桌子可能半年没动，杯子可能 30 秒就被拿走。统一的指数衰减 $e^{-\alpha\Delta t}$ 把这两者当成一回事，是错的。

**替代方案：** 可靠度由 `MemoryReliabilityProjector` 从 prior odds 出发，融合经校准且按独立性降权的似然比：

```python
effective_weight = evidence.reliability * evidence.independence_weight
log_likelihood_ratio = log(p_evidence_given_current) - log(p_evidence_given_not_current)
log_odds += effective_weight * log_likelihood_ratio
```

要表达"过去十天里可能被移动"，必须由带人物、物体、活动、情境的 `TRANSITION_SURVIVAL` 模型提供似然，而不是套一个统一衰减。

**八个生命周期状态，各自语义不同：**

| 状态 | 含义 |
|---|---|
| `uncertainty_growth` | 当前状态概率扩散 |
| `contradicted` | 被后续证据**反证** |
| `superseded` | 被有来源的**新版本替代** |
| `historical` | 仍作为过去事实保留 |
| `habit_regime_change` | 习惯阶段改变 |
| `archived` | 存储层归档 |
| `deleted` | 授权/治理删除，触发派生重建 |
| `true_forgetting` | 降低可用性，**但不篡改历史** |

`contradicted` 和 `superseded` 的区分尤其重要：前者是"我错了"，后者是"情况变了"，两者的下游处理不同，多数系统混为一谈。

**数值细节也做对了**：对数域计算似然比，稳定 logistic，避免 `exp` 溢出。

## 五、契约优先：这个项目真正的形态

读完模块之后，最该注意的是：**结构三本质上不是一套算法，是一套把失败模式编码成强制不变量的契约系统。**

证据在测试文件里。46 个测试，绝大多数是"必须被拒绝"型：

```
test_hard_constraint_violation_cannot_be_resolved
test_tactile_identity_evidence_requires_authorization_and_safety
test_information_gain_rejects_actions_scored_on_a_different_hypothesis_set
test_oracle_observation_rejects_planning_update_model_drift
test_oracle_loop_rejects_cross_trace_verification_evidence
test_feedback_projector_rejects_unmodeled_realized_outcome
test_action_success_cannot_overstate_task_goal_completion
test_not_found_without_observation_opportunity_is_rejected
test_memory_reliability_uses_evidence_not_raw_age
test_execution_posterior_failure_leaves_no_partial_batch
```

注意反复出现的 `without_a_write` ——**验证失败时不能留下部分写入**，这是事务性保证。

§1.2 那份"必须防止的十个错误"清单，实际上是整个代码库的规格说明。这个做法的价值是：**当你后来换掉融合算法、换掉检测器、换掉规划器时，这些不变量仍然成立**。契约是稳定的，实现是可替换的。

## 七、评价协议

### 7.1 四类指标

**查询与后验**：Recall@k、MRR、**unknown 的 AUROC/AUPRC**、open-set risk、ambiguous 检测准确率、**selective risk/coverage**、ECE/Brier/NLL、询问正确率与不必要询问率

**必须报告的基线**（11 条，从 `text-image similarity only` 到 `oracle upper bounds`）

### 7.2 一条重要的自我约束

> ECE、Brier 和 NLL 只作为**诊断**，不能单独证明方向有效。最终 go/no-go 必须看同预算下的实例检索、**误拿率**、行动效用和真实/半真实外部有效性。

这句话很关键：校准指标好看不等于系统有用。**误拿率**才是家庭机器人真正的高代价失败。

## 九、这个设计最强和最弱的地方

### 9.1 最强的三处

**(1) 规划与更新的似然模型一致性（§8）。** 这是全篇最尖锐的观察，而且是可以独立写进论文的工程洞见。大量 active perception 工作在这里默默地不自洽。

**(2) action success 与 task goal 的分离（§9.1）。** 防止的是一整类被污染的成功率统计。约束 `task_goal ≤ success` 简单但有效。

**(3) 拒绝指数衰减作为记忆模型（§10）。** 立场正确、可证伪，且在代码里被写成了强制不变量（`age_used_as_direct_reliability_evidence=False`）。

### 9.2 最弱的三处

**(1) 没有外部基线定位。** §13.4 列的 11 条基线**全是自己系统的消融**，一条外部工作都没有。而每一项能力都有强 prior work（ConceptGraphs、OK-Robot、GOAT 之于实例检索；3D-MOS、OO-POMDP 之于 VoI 搜索；KnowNo 之于校准拒答）。缺 positioning 是最致命的。

**(2) 融合算子是启发式，但论断依赖"校准"。** 加权对数意见池不是任何概率模型的后验，$w_m$ 是手调的。文档诚实承认了这是 baseline，但"经校准的联合后验"这个措辞在数学上站不住——融合是 score，校准是后接的一层，两者不该混称。

> 补充：$\{w_m\}$ 是一个**聚合权重族**，而你 RRCL 论文的结论正是这类权重从训练统计量选不可靠（命题 A/B）。这既是风险也是可以引自己的设计辩护。

**(3) `unknown` 的似然是循环定义的。** 契约强制每个候选（包括 unknown）提供全部六通道证据，那么 $p_{\text{language}}(e\mid\text{unknown})$ 是什么？没有生成模型，只能拍常数——而 unknown AUROC 这个指标恰恰建立在它上面。出路是从**空间覆盖率**导出：未探索体积 × 校准漏检率 × 类别先验。

### 9.3 一个内部张力

§4.1 说 unknown "不是普通物体节点，也不能携带伪造的位置"；但 §8 要选下一个观察点就**必须**知道去哪儿找它。这是文档内部的真实矛盾。可能的解法：unknown 不带点位置，但带一个**覆盖率导出的空间密度场**——既不伪造位置，又让 VoI 可计算。

## 十、如果要用一段话向导师介绍它

> 这个项目研究的是：当用户用模糊、时间化、人物化的语言描述一个物体时，家用机器人如何在**不确定身份、不确定位置、且目标可能根本没被建图**的条件下做出可追溯的决策。我们不把它当成一个检索问题，而是当成一个**开放集的序贯决策问题**：系统输出带显式 unknown 的实例级后验，证据不足时在询问、多视角观察、开容器和移动之间按净信息价值选动作，执行的成功与失败以概率证据回写长期记忆。目前完成的是契约层与真值闭环基线——**六通道后验、多视角去相关身份确认、静态/动态分层地图、信息价值规划、不确定执行写回**都已实现并被 46 个不变量测试约束，其中大部分测试验证的是"错误输入必须被拒绝且不留部分写入"。下一步是接入受控噪声与真实感知。
