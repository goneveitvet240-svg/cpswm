# 第五轮候选推进计划：检验真实输入分辨率是否改善闭环

此计划在第四轮66帧结果完成前固定。必须先完成该轮两审、全量采集与复算，再实现本轮；如剩余时间不足则保留未完成状态。保持全部现有方法、两个前端、0.5开发过滤值、目标位置、先验、相机物理设置与预算，不选正式架构或模型。

已见目标在320×320实际渲染图中仅约554/558像素。拟将真实Unity采集分辨率作为唯一新增控制变量，使用320×320与640×640两个预声明条件，均FOV60、同一初始实际位姿、同北/南位置、每种分辨率完整执行6方法×2位置×2前端=24场，共48场。不通过后处理放大旧图冒充新增像素；所有实际原始图/动作/后验都保留。旧a8992c0的24场不直接拼接成新源码的48场，需要同新SHA重跑两个分辨率。

检验目标是运行中的感知输入是否限制了任务。若640改善检测与停止，可以说该输入条件下的前端表现改善；如后验方法与关闭反馈/扫描仍相同，继续记录无方法额外收益。若结果更差也完整报告，不据此挑分辨率或只发布成功位置。输入字节数、实际图尺寸、目标像素、框IoU、动作数/角度和墙钟分别记录，不把额外图像信息与计算开销当免费优势。

两轮审查分别验证真实采集配置传递、默认320兼容、合法640像素与边界/恢复，再攻击错报图尺寸、跨配置混入、漏场/重复场/伪造阳性及与实际所有者回包不一致。来源固定后才实际跑48场并逐场新进程复算。这个任务仍为单房屋、单Apple资产、受控语义先验的局部相机闭环，不补齐自然身份/人物/接触、完整神经修订、导航抓取或跨场景验证。
