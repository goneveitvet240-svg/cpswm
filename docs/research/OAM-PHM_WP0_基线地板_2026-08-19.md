## 2. 地板数字（F0 固定样例，书桌 → 沙发异常 → 书桌）

查询设计：每次放置后 1 小时问"它在哪"，而检测历史严格早于查询时刻——**基线必须预测，不能读答案**。

| 基线 | top-1 | NLL | n |
|---|---:|---:|---:|
| `oam-phm-last-seen@0.1` | **0.333** | 5.0674 | 3 |
| `oam-phm-household-frequency@0.1` | **0.667** | 2.7648 | 3 |
| `oam-phm-markov-transition@0.1` | **0.333** | 5.0674 | 3 |

两次运行字节一致，`sha256(artifact) = 48a86633…`。

### 这三个数字讲的正是 OAM-PHM 的核心论点

**last-seen 0.333** —— 第 2 天书出现在沙发（`temporary_exception`），last-seen 从此永远相信沙发，第 3 天错。这就是 `§2.2` 记录的边界"检测命中直接增加位置习惯证据"的最直接后果：**一次偶然异常永久污染当前状态**。

**household-frequency 0.667** —— 池化抗住了第 2 天的异常，第 3 天答对。但它第 2 天错，因为池化分布**追不上当前状态**。

**关键在于两者的互补失败**：

> 单一位置分布赢了习惯就输了当前状态，赢了当前状态就输了习惯。**没有更好的池化估计器能同时赢**。

这正是 `§2.2` 那一行——*"一个位置分布同时承担当前状态和长期规律"*——第一次变成可测量的东西。要突破它必须**分离当前信念与长期习惯**，也就是 WP2，而不是把频率先验调得更好。

**markov 0.333** —— 3 次稀疏检测只产生 1 次转移，一阶估计退化到与 last-seen 相同。这量化了 `§1.1` 场景里"选择性观察"的代价。

**地板留有余量**：没有任何可运行基线解决这个固定样例（测试 `test_no_runnable_baseline_solves_the_fixture` 固定了这一点），所以 WP2–WP6 的增益是可测的。

## 3. 两条结构性保证

### 3.1 基线不可能看到真值

`§5.1` 不变量 8 规定只有 M29/M31/M32 可读 `gt.*`。基线是模型不是评价器，所以：

- 基线的输入类型是 `SymbolicSimulationResult`（机器人可见流），**不是** `PrivilegedSymbolicSimulationView`
- 真值只以 `tuple[UUID, ...]` 形式传给打分函数，永不传给基线
- 测试 `test_baseline_module_never_imports_ground_truth` **解析模块的 AST**，断言它不 import 任何 `cpswm_gt`

最后一条是结构性的：不是靠约定，是靠导入图。

### 3.2 输入必须完全相同

`§9.4` 规则 1 与 6 要求同感知输入、同预算，禁止靠给候选方法更多观察制造收益。`compare_baselines` 把同一个 run 和同一个查询集喂给每个条目，测试 `test_every_baseline_sees_identical_inputs` 用一个记录型子类验证每个基线看到的检测数与机会数完全一致。

## 5. 过程中的一个发现

F0 固定样例里，`gt_entity_id` 与机器人可见的 `object_instance_id` / `location_id` **是同一个 UUID 命名空间**（评价器 line 789–790 直接 `==` 比较）。

在 F0-L0 符号 oracle 轨道上这是合理选择，但需要记录两点：

1. 泄漏检测器因此只能针对 `gt_event_id`，**不能**针对实体 ID——因为实体 ID 本来就共享。这与文档 §4 "精确特权引用检测器"的限定一致，但值得在文档里说明白共享的是哪一层。
2. 到 B0/B1 接入真实感知后，两个 ID 空间**必然分叉**（真实检测给出的是感知实例 ID，不是真值实体 ID）。届时评价器的直接相等比较会失效，需要一层显式的 identity resolution。**建议现在就在文档里记下这个已知的迁移点**，不要等到 B1 才发现。
