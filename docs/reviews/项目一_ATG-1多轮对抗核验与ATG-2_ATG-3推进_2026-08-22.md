# 项目一 ATG-1 多轮对抗核验与 ATG-2/ATG-3 推进（2026-08-22）

## 结论

- ATG-1 经四轮 adversarial verification（对抗核验）后仍成立：11 臂拓扑、全局唯一 tuning run ID（调参运行标识）、逐臂五项绑定、split artifact hash（划分资产哈希）和输出隔离均为 fail-closed（失败即关闭）。
- ATG-2 在狭义 SHIFT comparison（三臂比较）范围内成立：ordinary BOCPD、legacy independent cause-factorized BOCPD 和 joint CF-BOCPD 各自执行完整且独立的 18-trial search space（18 次搜索空间），并记录实测时间、预测次数、延迟、峰值内存、持久参数字节和参数量。
- ATG-3 在同一三臂范围内成立：只有绑定 ATG-1、validation/test hash、三份账本、冻结参数、模型版本和代码快照的强 receipt（强回执）可以解封 TEST；解封后禁止重新调参和二次解封。
- 这不是 11 臂全实验闭环。其余 8 臂仍为 `adapter-unbound`，所以 `global_eleven_arm_tuning_status` 和 `global_eleven_arm_experiment_status` 继续为 `BLOCK`。
- 正式结构一 B1（M05–M12 perception，感知主线）没有被本次 SHIFT 子任务替代，继续为 `BLOCK`。

## ATG-1 四轮对抗核验

1. 逐臂绑定篡改：分别攻击 comparison、manifest arm、model version、method semantics、topology result/binding，反序列化均拒绝。
2. 外层重签攻击：修改 split experiment ID，或在 train/TEST 间重分配 case count 后重算外层 manifest hash，仍因内部 artifact manifest hash 失配而拒绝。
3. Pydantic `model_copy` 绕过与 tuning ID 冲突：内存中绕过 nested validator（嵌套校验器）后再做 wire round-trip（线格式往返），会重新触发校验；跨 comparison 的重复 tuning run ID 同样拒绝。
4. 文件系统攻击：`--force`/atomic writer（原子写入器）不能沿 symlink（符号链接）覆盖 `pyproject.toml` 等受保护仓库文件。

对应自动化证据：`tests/test_atg1_multi_round_adversarial.py`。

## ATG-2 独立调参与实测预算账本

每臂 search space 固定为 18 个 trial，trial ID 绑定 tuning run ID、序号和参数；trial records（试验记录）使用 previous-hash chain（前向哈希链）。每份 ledger（账本）验证：

- 完整且有序覆盖声明的 search space；
- selected params（选定参数）来自已经完成的 trial；
- validation split hash、model version 和 tuning run ID 全链一致；
- elapsed time、validation predictions、peak memory、worst-trial p95 latency、persistent bytes、parameter count 均为实测值并在预算内；
- receipt 对每臂绑定 trial count、search-space hash、selected-params hash、ledger hash、model version、completion status 和 canonical log head。

TEST 在 ATG-2 完成时仍为 sealed（封存），ATG-2 API 只接收 validation cases（验证集样本）。

## ATG-3 合规解封与三臂公平比较

解封前同时验证：receipt authenticity（回执真实性）、receipt scope（回执作用域）、experiment ID、validation hash、TEST hash、ATG-1 topology hash 和当前 code snapshot hash（代码快照哈希）。三臂使用各自在 ATG-2 冻结的参数，在同一 12-case frozen TEST（冻结测试集）上运行。

置信区间以 `scenario_seed_trajectory` 为 paired bootstrap resampling unit（成对自助重采样单位），避免把同一轨迹内相关样本伪装成独立样本。

本次可复现实验的证据是 mixed（混合）而不是单向胜出：joint CF-BOCPD 的 TEST micro-F1 为 `0.6875`，ordinary 为 `0.6857`，legacy independent 为 `0.4615`；但 joint 的 NLL 为 `1.4057`，明显差于 ordinary 的 `0.6965` 和 legacy 的 `0.8073`。因此报告的 `forbidden_claims` 明确包含 `general-method-superiority` 和 `state-of-the-art`。

## 可复现入口与边界

运行：

```bash
.venv/bin/python apps/evaluation_runner/run_project_one_shift_gates.py \
  --output output/project_one_shift_gate_report_v1.json
```

`code_snapshot_sha256` 覆盖本门控的 core source（核心源码）、CLI、tests（测试）和 benchmark config/assets（基准配置与资产）。生成报告含 wall-clock/resource measurements（墙钟与资源实测），因此数值字段不承诺逐字节重复；协议、数据、搜索空间、选择规则、哈希绑定和结构化结论可复核。

当前允许的准确表述是：“SHIFT 三臂 ATG-2/ATG-3 已闭环，并报告冻结合成套件上的成对结果。”不能表述为：“11 臂全部实验完成”“正式结构一 B1 已完成”或“joint CF-BOCPD 普遍优于已有方法”。
